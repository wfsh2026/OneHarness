## 1. 游戏定位与核心体验

### 1.1 产品定位

| 属性 | 内容 |
|------|------|
| 品类 | 多人联机卡通射击游戏 |
| 平台 | 微信小游戏（主）/ Android / iOS |
| 视角 | TPS（第三人称射击） |
| 风格 | 卡通割草、Roguelike 构筑、PVE/PVP 双轨 |
| 匹配规模 | 1人 ~ 10人（视模式而定，最大 5V5） |

### 1.2 核心体验关键词

```
爽快割草 · 策略构筑（BD）· 满屏特效 · 多人协作 / 对抗
```

### 1.3 战斗体验画像（数值目标）

| 体验指标 | 目标数值 | 说明 |
|---------|---------|------|
| TTK 小怪 | 0.5 ~ 1s | 割草碾压感 |
| TTK 精英/Boss | 3 ~ 8s | 依赖元素连携 |
| 操作密度 | 中等偏低 | 悬浮武器自动索敌，玩家核心在走位和 BD 决策 |
| 容错边界 | 高 | 多次倒地可复活，支持队友救援与自动复活 |
| 血线压力 | 前期 80~100%，后期 20~60% | 随回合数阶梯上升 |

## 2. 核心玩法循环

### 2.1 宏观游戏循环（局外 ↔ 局内）

```
【局外】
  选择模式 → 匹配组队 → 带入武器/皮肤外观
        ↓
【局内启动】
  读取配置 → 初始化角色/装备 → 等待玩家就绪
        ↓
【战斗循环】
  回合开始 → 战斗进行 → 回合结算 → 下一回合 / 模式结算
        ↓
【结算与产出】
  战报展示 → 发放经验/代币 → 更新排行榜 → 返回局外
```

### 2.2 局内核心循环（单回合内）

```
回合计时开始
  ↓
怪物/对手出现（极坐标刷怪 / 固定区域 / 对手交战）
  ↓
玩家行动（走位 · 射击 · 技能 · 驾驶载具）
  ↓
伤害结算（命中 → 元素附加 → 元素派生链触发 → 击杀）
  ↓
击杀奖励（积分 / 经验 / 掉落物 / 词条选择窗口）
  ↓
【三选一词条窗口（PVE Roguelike）】
  选取词条 → 流派强化 → 返回战斗
  ↓
回合胜负判定（达成得分 / 时间耗尽 / 全灭）
  ↓
复活 / 进入下一回合 / 结算
```

### 2.3 玩家操作密度设计原则

- **自动化**：悬浮武器自动索敌、开火，玩家无需额外操作
- **主动决策**：走位聚怪、规避高危伤害、三选一词条构筑
- **低操作上限**：适配微信小游戏轻度用户，禁止多键组合技连招设计

## 3. 游戏模式体系

### 3.1 模式分类

所有模式以「模式枚举（ModeEnum）」标识，分为两大类：

#### A类：对战模式（PVP）

| 模式名 | 人数结构 | 核心规则 | 胜负方式 |
|--------|---------|---------|---------|
| 1V1 对战 | 1V1 | 对枪，无复活 | 先击杀对手 |
| 5V5 复活战 | 5V5 | 有复活，击杀计分 | 积分先到 / 时间耗尽计总分 |
| 5V5 双倍积分 | 5V5 | 5V5 复活战变体，双倍得分 | 同上 |
| 5V5 无限火力 | 5V5 | 弹夹无限，节奏更快 | 同上 |
| 个人夺金 | 最多 10人 | 击杀掉金币，拾取得分 | 积分先到 |
| 小队夺金 | 多队 | 同上，团队积分 | 队伍积分先到 |
| 移动占点 | 多队 | 占领移动控制点得分 | 积分先到 / 时间耗尽 |

#### B类：合作模式（PVE）

| 模式名 | 人数结构 | 核心规则 | 胜负方式 |
|--------|---------|---------|---------|
| Boss 战 | 1~5人协作 | 全员协作击杀 Boss | 击杀 Boss 胜利 |
| 探索收集 | 1~5人协作 | 清怪波次+收集资源 | 完成目标 / 全灭失败 |
| 多武器PVE | 1~4人协作 | Roguelike 割草，三选一 BD | 通关目标回合数 |
| 靶场训练 | 1人 | 练习场，假人靶 | 无胜负 |

### 3.2 模式通用参数表

> 策划在设计新模式时，必须明确填写以下所有参数，不得留空或标注「待定」。

| 参数字段 | 含义 | 推荐范围 | 说明 |
|---------|------|---------|------|
| `MaxRoleNum` | 总玩家上限 | 1 ~ 10 | 最大 20 |
| `MaxRoleNumPerTeam` | 每队上限 | 1 ~ 5 | 最大 10 |
| `MinStartPlayCharacterNum` | 最少开始人数 | 1 ~ 4 | 不足不开局 |
| `RoundTime` | 单回合时长（秒）| 60 ~ 300 | -1 = 无限制 |
| `MaxRoundCount` | 最大回合数 | 1 ~ 5 | 最大 20 |
| `WinScore` | 胜利所需积分 | 10 ~ 50 | -1 = 仅按时间/回合判定 |
| `StartModeDownTime` | 等人倒计时（秒）| 5 ~ 30 | 0 = 立即开始 |
| `StartRoundDownTime` | 回合开始读秒 | 3 ~ 10 | 给玩家准备时间 |
| `WaitNextRoundTime` | 回合间隔（秒）| 5 ~ 15 | 两回合之间等待 |

### 3.3 胜负判定规则

#### 回合胜负（RoundWinState）

| 规则名 | 适用场景 | 说明 |
|--------|---------|------|
| 个人积分最高 | 1V1、个人竞技 | 回合内积分最多者得一局 |
| 队伍积分最高（允许平局）| 5V5 等 | 分高队获回合胜 |
| 队伍积分最高（强制分胜负）| 占点、夺金 | 不允许平局，必分输赢 |

#### 模式胜负（ModeWinState）

| 规则名 | 适用场景 | 说明 |
|--------|---------|------|
| 个人总积分最高 | 个人竞技 | 所有回合积分总和 |
| 队伍总积分最高 | 队伍对抗 | 队伍历史积分合计 |
| 回合胜利次数最多 | BO3/BO5 | 胜场计数 |

### 3.4 积分来源渠道

| 积分来源 | 推荐分值 | 适用模式 |
|---------|---------|---------|
| 击杀玩家 | 1 分 | PVP 模式 |
| 击杀普通怪物 | 1 分 | PVE 模式 |
| 击杀 Boss | 5 ~ 10 分 | Boss 战 |
| 占领控制点（每秒）| 1 分 | 占点模式 |
| 拾取金币 | 金币面值 | 夺金模式 |
| 最终存活队伍 | 5 ~ 20 分 | 大逃杀类 |

### 3.5 模式回合生命周期（状态机）

```
None
  → Wait（等待玩家就绪）
    → WaitStartDownTime（满人倒计时）
      → WaitRoundStart（回合开始准备）
        → RoundStart（战斗进行中）
          → RoundEnd（回合结算）
            → WaitNextRound（回合间隙）
              → [循环 WaitRoundStart，直至达到 MaxRoundCount]
    → WaitModeOver（模式结算）
      → ModeOver（结算展示）
        → SaveReport（保存战报）
          → QuitApp（退出）
```

### 3.6 预设行为包（快速复用）

| 预设包 | 核心机制 | 关键配置 |
|--------|---------|---------|
| M01 限时积分战 | 时间耗尽计积分 | `RoundTime` + `WinScore=-1` |
| M02 先到积分 | 率先达到目标分 | `WinScore` + `RoundTime=-1` |
| M03 多回合 BO 制 | 胜场制 | `MaxRoundCount=3, ModeWinRoundCount=2` |
| M04 有复活 | 死亡倒计时重生 | `RelifeData.relifeTimer`（3~10s）|
| M05 无复活淘汰 | 死亡不复活 | 无 RelifeData |
| M06 PVE 协作 | 全员同队打 AI | `MaxRoleNumPerTeam = MaxRoleNum` |
| M07 物品掉落 | 击杀掉落可拾取 | 开启 `ServerModeDropItem` |
| M08 自动拾取 | 进入范围自动拾取 | 开启 `ServerModeAutoPickUpItem` |
| M09 无限火力 | 弹夹永不耗尽 | `IsUnlimitedFireMode = true` |

## 4. 战斗系统全景

### 4.1 战斗系统构成总览

```
战斗系统
├── 枪械系统       ← 玩家武器、射击、弹道、换弹
├── Ability 系统   ← 技能 AB（主动/被动）+ 效果 AE（buff/debuff）
├── GPO 系统       ← 所有 AI 单位（怪物/Boss/炮台/载具/道具/场景机关）
├── 载具系统       ← 可驾驶单位（坦克/直升机）
├── 3C 系统        ← 角色移动/跳跃/瞄准/视角
├── 镜头系统       ← 摄像机跟随/视角切换（纯客户端）
└── 模式系统       ← 回合/积分/胜负/AI 波次管理
```

### 4.2 伤害结算流程

```
触发伤害
  ↓
命中判定（悬浮武器按命中率判定 / 普通枪械按射线/碰撞判定）
  ↓
基础伤害计算（攻击力 × 暴击率 × 各类加成倍率）
  ↓
元素附加（命中附加灼烧/感电等 Debuff 层数）
  ↓
元素派生链触发（灼烧 → 火球 → 陨石 / 感电 → 电弧 → 落雷）
  ↓
击杀判定（HP ≤ 0）
  ↓
击杀奖励结算（积分 / 掉落物 / 词条触发 / 吸血回复）
  ↓
飘字表现（血量数字 / 暴击/元素色彩区分）
```

### 4.3 关键数值设计原则

- **暴击**：暴击率（%）× 暴击伤害（%），通用词条可叠加提升
- **元素伤害**：独立于物理伤害计算，受元素伤害加成词条影响
- **吸血**：击杀或命中时回复己方 HP，来源于 Ability AE 词条
- **免伤**：减少受到伤害的百分比，有配表上限防止无限叠加

## 5. 敌人与关卡设计（GPO体系）

GPO（Game Play Object）是所有非玩家单位的统一管理框架，覆盖怪物、Boss、炮台、载具、道具、场景机关等。

### 5.1 GPO 单位类型全表

| 分类 | GPO 模板 | 行为特征 | 攻击方式 |
|------|---------|---------|---------|
| **载具** | GPOM_Tank | 可被玩家驾驶，炮击攻击 | 炮弹/机枪 |
| **载具** | GPOM_Helicopter | 空中载具，可驾驶 | 机枪/导弹 |
| **固定炮台** | GPOM_Turret | 固定旋转炮台，自动索敌 | 炮弹 |
| **固定炮台** | GPOM_MachineGun | 多炮管机枪炮台，过热冷却机制 | 连发子弹 |
| **固定炮台** | GPOM_MissileBattery | 导弹车，追踪导弹 | 追踪导弹 |
| **无人机** | GPOM_Uav | 空中飞行，巡逻攻击 | 投弹/机枪 |
| **场景机关** | GPOM_MobileControlPoint | 移动控制点，触发积分 | 无攻击 |
| **场景机关** | GPOM_SceneGpo | 通用场景物件（宝箱/开关等）| 无攻击 |
| **BOSS** | GPOM_RexKing | 霸王龙 Boss，多阶段 | 喷火/爪击/召唤 |
| **BOSS** | GPOM_SwordTiger | 剑虎 Boss，冲刺攻击 | 冲刺/挥爪 |
| **BOSS** | GPOM_WuGui | 乌龟 Boss，龟壳防御 | 体冲/吐弹 |
| **BOSS** | GPOM_FeiYu | 飞鱼 Boss，空中飞行 | 俯冲/吐弹 |
| **道具** | GPOM_GoldenEgg | 金蛋道具，可拾取 | 无攻击 |
| **替身/靶** | GPOM_Dummy / GPOM_HeroDummy | 训练靶，无主动行为 | 无攻击 |
| **角色 AI** | GPOM_Character | AI 英雄角色，有技能 | 多样 |
| **刷怪器** | GPOM_Gpospawner | 波次控制器，无实体 | 无攻击 |
| **盾牌** | GPOM_Shield | 格挡投射物的护盾体 | 无攻击 |

### 5.2 GPO 通用属性字段

> 每种 GPO 必须在 GPOM 配置表中填写以下基础属性（不得留空）：

| 字段 | 含义 | 单位 | 必填 |
|------|------|------|------|
| `Hp` | 最大血量 | 点 | ✅ |
| `Atk` | 基础攻击力 | 点 | ✅（有攻击行为时）|
| `MoveSpeed` | 移动速度 | m/s | ✅（有移动行为时）|
| `AttackDistance` | 攻击范围 | m | ✅（有攻击行为时）|
| `AttackIntervalTime` | 攻击间隔 | s | ✅（有攻击行为时）|
| `SearchDistance` | 索敌范围 | m | ✅（有自动索敌时）|
| `Scale` | 模型缩放 | 倍率 | ✅（与碰撞强绑定，需由服务端设置）|

### 5.3 GPO 行为模式设计规范

每个 GPO 的行为由以下四个维度决定：

#### 索敌规则

| 索敌方式 | 说明 | 适用单位 |
|---------|------|---------|
| 球形范围检测 | 每 0.5s 检测周围 N 米内最近目标 | 炮台、怪物 |
| 视野扇形检测 | 有前向视野限制 | AI 角色 |
| 无索敌 | 不主动攻击 | 场景机关、道具 |

#### 移动规则

| 移动方式 | 说明 | 适用单位 |
|---------|------|---------|
| 静止不动 | 原地攻击 | 炮台 |
| 寻路追击 | NavMesh 寻路 | 地面怪物 |
| 巡逻路径 | 预设巡逻点 | 无人机、巡逻兵 |
| 随机区域移动 | 在指定区域内随机游走 | 部分怪物 |
| 跟随玩家 | 始终朝向/跟随特定目标 | 召唤物、宠物 |

#### 攻击规则

> 所有攻击必须明确：触发条件 / 伤害数值 / 攻击范围 / 攻击间隔 / 命中判定方式 / 子弹类型（若有）

#### 死亡规则

| 规则 | 说明 |
|------|------|
| 死亡掉落 | 掉落道具/金币（配置掉落表）|
| 击杀归属链 | 召唤物击杀须归属到最顶层 MasterGPO（即召唤玩家）|
| 死亡特效 | 指定死亡时播放的特效/音效 |

### 5.4 刷怪设计规范（动态极坐标系统）

PVE 模式使用**以玩家为圆心的极坐标刷怪系统**，规则如下：

| 参数 | 推荐值 | 说明 |
|------|-------|------|
| 最小生成距离（内径）| 4m | 玩家周围 4m 内不生成 |
| 最大生成距离（外径）| 12m | 超出 12m 范围不生成 |
| 前方权重（±60°）| 高权重 | 大量刷怪，迎面挑战感 |
| 侧方权重（±60~120°）| 中权重 | 侧翼压力 |
| 后方权重（120~180°）| 低权重 | 偶有背刺压力 |

**波次时间轴格式**：
```
触发条件：当前回合数 == X，且回合内已过时间 == Y秒
行为：从配置的"怪物组ID列表"中随机抽取一组
生成逻辑：N只怪物在 [Y秒, Y+间隔秒] 区间内随机分散逐个生成（协程离散）
```

### 5.5 Boss 设计规范

每个 Boss 策划案必须提供以下内容：

| 设计项 | 必填内容 |
|--------|---------|
| 阶段划分 | HP 百分比阈值（如 100%→70%→40%→死亡）|
| 每阶段行为 | 技能列表 + 切换触发条件 |
| 技能详情 | 动作名 / 伤害值 / 范围 / 前摇时间 / CD |
| 难度分档 | 按人数（1/2/4 人）提供不同 HP 和伤害倍率表 |
| 弱点设计 | 是否有特定弱点部位 / 破防机制 |
| 召唤物 | 若有召唤物，提供完整归属链说明 |

## 6. 枪械与武器系统

### 6.1 枪械类型总览

| 枪械类型 | 攻击方式 | 特点 |
|---------|---------|------|
| 普通步枪/突击枪 | 单点射击 | 中距离，通用 |
| 散弹枪 | 扇形扩散 | 近距离高伤 |
| RPG 火箭筒 | 弧线弹道 | AOE 爆炸 |
| 手雷/投掷物 | 抛物线 | 延迟爆炸 AOE |
| 近战（棒球棍等）| 近身范围 | 高单体伤害 |
| 特殊枪（穿透弹/追踪弹）| 特殊弹道 | 依据词条/技能赋予 |

### 6.2 枪械核心属性字段

> 每把新枪必须填写以下所有属性，不得留空：

| 字段 | 含义 | 单位 | 必填 |
|------|------|------|------|
| 枪械 ID | 唯一标识符 | - | ✅ |
| 元素枚举 | 无/火/电/冰/毒等 | 枚举 | ✅ |
| 元素伤害 | 附加的元素伤害值 | 点 | ✅ |
| 悬浮命中率 | 悬浮模式下的命中概率 | % | ✅（多武器PVE）|
| 射击间隔 | 两次射击最短间隔 | s | ✅ |
| 弹夹容量 | 单弹夹子弹数 | 发 | ✅ |
| 换弹时间 | 换弹动作耗时 | s | ✅ |
| 射程 / 最大距离 | 子弹有效射程 | m | ✅ |
| 基础伤害 | 单发命中伤害 | 点 | ✅ |
| 暴击率 | 基础暴击概率 | % | ✅ |
| 暴击伤害倍率 | 暴击时伤害倍率 | 倍 | ✅ |

### 6.3 悬浮武器系统设计规范（多武器PVE 专属）

| 规则 | 说明 |
|------|------|
| 最大挂载数 | 4 把（读全局配置，策划可调） |
| 挂点分配 | 获得新武器自动占用编号最小的空闲挂点 |
| CenterPos 延迟跟随 | 玩家移动后 0.1s（可配）开始跟随 |
| 追赶距离阈值 | CenterPos 与玩家距离 > N米 时乘速倍率追赶 |
| 命中判定 | 直接按配置的悬浮命中率（如85%）判定，无散布和后坐力 |
| 射击独立性 | 跟随移动时也能独立索敌开火 |

### 6.4 新枪注册流程（策划需配合程序完成）

策划设计新枪时，需同时提供：
1. **外观方案**：枪械模型 ID + 皮肤绑定
2. **属性表**：填写 6.2 中所有字段
3. **弹道类型**：直线 / 弧线 / 扇形 / 追踪（选一或组合）
4. **元素类型**：所属元素枚举
5. **动画配置**：射击动画标识、换弹动画标识

## 7. 技能与效果系统（Ability / AE）

### 7.1 系统职责

| 层级 | 名称 | 策划理解 |
|------|------|---------|
| AB（Ability） | 技能行为 | 一次「可见动作」：发射火球、召唤陨石、喷吐火柱 |
| AE（AbilityEffect） | 技能效果 | 持续型 Buff/Debuff：灼烧、感电、速度提升、吸血 |

**关系**：AB 触发时可以附加 AE（如火球命中目标后施加灼烧 AE）；AE 可以周期性触发新 AB（如灼烧每秒触发一次伤害 AB）。

### 7.2 元素派生链设计（PVE 核心 BD）

#### 火元素流派

| 派生层级 | 词条名 | 触发条件 | 效果 | 前置要求 |
|---------|--------|---------|------|---------|
| 基础 | 灼烧 | 火元素武器命中 | 持续掉血，可叠层，满层重置最早层 | 无 |
| 1级 | 火球 | 命中 X 次后 | 概率发射火球（AOE + 附加灼烧）| 无 |
| 2级 | 陨石 | 火球爆炸后 | 概率召唤陨石坠落（延迟，AOE + 灼烧）| 持有「火球」词条 |
| 3级 | 燃烧区 | 陨石坠地后 | 生成持续圆形火圈（持续伤害）| 持有「陨石」词条 |
| 特化 | 爆燃 | 灼烧目标受到火伤时 | 概率清空灼烧层数，瞬间全额结算剩余伤害 | 持有「灼烧」词条 |

#### 电元素流派

| 派生层级 | 词条名 | 触发条件 | 效果 | 前置要求 |
|---------|--------|---------|------|---------|
| 基础 | 感电 | 电元素武器命中 | 目标受所有伤害额外增加 X% | 无 |
| 1级 | 电弧 | 命中后 | 概率弹射到就近敌人；感电目标额外增幅 | 无 |
| 2级 | 落雷 | 暴击/概率触发 | 延迟劈下落雷（定点），附加感电 | 无 |
| 3级 | 地面电流 | 落雷触地后 | 向外扩散多道电流（单目标不重复受伤）| 持有「落雷」词条 |
| 特化 | 静电场 | 感电目标受到电伤时 | 对周围爆发闪电 AOE，并传染感电 | 持有「感电」词条 |

### 7.3 词条（BD）卡池设计规范

> 三选一 Roguelike 词条每次弹出必须满足以下设计要求：

| 设计项 | 要求 |
|--------|------|
| 卡池构成 | 通用词条池 + 玩家当前武器元素对应的流派词条池 |
| 流派权重叠加 | 同元素武器数量 N 把时，该流派词条基础权重乘以倍率 |
| 品质成长 | 仅紫/橙/红品质词条随回合数提升权重 |
| 前置依赖 | 必选项：全部拥有才激活；任选项：拥有任意一个即激活 |
| 刷新禁止重复 | 同一选择窗口内，刷新后禁止出现与上次完全相同的词条列表 |

### 7.4 Debuff 层叠设计规范（必填项）

设计有层叠机制的 Debuff 时，策划案必须提供：

| 配置项 | 含义 | 示例 |
|--------|------|------|
| 最大层数 | 能叠加的最多层数 | 10 层 |
| 单层伤害/效果 | 每层带来的数值效果 | 每层每秒 50 伤害 |
| 单层持续时间 | 每层的存续时长 | 5 秒 |
| 满层行为 | 层数满了之后的特殊处理 | 重置最早层的时间戳 |
| 叠层来源限制 | 同一来源是否可叠加 | 同一玩家可叠，不同玩家也可叠 |

### 7.5 通用词条类型

| 类别 | 词条示例 | 叠加规则 |
|------|---------|---------|
| 无限叠加 | 所有元素伤害+%、武器暴击伤害+%、最大生命值+% | 无上限 |
| 有限叠加 | 射速+%、暴击率+%、换弹速度+%、移速+%、免伤+% | 需配表上限 |

## 12. 全局事件编排系统（EventDirector）

EventDirector 是面向策划的高阶事件编排工具，用于配置游戏内的「特殊时机触发特殊玩法变化」，不需要程序额外写代码。

### 12.1 四维配置结构

| 维度 | 含义 | 示例配置 |
|------|------|---------|
| **时间（Time）** | 事件在何时窗口内有效 | 任意时间 / 回合开始后10秒 / 模式开始时 |
| **主体（Subject）** | 事件作用于谁 | 全体玩家 / 指定 AI 类型 / 特定 GPO |
| **条件（Condition）** | 满足什么条件后触发 | 玩家开火N次 / 击杀N只怪 / 玩家进入区域 |
| **动作（Action）** | 条件满足后执行什么 | 召唤AI / 回复HP / 开启无限弹药 / 积分翻倍 |

### 12.2 已支持的事件动作清单（无需新增代码）

| 动作 | 说明 |
|------|------|
| 召唤 AI | 指定位置召唤特定类型 GPO |
| 回复 HP | 对主体回复一定比例/数值 HP |
| 积分倍率提升 | 提升当前积分获取倍率 |
| 开启无限弹药 | 一段时间内弹夹不消耗 |
| 播放 Ability 效果 | 触发一次 AB 技能（如范围爆炸）|

### 12.3 事件配置规范

策划在需要特殊事件时，必须提供：

| 配置项 | 要求 |
|--------|------|
| 触发条件 | 明确的数值条件（X次/Y血量/Z时间），不得用「一定程度后」|
| 触发概率 | 若非100%触发，必须给出具体百分比 |
| 冷却时间 | 同一事件两次触发的最短间隔 |
| 最大触发次数 | -1=无限次；正整数=最多触发N次 |
| 同屏上限 | 若触发召唤，需说明场上同时最多几个 |

## 14. 多人联机架构（策划视角）

### 14.1 权威服务器模型

所有战斗逻辑由**服务端**权威计算，客户端仅负责表现与输入上报：

```
[玩家输入] → 客户端本地预测 → 发送给服务端
                                    ↓
                              服务端处理（权威）
                                    ↓
                         广播结果给所有客户端 → 客户端修正表现
```

**策划设计影响**：
- 所有伤害结算、AI 行为、胜负判定均在服务端执行
- 客户端上的表现（特效、动画、飘字）与服务端逻辑分离
- 网络延迟会影响表现的响应感，设计时需考虑容错与预测

### 14.2 匹配机制

| 模式 | 支持匹配人数 |
|------|-----------|
| 多武器 PVE | 单人 / 双人 / 四人 |
| 5V5 模式 | 5人队伍 或 单排匹配至满10人 |
| 1V1 | 双人 |

**匹配原则**：不强行补充机器人，玩家人数不足时按实际人数动态索引难度配置表。

### 14.3 断线保护

- 玩家断线后 30 秒内可重连，重连后补偿游戏状态
- 断线超过 30 秒则视为离线，触发离线保护（队友继续游戏）
