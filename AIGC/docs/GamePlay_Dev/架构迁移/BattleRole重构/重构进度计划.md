## 架构规范（重要，施工时遵守）

1. BattleRole 不持有组件引用 → 一切通过 Dispatcher/Register
2. 外部读写的字段必须在 BattleRole.cs 声明为 public
3. 组件间通信只用事件
4. 组件写 `role.fieldName = value`（不是自己的副本）
5. SideAimComponent 对 role.PlayFireState() 等方法的调用是直接调用（不是 Dispatcher）
6. **每次迁移后必须做代码对照审查**：将新组件的 AddUpdate / Event Handlers 与 `refactor/Back/` 中对应原始方法逐一比对，确认：
   - 所有原始方法调用都已在组件中对应（AddUpdate 或 Event 触发）
   - 条件守卫（IsLocalRole / IsTeammateBehavior / isLocalOrWatched 等）是否正确迁移
   - 是否有遗漏的 Dispatcher 调用（事件已注册但从未 dispatch）
   - 确认后在进度计划中注明"已对照审查 ✅"
