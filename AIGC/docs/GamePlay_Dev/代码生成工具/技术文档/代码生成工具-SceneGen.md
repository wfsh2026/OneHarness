## 零、定位声明

本文档是**完整场景创建流水线**的技术参考。AI Agent 在执行新场景创建任务前**必须阅读本文档**。

## 一、工具概述

`scene-gen.sh` 是一键创建新场景的**完整注册链路**工具，覆盖从 Map.cs ID 注册到服务端场景生成的全部流程。

**核心特征**：
- 一次命令完成 5 个步骤的注册和文件创建
- **两步强制流程**：Bash 脚本（Step A）+ Unity MCP 调用（Step B），**服务端场景不可跳过**
- 每个步骤内置幂等检查，重复运行不会重复写入

**与 `scene-server-gen.sh` 的关系**：

| 工具 | 适用场景 | 覆盖范围 |
|------|---------|---------|
| `scene-gen.sh` | **新建场景**（全链路） | Map.cs + SceneData + SceneConfig + 场景复制 + 服务端转换 |
| `scene-server-gen.sh` | **单独重生成服务端场景**（如客户端场景更新后） | 仅场景复制 + 服务端转换 |

> 新建场景时**必须使用 `scene-gen.sh`**，禁止手动创建 SceneConfig 或注册 Map.cs/SceneData.cs。

| `--mode-switch-res` | = `--sign` | Map ModeSwitchRes |

| 参数 | 默认值 | 说明 |
|------|--------|------|

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--stage-sign` | = `--name` | SceneData StageSign |
| `--element-config` | = `--name` | SceneData ElementConfig |

| 参数 | 默认值 | 说明 |
|------|--------|------|

### 可选参数 — 跳过步骤

| 参数 | 说明 |
|------|------|
| `--skip-map` | 跳过 Map.cs 注册（Step 1） |
| `--skip-scene-data` | 跳过 SceneData_AutoGenerated.cs 注册（Step 2） |
| `--skip-config` | 跳过 SceneConfig.asset 创建（Step 3） |

> ⚠️ **服务端场景生成为强制步骤，没有 skip 选项。**

## 四、执行流程

### Step 1: Map.cs 注册（ID 常量 + Data 数组条目）

**跳过条件**：`--skip-map`

**幂等检查**：搜索 `Id_{SIGN}`，已存在则跳过并从现有条目读取 `MAP_ID`。

**操作**：
1. **自动分配 Map ID**：扫描 Map.cs 中所有 `public const int Id_*` 声明，取最大值 + 1（如未指定 `--map-id`）
2. **插入 ID 常量**：在最后一个 `Id_` 常量行之后插入，缩进为 **2 个 TAB**
   ```csharp
   		public const int Id_NewCity = 15;
   ```
3. **插入 Data 数组条目**：在 `Data = new Map[]` 数组的闭合 `};` 之前插入，缩进为 **5 个 TAB**
   ```csharp
   					, new Map( 15, "新城市", "NewCity", "NewCity", "MapNew", false, 0, "NewCity" )
   ```

### Step 2: SceneData_AutoGenerated.cs 注册

**跳过条件**：`--skip-scene-data`

**幂等检查**：搜索 `MapSet.Id_{SIGN}`，已存在则跳过。

**操作**：
1. 如果 `SceneData_AutoGenerated.cs` 不存在，**自动创建初始模板**（含 partial class + static constructor + 标记注释）
2. 在 `[END_GENERATED_SCENE_DATA]` 标记行之前插入新注册行：
   ```csharp
               datas.Add(new Data { ID = MapSet.Id_NewCity, StageSign = "MapTDM_07_NewCity", ElementConfig = "MapTDM_07_NewCity" });
   ```
3. 若指定 `--festival-asset`，StageSign 值会使用 `FestivalAssetData.GetMapAsset("...")` 包装

### Step 3: SceneConfig.asset 创建（YAML 模板）

**跳过条件**：`--skip-config`

**幂等检查**：检查 `Assets/Bundle/Configs/Scene/{NAME}.asset` 是否已存在，已存在则跳过。

**操作**：
1. 确保 `Assets/Bundle/Configs/Scene/` 目录存在
2. 生成最小可用的 Unity YAML 格式 SceneConfig.asset（详见 §九）
3. `PlayerSpawnPoints` 等数组字段为空，需后续在 Unity 编辑器中填入

### Step 4: 客户端场景复制（可选）

**触发条件**：指定了 `--copy-from` 参数

**操作**：
1. 解析 `--copy-from` 路径：
   - 完整 `Assets/` 路径 → 直接使用（自动处理 `.unity` 后缀）
   - 简单场景名 → 拼接 `{scene-dir}/{name}.unity`
2. 验证源场景文件存在
3. 复制 `.unity` 文件到目标路径（不复制 `.meta` 文件，Unity 自动生成新 GUID）
4. 如目标已存在则覆盖

### Step 5: 服务端转换配置（强制步骤，不可跳过）

**操作**：
1. 将场景名写入临时配置文件：`{ProjectRoot}/Temp/AIGC_SceneConvertConfig.txt`
2. 输出强制提示：AI Agent 必须执行 Step B

### Step B: MCP 执行服务端场景转换（AI 必须调用 execute_menu_item）

**调用**：
```
execute_menu_item "Tools/功能/场景/AI场景转换"
```

**Unity 自动执行**：
1. 读取 `Temp/AIGC_SceneConvertConfig.txt` 获取目标场景名
2. 打开客户端场景
3. 删除旧服务端场景（如有 `Server{NAME}.unity`）
4. 执行场景优化（移除渲染组件、设置 `IsServer=true`、添加 `HitType` 等）
5. 另存为 `Server{NAME}.unity`
6. 注册 EditorBuildSettings（客户端 + 服务端场景）
7. 删除临时配置文件
8. 回切到客户端场景

## 六、幂等性保证

| 步骤 | 幂等检查机制 | 重复运行行为 |
|------|------------|------------|
| Step 1: Map.cs | `grep "Id_{SIGN}"` 检查 ID 常量是否已存在 | 跳过注册，从已有条目读取 MAP_ID |
| Step 2: SceneData | `grep "MapSet.Id_{SIGN}"` 检查注册行是否已存在 | 跳过注册 |
| Step 3: SceneConfig | 检查 `.asset` 文件是否已存在 | 跳过创建 |
| Step 4: 场景复制 | 目标文件存在时**覆盖**（输出警告） | 覆盖已有场景 |
| Step 5: 配置写入 | 无需幂等（每次覆盖写入） | 覆盖临时配置 |
| Step B: MCP 转换 | Unity 侧删除旧 Server 场景后重建；EditorBuildSettings 注册前检查是否已存在 | 重建服务端场景 |

## 七、SceneData_AutoGenerated.cs 架构

### 设计模式

采用 **partial class + static constructor** 设计，将自动生成的场景注册数据与手写的 `SceneData.cs` 分离。

```
SceneData.cs（手写）         SceneData_AutoGenerated.cs（自动生成）
┌───────────────────┐       ┌──────────────────────────────┐
│ partial class     │       │ partial class SceneData       │
│ SceneData         │  ←──  │   static SceneData() {        │
│                   │       │     // [GENERATED_SCENE_DATA]  │
│ // 手动维护的     │       │     datas.Add(...);            │
│ // 场景逻辑       │       │     datas.Add(...);            │
│                   │       │     // [END_GENERATED_SCENE_DATA] │
└───────────────────┘       │   }                           │
                            └──────────────────────────────┘
```

### 标记注释

| 标记 | 用途 |
|------|------|
| `// [GENERATED_SCENE_DATA]` | 自动生成区域的起始标记 |
| `// [END_GENERATED_SCENE_DATA]` | 自动生成区域的结束标记，新条目插入到此标记之前 |

### 自动创建的初始模板

当 `SceneData_AutoGenerated.cs` 不存在时，脚本自动创建：

```csharp
// ─────────────────────────────────────────────────────
// 本文件由 scene-gen.sh 自动生成，请勿手动修改。
// 手写场景数据请编辑 SceneData.cs
// ─────────────────────────────────────────────────────
using Sofunny.BiuBiuBiu2.Template;

namespace Sofunny.BiuBiuBiu2.Data {
    public partial class SceneData {
        static SceneData() {
            // [GENERATED_SCENE_DATA] — 以下由 scene-gen.sh 自动生成，请勿手动修改
            // [END_GENERATED_SCENE_DATA]
        }
    }
}
```

### 注册行格式

```csharp
            datas.Add(new Data { ID = MapSet.Id_{SIGN}, StageSign = "{STAGE_SIGN}", ElementConfig = "{ELEMENT_CONFIG}" });
```

当使用 `--festival-asset` 时：

```csharp
            datas.Add(new Data { ID = MapSet.Id_{SIGN}, StageSign = FestivalAssetData.GetMapAsset("{STAGE_SIGN}"), ElementConfig = "{ELEMENT_CONFIG}" });
```

## 八、Map.cs 数据格式

### ID 常量

- **缩进规则**：2 个 TAB
- **插入位置**：紧跟在最后一个 `Id_` 常量声明之后
- **格式**：

```csharp
		public const int Id_{SIGN} = {MAP_ID};
```

### Data 数组条目

- **缩进规则**：5 个 TAB
- **插入位置**：`Data = new Map[]` 数组的闭合 `};` 之前
- **格式**：

```csharp
					, new Map( {ID}, "{DISPLAY_NAME}", "{SIGN}", "{RES_SIGN}", "{RES_ICON}", {IS_DEFAULT}, {SORT}, "{MODE_SWITCH_RES}" )
```

### Map 构造函数 8 参数

| 序号 | 参数 | 类型 | 来源 | 说明 |
|-----|------|------|------|------|
| 1 | id | `int` | `--map-id` 或自动递增 | 地图唯一 ID |
| 2 | displayName | `string` | `--display-name` | 中文显示名 |
| 3 | sign | `string` | `--sign` | 标识符 |
| 4 | resSign | `string` | `--res-sign`（默认 = sign） | 资源标识 |
| 5 | resIcon | `string` | `--res-icon`（默认 `"MapNew"`） | 图标资源名 |
| 6 | isDefault | `bool` | `--is-default`（默认 false） | 是否默认地图 |
| 7 | sort | `int` | `--sort`（默认 0） | 排序值 |
| 8 | modeSwitchRes | `string` | `--mode-switch-res`（默认 = sign） | 模式切换资源 |

### ID 自动递增逻辑

```bash
# 扫描所有 public const int Id_* 声明，取最大数值 + 1
MAP_ID=$(grep -oE 'public const int Id_\w+\s*=\s*[0-9]+' "$MAP_FILE" \
    | grep -oE '[0-9]+$' | sort -n | tail -1)
MAP_ID=$((MAP_ID + 1))
```

## 十、Bug 记录

### Bug#11: `--copy-from` 路径拼接

**问题**：早期版本 `--copy-from` 仅支持简单场景名，传入完整 `Assets/` 路径时会拼接出错误路径。

**修复**：增加路径前缀判断，支持两种输入格式：

```bash
if [[ "$COPY_FROM" == Assets/* ]]; then
    # 完整相对路径：直接使用（自动处理 .unity 后缀）
    SRC_SCENE="$PROJECT_ROOT/${COPY_FROM%.unity}.unity"
else
    # 简单场景名：拼接 scene-dir
    SRC_SCENE="$SCENE_FULL_DIR/${COPY_FROM%.unity}.unity"
fi
```

**当前状态**：✅ 已修复。两种路径格式均可正常工作。

### 服务端场景强制化（移除 `--skip-server`）

**问题**：早期版本存在 `--skip-server` 参数，允许跳过服务端场景生成。导致新建场景流水线不完整，服务端缺少对应场景文件。

**修复**：移除 `--skip-server` 参数，服务端场景转换配置（Step 5）为强制步骤，始终执行。

**当前状态**：✅ 已强制化。脚本参数列表中不存在 `--skip-server`。
