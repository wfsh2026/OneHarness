## 一、需求分析 — ⚠️ 需求与工具适用性判断

### 原始需求定位

BIU26 悬浮武器 Ability 技术文档（S-04）明确指出：

> **复用 `AB_TrackingMissle`（ConfigId 10040）类型**，通过新增 CSV 数据行 + AbilityEditor 重新生成配置常量来接入，**不新建 SAB/CAB 系统类**。

这意味着原始需求是一个 **"复用现有类型"** 场景：
- ❌ 不需要新建 AbilityM_XXX.cs（复用 AbilityM_TrackingMissle）
- ❌ 不需要新建 SAB/CAB System（复用现有的 SAB/CAB_TrackingMissleSystem）
- ✅ 只需追加 CSV 数据行 + 重新运行 AbilityEditor 生成常量

### ability-gen.sh 适用性

`ability-gen.sh` 设计用于 **创建全新 Ability 类型**（新 M_ 数据类 + Select + System + RPC + CSV），与本需求的"复用"场景不直接匹配。

### 执行方案

为验证 `ability-gen.sh` 工具的完整能力，本计划按 **"新建全新 Ability 类型"** 方式执行，创建 `AB_BIU26FloatingWeaponBullet` 作为独立类型（而非复用 TrackingMissle）。

> **⚠️ 请用户确认**：是按"新建类型"方式验证工具，还是只做 CSV 追加？如果只做 CSV 追加，则不需要 ability-gen.sh。

## 二、执行命令

### 命令

```bash
ability-gen.sh \
  --name BIU26FloatingWeaponBullet \
  --type AB \
  --fields "M_TrackSpeed:float,M_LockSpeed:float,M_MoveDistance:float,M_LifeTime:float,M_Power:int" \
  --csv-fields "M_TrackSpeed,M_LockSpeed,M_MoveDistance,M_LifeTime,M_Power" \
  --primary-keys "M_Sign" \
  --sync-client true \
  --in-fields "In_StartPoint:Vector3,In_TargetPoint:Vector3,In_TargetGPOId:int,In_WeaponItemId:int" \
  --project-root <项目根目录>
```

### 参数说明

| 参数 | 值 | 来源 |
|------|-----|------|
| `--name` | `BIU26FloatingWeaponBullet` | 基于需求名称，独立 AB 类型 |
| `--type` | `AB` | 短效技能类型（飞弹命中后销毁） |
| `--fields` | 5 个 M_ 字段 | 参考 AbilityM_TrackingMissle 的字段结构（S-05 §配表层） |
| `--csv-fields` | 与 fields 对应 | CSV 列头 |
| `--primary-keys` | `M_Sign` | 默认主键 |
| `--sync-client` | `true` | 需要客户端飞弹表现 |
| `--in-fields` | 4 个 In_ 字段 | 来源于 S-06 链路中的 InData 字段 + S-08 §8.2 调用示例 |

### M_ 字段详解（来源：AbilityM_TrackingMissle 字段参考）

| 字段 | 类型 | 说明 | 建议 CSV 默认值 |
|------|------|------|----------------|
| `M_TrackSpeed` | float | 追踪飞行速度 | 15 |
| `M_LockSpeed` | float | 锁定后飞行速度 | 20 |
| `M_MoveDistance` | float | 最大飞行距离 | 30 |
| `M_LifeTime` | float | 生命周期（秒） | 2.0 |
| `M_Power` | int | 基础伤害值 | 300 |

### In_ 字段详解（来源：S-08 §8.2 Ability 工程师填桩信息）

| 字段 | 类型 | 说明 |
|------|------|------|
| `In_StartPoint` | Vector3 | 悬浮武器世界坐标（发射起点） |
| `In_TargetPoint` | Vector3 | 目标 Body Transform 位置 |
| `In_TargetGPOId` | int | 锁定目标 GPO ID |
| `In_WeaponItemId` | int | 武器物品 ID（Phase 1 暂为 0） |

## 四、工具局限性说明

### 4.1 工具完成 vs 需要手动补充

| 方面 | 工具生成 | 需手动补充 |
|------|---------|-----------|
| M_ 数据类 + 字段 | ✅ | — |
| In_ 输入数据类 | ✅ 空壳 class | 字段由 --in-fields 自动填入 |
| Select 缓存系统 | ✅ 完整 | — |
| Server System 骨架 | ✅ 含教学注释 | 飞行轨迹逻辑、命中判定、伤害计算 |
| Client System 骨架 | ✅ 含教学注释 | 飞弹飞行表现、爆炸特效 |
| RPC 结构体 | ✅ | 可能需要追加字段 |
| CSV 文件 | ✅ 空表头 | 填入 BIU26 数据行 |
| 所有注册 | ✅ 原子操作 | — |

### 4.2 与原始需求的差异

| 原始需求（复用 TrackingMissle） | 本方案（新建独立类型） |
|-------------------------------|---------------------|
| 复用已有 SAB/CAB System | 新建独立 SAB/CAB System |
| 只追加 CSV 行 | 创建完整 CSV 文件 |
| ConfigId 在 10040 下新增行 | 新分配独立 ConfigId |
| 共享 M_ 字段结构 | 独立 M_ 字段定义 |
| 变更范围极小 | 变更范围完整（但后续可独立演化） |
