# 假设验证晋升

## 结论

未验证想法不应直接写成项目事实。探索型内容应先作为假设记录，经过验证或用户确认后，才能晋升为机制、决策或稳定知识。

## 建议状态流

```text
想法 -> 假设 -> 验证记录 -> 已确认事实/机制/决策
                  \
                   -> 被否决方案
```

## 适用范围

- 新玩法、新功能、新交互。
- 有多个可能方向的方案探索。
- 需要保留为什么“不做某方案”的场景。

## 写入建议

- 假设写入项目 wiki 的候选区、开放问题或运行记录。
- 验证结果写入运行记录或验证报告。
- 成立结论写入项目 wiki。
- 不成立结论写入被否决方案或废弃记录，并说明原因。

## 来源

来自旧项目删除前审查中提取的可复用假设验证经验，详见来源索引。当前 AIGC 抽象为通用候选知识。
