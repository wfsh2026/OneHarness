# 1 代架构制作文档编写规范

> 本文档定义 `aigc/wiki/raw/sausage-man/制作文档/` 目录下所有制作文档的标准格式。
> 所有批次产出的制作文档必须遵循本规范。

---

## 一、文件命名

- 格式：`{系统中文名}制作.md`
- 示例：`载具制作.md`、`模式制作.md`、`角色3C制作.md`
- 路径：统一存放于 `aigc/wiki/raw/sausage-man/制作文档/{领域}/`（领域对应 features/ 子目录名）

---

## 二、文档结构（强制章节）

每份制作文档必须包含以下章节，章节编号和标题格式必须一致：

```markdown
# 1 代架构{系统名}制作规范

> **适用范围**：{明确说明本文档覆盖的功能/类型范围}
> **不适用**：{明确排除的范围，如有}（无则省略）
> **参考实现**：{推荐参考的已有实现}（无则省略）

---

## 一、架构概述
## 二、新建/扩展 Checklist
## 三、配置文件详解
## 四、关键代码修改点
## 五、常见问题与踩坑记录
## 六、验收标准
```

> ⚠️ 如果某个系统较为复杂，可在上述基础上插入章节（如"预制体制作要点"），但不可删减强制章节。

---

## 三、各章节内容要求

### 3.1 文件头

| 要素 | 要求 | 示例 |
|------|------|------|
| **标题** | `# 1 代架构{系统名}制作规范` | `# 1 代架构模式制作规范` |
| **适用范围** | 明确覆盖哪些子类型/场景 | `基于 ClientModeBase 的对战模式开发` |
| **不适用** | 排除不在本文档范围内的（如 2 代实现） | `2 代 ECS 模式（Biubiubiu2/GamePlay/Mode/）` |
| **参考实现** | 推荐一个典型实现供读者参考 | `经典吃鸡（BR），路径 → Client/Modules/Mode/BR/` |

### 3.2 一、架构概述

必须包含以下子节：

#### 1.1 系统体系对比/分类（如有多种实现方式）

- 用 **对比表** 展示同一系统下不同实现方式的差异
- 维度：管理方式、网络同步、创建流程、预制体位置等

#### 1.2 核心类依赖

- 用 **ASCII 树形图** 展示核心类的继承/组合关系
- 格式：
```
Manager/Factory
    ├── Base.cs                ← 简要说明
    │   ├── SubA.cs            ← 简要说明
    │   └── SubB.cs            ← 简要说明
    └── Config/Data.cs         ← 简要说明
```
- 标注三端对应关系（Client/Server/Host 各自的入口类）

#### 1.3 预制体与资源加载（★ 强制）

- **必须**列出该系统涉及的所有预制体（Prefab）及其加载方式
- 包含以下信息：
  - **预制体路径**（`Assets/ToBundle/...` 或 `Assets/Art/...`）
  - **加载入口方法**（如 `AssetsLoad.LoadXxx()`）
  - **加载器源码位置**（如 `Assets/Script/Asset/Loaders/XxxLoader.cs`）
  - **创建时序**（哪个方法在什么时机调用加载，用 ASCII 流程图展示）
- 如该系统涉及动态加载资源（材质、动画控制器、ScriptableObject 等），一并列出
- 用表格 + 流程图的组合方式呈现

#### 1.4 禁止修改的文件（如有）

- 列出不可修改的核心文件及原因
- 格式：`**文件名** — 原因`

### 3.3 二、新建/扩展 Checklist

- 用 **分 Phase 的表格** 列出完整操作步骤
- 每个 Phase 是一个逻辑阶段（如"常量配置" → "代码修改" → "资源创建"）
- 表格列：`# | 文件 | 操作 | 说明`
- 使用 `{占位符}` 表示可替换内容（如 `{Sign}`、`{ModeName}`）
- **按执行顺序编号，不可跳步**

```markdown
### Phase 1：{阶段名}

| # | 文件 | 操作 | 说明 |
|---|------|------|------|
| 1 | `路径/文件名` | 新增/修改/检查 | 具体说明 |
| 2 | ... | ... | ... |
```

### 3.4 三、配置文件详解

- 为每个涉及的配置文件创建子节
- 每个配置文件必须包含：
  - **格式示例**（用代码块展示一条样例数据）
  - **字段说明表**：`字段 | 类型 | 说明`
  - **特殊注意事项**（如"Ratio 是权重值非百分比"）

### 3.5 四、关键代码修改点

- 为每个需要修改的代码位置创建子节
- 每处必须包含：
  - **文件路径**
  - **代码示例**（用 C# 代码块）
  - 用 `{占位符}` 标注可替换部分
  - 必要的注释说明触发链路

### 3.6 五、常见问题与踩坑记录

- 每个问题一个子节，编号递增（6.1, 6.2, ...）
- 每个问题必须包含三要素：
  - **问题现象**（加粗"原因"标签）
  - **根因分析**
  - **解决方案**
- 鼓励记录排查顺序（有序列表）

### 3.7 六、验收标准

- 按类别分组（编译、配置、运行时、资源等）
- 使用 Markdown checkbox 列表
- 每条验收项必须可独立验证

```markdown
### 6.1 编译
- [ ] 零 CS error
- [ ] Unity Console 无 NullReferenceException

### 6.2 运行时
- [ ] 功能 A 正常
- [ ] 功能 B 正常
```

## 四、格式规范

### 4.1 代码块

- C# 代码使用 ` ```csharp `
- 配置/YAML 使用 ` ```yaml `
- 目录结构使用 ` ``` `（无语言标识）

### 4.2 占位符

- 使用 `{大驼峰}` 格式：`{Sign}`、`{ModeName}`、`{SkillSign}`
- 文档开头需说明占位符含义

### 4.3 路径

- 代码路径从 `Assets/Script/` 开始
- 配置路径从 `Assets/ToBundle/` 开始
- 美术/预制体路径从 `Assets/Art/` 开始
- **⚠️ 所有路径必须与 [[resource-map]] 交叉验证**，禁止凭记忆填写

### 4.4 表格

- 对比表用 `|` 分隔
- 大段内容用独立子节而非表格内换行

### 4.5 三端标注

- 涉及 C/S/H 三端时，用前缀标注：
  - **C** = Client
  - **S** = Server
  - **H** = Host
- 在核心类依赖图中标注三端入口

## 五、质量检查清单

编写完成后自检：

- [ ] 文件头包含适用范围
- [ ] 架构概述有核心类依赖树
- [ ] **预制体/资源加载有完整表格 + 创建时序流程图（★ 强制）**
- [ ] Checklist 步骤完整且按顺序
- [ ] 配置文件有格式示例 + 字段说明
- [ ] 代码修改点有代码示例
- [ ] 常见问题不少于 3 条
- [ ] 验收标准覆盖编译/运行时
- [ ] 占位符使用一致
- [ ] 无 2 代文档引用（ADR#2）
