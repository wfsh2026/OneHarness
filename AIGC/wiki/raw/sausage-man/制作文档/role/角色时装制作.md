## 一、架构概述

### 1.1 三层架构

角色时装系统采用三层架构设计，自顶向下为：总管理器层 → 部件状态机层 → 模块化插槽层。

```
第一层：SkinManager (总管理器)
  │  职责: 协调所有 18 部件的加载/卸载/合并
  │  核心数据: Dictionary<int, FashionPart> fashionParts
  │  控制: Mesh Combining + Texture Atlas
  │
  │  ┌─ RoleSkinManager.cs                   ← 角色层总管理器入口
  │  ├─ RoleSkinManager_MalouParty.cs        ← 狼人模式特化
  │  └─ SkinManager.cs (Motion层)            ← Motion 层皮肤管理
  │
第二层：SkinChanger + SkinFashionPart (部件状态机)
  │  职责: 每部件独立状态转换 (StateA-E)
  │  驱动: SkinChangeAnimation 组件负责过渡动画
  │  状态参数: IdleState / TransitionState（骨骼 Animator 驱动）
  │
  │  ┌─ SkinChanger.cs                       ← 换装驱动器
  │  ├─ SkinFashionPart.cs                   ← 部件实例
  │  └─ SkinChangeAnimation.cs               ← AnimationClip 映射 + 过渡配置
  │
第三层：SkinSlot + Containers (模块化插槽系统)
     职责: 资源加载/挂载/容器管理
  
     ┌─ SkinSlot.cs                          ← 插槽基类
     ├─ SkinSlot_Fashion.cs                  ← 时装加载插槽
     ├─ SkinSlot_Effect.cs                   ← 特效加载插槽
     ├─ SkinFashionContainer.cs              ← 时装容器
     └─ SkinEffectContainer.cs               ← 特效容器
```

### 1.2 18 部件系统 (FashionPartType)


每个部件通过 `FashionPartType` 枚举索引，`SkinManager.fashionParts` 字典以此为 key 管理所有部件实例。

### 1.4 数据流向

```
配置加载流:
  FashionInfo.txt → FashionPartType 解析 → SkinManager.fashionParts 初始化
  FashionAsset.txt → 资源路径映射 → SkinSlot_Fashion 异步加载
  FashionEffect.txt → 特效配置 → SkinSlot_Effect 特效实例化
  FashionSet.txt → 套装组合定义 → 批量换装

换装执行流:
  用户选择时装 → RoleSkinManager.ChangeSkin()
    → SkinChanger 驱动状态切换
      → SkinSlot_Fashion 加载新资源
        → OnFashionLoaded 回调
          → 注册 DissolvePosReceiver（溶解效果）
          → 初始化 ISkinComponent
          → 触发 Mesh Combining（移动端）
          → 触发 Texture Atlasing

战斗同步流:
  Client: ClientChangeSkinFeatureManager.ChangeSkin()
    → Proto_ChangeSkin.CmdWarChangeSkin（发送到服务端）
      → Server: ServerChangeSkinFeatureManager（验证请求）
        → Host: RoleSkinChangeSkin（TargetRpc/Rpc 广播）
          → 各客户端执行本地换装
```

## 三、配置详解

### 3.1 FashionInfoConfig (FashionInfo.txt)

时装基础信息配置，定义时装 ID、名称和所属部件类型。


| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | long | 时装唯一标识 | `100001` |
| `name` | string | 时装显示名称 | `"经典发型"` |
| `type` | int | 对应 FashionPartType 枚举 | `0`=Hair, `5`=Shirt, `11`=Suit |

### 3.2 FashionAssetConfig (FashionAsset.txt)

时装资源路径映射，控制资源加载和品质等级。

```csharp
// 配置路径: Assets/ToBundle/Config/Txt/FashionAsset.txt
public readonly long id;        // 关联 FashionInfo 的时装 ID
public readonly string path;    // 资源 Bundle 路径
public readonly string name;    // 资源名称
```

| 字段 | 类型 | 说明 |
|------|------|------|

### 3.3 FashionEffectConfig (FashionEffect.txt)

时装特效配置，控制特效挂载、裁剪策略和动态骨骼。**所有数组字段长度必须一致。**

```csharp
// 配置路径: Assets/ToBundle/Config/Txt/FashionEffect.txt

public readonly int[] isCombinerMesh;          // 是否合并网格（1=合并,0=独立）
public readonly int[] autoQueue;               // 自动渲染队列
public readonly string[] dynamicBoneRootName;  // 动态骨骼根节点名
public readonly int[] IsCullLowEffect;         // 低配裁剪（1=低配跳过）
public readonly int[] IsCullMidEffect;         // 中配裁剪（1=中配跳过）
public readonly int[] isModifyParam;           // 材质参数修改标记
public readonly int[] isLoopAnim;              // 循环动画标记（1=循环）
```

**字段详解：**

| 字段 | 说明 | 注意事项 |
|------|------|---------|
| `effectName` | 特效 Prefab 名称数组 | 按顺序对应挂点 |
| `effectParentSign` | 骨骼挂点标记 | 必须与模型骨骼节点匹配 |

## 四、关键代码修改点

### 4.1 材质/贴图合并

#### Mesh Combining (SkinnedMeshCombiner)

```csharp
// 文件: Assets/Script/GamePlay/Client/Motion/SkinnedMeshCombiner.cs
// 移动端启用 Mesh Combining，PC 端禁用
GlobalDefine.IsPCPlatform ? false : isMeshCombine
```

**规则：**
- 移动端（Android/iOS）：将所有部件合并为**单个 SkinnedMeshRenderer**，减少 DrawCall
- PC 端：保持多个 Renderer，利用 GPU 性能
- **Classic AI 模式例外**：不执行合并（AI 角色无需高精度表现）

#### Texture Atlasing (ActorTextureCombiner)

```csharp
// 文件: Assets/Script/GamePlay/Client/Motion/ActorTextureCombiner/
// 多纹理合并为 Atlas
// 使用 Shader: Chicken_MatCap_RoleSplit
```

**分辨率策略：**

| 场景 | 前缀标识 | 分辨率 | 说明 |
|------|---------|--------|------|
| 自己 | `Me_` | 高分辨率 | 本地玩家需要高精度表现 |
| 他人 | `Other_` | 低分辨率 | 远处玩家降低开销 |

分辨率按**设备等级 + 平台(Android/iOS)**进一步分档：

| 平台 | 低画质 | 中画质 | 高画质 | 备注 |
|------|-------|-------|-------|------|
| iOS | 512 | 768 | 1024 | PVRTC 格式 |
| Android | 512 | 1024 | 1536 | ETC2 格式；屏幕分辨率 ≥ 2048 时自动升档 |

#### 合并触发时序（关键）

贴图/网格合并**不是**在资源加载时触发，而是在**所有时装部件加载完毕后同步执行**。完整调用链如下：

```
SetSkinInfo(FashionData)
  │
  ├─ 异步路径 → ShowFashionsAsync()
  │               ↓
  │           UpdateSkinChange() 每帧轮询
  │               ↓
  │           全部资源 isDone ──→──┐
  │                               │
  └─ 同步路径 → ShowFashionsSync() ←─┘
                    ↓
              FashionBufferCallBack()
                    ↓
              遍历 AddFashionPart()（全部 18 部位）
                    ↓
              【条件判断】UseMeshCombine && WarData.IsIntoWar
                    ↓ (满足)
              ┌─ ActorTextureCombiner(targetWH, targetWH)  // 创建合并器
              ├─ AddActorToCombined(renderers)              // 收集所有 Renderer
              ├─ DispatchAll()                              // 分发 Job（Burst 编译）
              ├─ CompleteAll()                              // ⚠️ 同步等待 — 阻塞主线程
              ├─ ReplaceSourceRenderers()                   // 替换原始网格+纹理
              ├─ GeCombinedMaterial() → useMat              // 获取合并后材质
              ├─ meshCombiner.CombineMesh(useMat)           // SkinnedMeshCombiner 合并网格
              ├─ DestroyInstance()                          // 清理临时 RenderTexture
              └─ ClearPartList()                            // 清空部位列表
```

**四个触发场景：**

| 触发场景 | 入口方法 | 说明 |
|---------|---------|------|
| **进入战场** | `SetSkinInfo()` → `FashionBufferCallBack()` | 首次换装，主路径 |
| **战中换装** | 重新调用 `SetSkinInfo()` | 如战场换肤指令触发 |
| **NPC 加载** | `SetNpcSkin()` | NPC 皮肤独立路径 |
| **异步完成回调** | `UpdateSkinChange()` → `ShowFashionsSync()` | 资源异步加载完后汇入同步路径 |

**平台判断（InitWar 时设置）：**

```csharp

```

- ✅ 移动端（Android / iOS）：`UseMeshCombine = true`
- ❌ PC 端：`UseMeshCombine = false`，保持多 Renderer

### 4.2 Shader Keyword 优化

```csharp
// 文件: Assets/Script/GamePlay/Client/Modules/SkinChange/Runtime/SkinComponents/PeformanceOpitimize/KeywordOptimizer.cs

// 换装过渡时开启 _USE_DISSOLVE Keyword
// 2 秒后自动关闭，节省 GPU 开销
private void CloseDissolve(bool closeDissolve) {
    if (closeDissolve) {
        tempMat.DisableKeyword("_USE_DISSOLVE");
    } else {
        tempMat.EnableKeyword("_USE_DISSOLVE");
    }
}
```

**生命周期：**
1. `ChangeState` 时：启用 `_USE_DISSOLVE` Keyword → 开始溶解效果
2. `SetIdleShow` 时：禁用 `_USE_DISSOLVE` → 结束溶解
3. `LateUpdate` 计时器：兜底机制，防止 Keyword 泄漏

### 4.3 溶解效果系统

```csharp
// 文件: Assets/Script/GamePlay/Client/Modules/SkinChange/Runtime/SkinComponents/PeformanceOpitimize/DissolvePosDispatcher.cs
// 文件: Assets/Script/GamePlay/Client/Modules/SkinChange/Runtime/SkinComponents/PeformanceOpitimize/DissolvePosReceiver.cs
```

**主从模式：**
- **DissolvePosDispatcher（主控）**：单个 Dispatcher 实例协调多个 Receiver
- **DissolvePosReceiver（从控）**：每个需要溶解效果的部件挂载 Receiver
- Dispatcher 在 `LateUpdate` 中统一更新溶解位置数据
- 所有 Receiver 共享溶解位置，**减少冗余计算**

## 五、常见问题与踩坑记录

### 5.1 Mesh Combining 相关

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 移动端合并后出现 UV 错乱 | Atlas 合并时 UV 偏移计算错误 | 检查 ActorTextureCombiner 的 UV 重映射逻辑 |
| PC 端不显示合并效果 | 设计如此：`GlobalDefine.IsPCPlatform ? false : isMeshCombine` | PC 端保持多 Renderer，不执行合并 |
| Classic AI 角色合并异常 | AI 模式例外：不执行 Mesh Combining | 确认 AI 模式判断逻辑正确 |
| 合并后骨骼动画异常 | SkinnedMeshRenderer 的 bones 数组未正确重映射 | 检查 SkinnedMeshCombiner 的骨骼绑定逻辑 |

### 5.2 溶解效果相关

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 溶解效果不消失 | `_USE_DISSOLVE` Keyword 未关闭 | 检查 KeywordOptimizer 的 LateUpdate 计时器是否正常工作 |
| 溶解方向异常 | DissolvePosDispatcher 位置数据异常 | 确认 Dispatcher 和 Receiver 正确关联 |
| 换装闪烁 | 新旧资源切换间隙 | 确保溶解过渡动画衔接，先开始溶解再切换资源 |

### 5.3 特效相关

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 低配设备卡顿 | 复杂特效未配置裁剪 | FashionEffect.txt 中设置 `IsCullLowEffect=1` |
| 头盔下出现头部特效穿模 | 未触发特效隐藏 | 检查 `ShowOrHideHeadEffectWhenHelmet` 逻辑 |
| 特效挂错位置 | effectParentSign 与骨骼节点名不匹配 | 核对模型骨骼节点命名 |
| 动态骨骼穿模 | dynamicBoneRootName 配置错误 | 检查配置文件中根节点名与模型一致 |

### 5.4 网络同步相关

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 新玩家看不到已换装角色 | TargetRpc 未包含完整 SkinChangeData | 确认 RoleSkinChangeSkin 的初始化同步逻辑 |
| 换装请求被拒绝 | 服务端权威验证失败 | 检查 ServerChangeSkinFeatureManager 的验证逻辑 |
| 多端换装不一致 | Rpc 广播遗漏 | 确认 RpcChangeFashionSkinState 正确广播 |

### 5.5 配置相关

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 特效数组越界 | FashionEffect.txt 数组长度不一致 | 所有数组字段（effectName/effectParentSign/isCombinerMesh 等）长度必须相同 |
| 新时装不显示 | FashionAsset.txt 未配置 path | 确认资源路径正确且已打包 |
| 套装穿戴不完整 | FashionSet.txt 的 items 数组缺少部件 ID | 逐一验证 items 中每个时装 ID 有效 |
