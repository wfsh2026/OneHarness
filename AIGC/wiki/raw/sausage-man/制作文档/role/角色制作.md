# 1 代架构角色制作规范

> **适用范围**：基于 `BattleRole / BattleRoleLogic / RoleLogicServer / RoleLogicClient` 的角色系统开发与扩展（新增 Component、扩展 partial、新增 Feature 等）
> **不适用**：2 代架构角色系统（Biubiubiu2/）— 此文档不涵盖
> **参考实现**：BattleRoleCombatComponent（Component 范例）、RoleLogicServer_DownHp（Server partial 范例）、ClientRolePowerSkillManager（Feature 范例）

**占位符说明**：

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{ComponentName}` | 组件功能名（大驼峰） | `Sliding`、`Dance`、`EnergyBattle` |
| `{FeatureName}` | Feature 功能名（大驼峰） | `PowerSkill`、`Treasure`、`Pet` |
| `{DomainName}` | partial 领域名 | `DownHp`、`Dead`、`Resurrection` |
| `{ModeName}` | 模式英文名 | `HideSeek`、`BladeBall`、`Knockout` |

## 一、系统概述

### 1.1 双层 Entity-Logic 架构

角色系统采用 **Entity/Presentation + Logic/Data** 双层结构，通过 C/S/H 三端分离实现网络对战：

```
BattleRole (Host, MonoBehaviour) ← Entity/Presentation 层
│   ├── 24 partial 文件（Role_Init / Role_Fields / Role_Move / ...）
│   ├── 44 BattleRoleComponent（组件化功能模块）
│   └── 外部系统（RoleControl / RoleSkill / RoleEffect / RoleHitCheck / ...）
│
└── BattleRoleLogic (Host, MonoBehaviour) ← Logic/Data 层
    ├── 40+ partial 文件（RoleLogic_Init / RoleLogic_Fields / RoleLogic_States / ...）
    ├── 25 BattleRoleLogicComponent（逻辑组件模块）
    ├── RoleLogicServer (Server, 37 partial) ← 服务端权威逻辑
    │   └── RoleCheat (子循环) ← 反作弊
    ├── RoleLogicClient (Client, 20 partial) ← 客户端表现逻辑
    └── RoleNet (Host, C/S/H) ← 网络同步框架
```

**核心关系**：
- `BattleRole` 持有 `BattleRoleLogic` 引用（`MyRoleLogic`）
- `BattleRoleLogic` 在 `Awake()` 中通过 `RequestLoop<RoleLogicServer>()` 和 `RequestLoop<RoleLogicClient>()` 创建 C/S 子系统
- 三层之间通过 `Events`（Dispatcher 模式）和直接引用通信

## 二、核心机制详解

### 2.1 组件体系（Component System）

#### BattleRoleComponent（Entity 层，44 个）

```csharp
// 基类定义 — BattleRoleComponent.cs
public abstract class BattleRoleComponent : BattleComponent {
    protected BattleRole role { get; private set; }
    protected BattleRoleLogic roleLogic => role?.MyRoleLogic;
    protected StartGame startGame => role?.MyStartGame;
    protected BattleWorld gameWorld => startGame?.MyGameWorld;
    protected RoleNet roleNet => roleLogic?.MyRoleNet;

    public override void Awake(IBattleSystem system) {
        this.role = system as BattleRole;
        base.Awake(system);
    }
}
```

**可用钩子方法**（继承自 `BattleComponent`）：

| 钩子 | 调用时机 | 用途 |
|------|---------|------|
| `OnInit()` | `Awake()` 后立即调用 | 初始化、注册事件 |
| `OnClear()` | `ClearAllComponents()` 时调用 | 清理引用、注销事件 |
| `OnUpdate()` | 每帧 `TimeEvent()` 驱动 | 帧逻辑（谨慎使用） |
| `OnEvent(T)` | `Dispatcher(event)` 时调用 | 响应 BattleRoleEvents |

**事件驱动**：组件之间通过 `BattleRoleEvents` 解耦通信：

```csharp
// 在组件中注册事件监听（OnInit 中）
role.RegisterEvent<BattleRoleEvents.UpdateSkin>(OnUpdateSkin);

// 在 BattleRole 中触发事件
Dispatcher(new BattleRoleEvents.UpdateSkin { data = skinInfo });
```

#### BattleRoleLogicComponent（Logic 层，25 个）

```csharp
// 基类定义 — BattleRoleLogicComponent.cs
public abstract class BattleRoleLogicComponent : BattleComponent {
    protected BattleRoleLogic roleLogic { get; private set; }
    protected BattleWorld gameWorld => roleLogic?.gameWorld;
    protected StartGame startGame => roleLogic?.MyStartGame;

    public override void Awake(IBattleSystem system) {
        roleLogic = system as BattleRoleLogic;
        base.Awake(system);
    }
}
```

**与 BattleRoleComponent 的区别**：

| 维度 | BattleRoleComponent | BattleRoleLogicComponent |
|------|---------------------|--------------------------|
| 所属层 | Entity/Presentation (BattleRole) | Logic/Data (BattleRoleLogic) |
| 可访问 | role, roleLogic, roleNet, gameWorld | roleLogic, gameWorld |
| 注册位置 | `BattleRole.AddComponents()` | `BattleRoleLogic.AddComponents()` |
| 典型职责 | 动画、皮肤、UI显示、碰撞 | HP、技能、武器、状态同步 |
| 数量 | 44 个 | 25 个 |

### 2.3 伤害计算链（Server Authoritative）★★★

伤害流程是角色系统最核心的服务端逻辑，完整链路如下：

```
═══════════════════════════════════════════════════════════════
  Client 射击命中 → Server 验证 → 扣血 → 广播结果
═══════════════════════════════════════════════════════════════

① Client 发送扣血请求
   RoleNetClient → CmdDownHp(fireRoleId, downHpRoleId, downValue, hitPart, ...)

② Server 网络入口接收（RoleNetServer_DownHp.cs）
   RoleNetServer.CmdDownHp()
     ├─ IsClientConnect 检查
     ├─ GameState == Start 检查
     ├─ 构建 CmdDownHpData 结构体
     └─ #if SERVER_LOGIC
          ├─ CheckNetState()        ← 网络状态校验
          ├─ CheckPickItemID()      ← 物品 ID 校验
          ├─ CheckWolfPartyDamage() ← 狼人模式特殊规则
          ├─ CheckDownHpValue()     ← 伤害值合法性（RoleCheat 反作弊）
          └─ CheckTeammate()        ← 队友伤害规则

③ 转入逻辑层（RoleLogicServer_DownHp.cs）
   RoleLogicServer.ServerDownHp(fireRoleId, attackType, value, ...)
     ├─ 前置检查：死亡/飞行/装甲校车/武林客栈 → return
     ├─ GetBuffPower()              ← 获取 Buff 增减益
     ├─ 护甲计算 → 最终伤害值
     ├─ HP -= finalDamage
     ├─ 攻击统计 → secondaryAtkRoles
     └─ if (HP <= 0) → 触发死亡流程

④ 死亡流程（RoleLogicServer_Dead.cs）
   ├─ 设置 IsDead 状态
   ├─ 统计击杀信息
   ├─ 通知模式系统（OnRoleKill 事件）
   └─ 广播客户端

⑤ 复活流程（RoleLogicServer_Resurrection.cs）
   ├─ 选择出生点
   ├─ 倒计时
   └─ 重置状态 → 复活
```

### 2.4 网络同步机制

角色系统使用**两种网络消息机制**：

#### Proto（Protobuf 结构化消息）

```csharp
// 发送（Server → Client）
gameWorld.Send(new Proto_Role.RpcDownHp {
    roleId = roleLogic.AutoRoleId,
    downValue = finalDamage,
    fireRoleId = fireRoleId
});

// 接收（Client 注册监听）
gameWorld.RegisterMessage<Proto_Role.RpcDownHp>(
    ClientMessageConstants.OnDownHp, OnReceiveDownHp
);
```

#### RPC（Mirror 网络方法调用）

```csharp
// RoleNetServer → 客户端 RPC
[ClientRpc]
public void RpcSyncState(int stateKey, bool value) { ... }

// RoleNetClient → 服务端 Cmd
[Command]
public void CmdDownHp(short fireRoleId, ...) { ... }
```

#### AT Events（内部事件总线）

```csharp
// 通过 gameWorld.DispatchMessage 分发
gameWorld.DispatchMessage(ClientMessageConstants.OnRoleDead, roleLogic);

// 注册监听
gameWorld.RegisterMessage<BattleRoleLogic>(
    ClientMessageConstants.OnRoleDead, OnRoleDead
);
```

### 2.5 Feature 机制

Feature 是挂载到 `BattleRoleLogic` 上的功能模块，与 Component 不同的是 Feature 通过 `AddFeature<T>()` / `GetFeature<T>()` 管理，具有独立的生命周期：

```csharp
// Server 端注册（RoleLogicServer.Init() 中）
roleLogic.AddFeature<RoleLogicResurrectionServer>();
roleLogic.AddFeature<RoleLogicPowerFeatureManager>();

// Client 端注册（RoleLogicClient.Init() 中）
roleLogic.AddFeature<ClientRolePowerSkillManager>();
roleLogic.AddFeature<SausageClientRolePet>();

// 获取 Feature 引用
Pet = roleLogic.GetFeature<SausageClientRolePet>();
```

## 六、常见问题与踩坑记录

### 6.1 BattleRoleComponent 的 OnInit 中 gameWorld 为 null

**问题现象**：在 `BattleRoleComponent.OnInit()` 中访问 `gameWorld` 返回 null

**根因分析**：`BattleRoleComponent` 的 `gameWorld` 依赖链为 `role → startGame → gameWorld`。`AddComponents()` 在 `BattleRole.Init()` 的早期调用，此时 `mStartGame` 刚赋值但某些引用可能未完全初始化。

**解决方案**：
1. 在 `OnInit()` 中使用 `role.MyRoleLogic.gameWorld` 替代 `gameWorld` 短路径
2. 如需延迟初始化，注册 `BattleLoadComplete` 消息，在回调中执行
3. 检查 `role?.MyStartGame?.MyGameWorld` 的空安全链

### 6.2 AddComponents 注册顺序导致依赖失败

**问题现象**：组件 A 在 `OnInit()` 中尝试获取组件 B 的引用，但返回 null

**根因分析**：`AddComponent<T>()` 会立即调用 `T.OnInit()`。如果组件 A 在组件 B 之前注册，A 的 `OnInit()` 执行时 B 还未被添加。

**解决方案**：
1. **调整注册顺序**：确保被依赖的组件先注册（在 `AddComponents()` 中排在前面）
2. **延迟获取**：不在 `OnInit()` 中获取其他组件引用，改为使用时动态获取
3. **事件驱动**：通过 `BattleRoleEvents` 解耦，避免直接组件引用

```csharp
// ❌ 错误：OnInit 中直接获取可能未注册的组件
protected override void OnInit() {
    var combat = role.GetBattleComponent<BattleRoleCombatComponent>(); // 可能为 null
}

// ✅ 正确：使用时获取或事件驱动
private BattleRoleCombatComponent combat;
private void EnsureCombat() {
    combat ??= role.GetBattleComponent<BattleRoleCombatComponent>();
}
```

### 6.3 Server partial 中忘记 #if SERVER_LOGIC 保护

**问题现象**：客户端构建时出现服务端专属 API 编译错误

**根因分析**：`RoleLogicServer` 的 partial 文件在客户端也会参与编译。服务端专属逻辑必须用 `#if SERVER_LOGIC` 包裹。

**解决方案**：

```csharp
public partial class RoleLogicServer {
    public void ServerOnlyMethod() {
#if SERVER_LOGIC
        // 服务端专属逻辑
        MyRoleCheat.OnSetDownHp(fireRoleLogic, value, attackType);
#endif
    }
}
```

> ⚠️ 字段声明如果使用了服务端专属类型，也需要 `#if SERVER_LOGIC` 包裹。

### 6.4 Feature 注册位置错误导致 GetFeature 返回 null

**问题现象**：在某些角色上 `roleLogic.GetFeature<T>()` 返回 null

**根因分析**：Feature 在 `RoleLogicServer.Init()` 或 `RoleLogicClient.Init()` 中通过条件分支注册。如果某些模式不满足条件，Feature 就不会被注册。

**解决方案**：
1. 调用 `GetFeature<T>()` 前始终做 null 检查
2. 如果 Feature 是通用功能，放在无条件注册区域
3. 互斥分支（如 `IsPveRogueMode ? A : B`）要确保所有路径都有覆盖

```csharp
// ✅ 正确：始终检查
var pet = roleLogic.GetFeature<SausageClientRolePet>();
if (pet != null) {
    pet.DoSomething();
}
```

### 6.5 模式专属组件在非该模式下执行了逻辑

**问题现象**：非该模式的对局中出现预期外的组件行为或性能开销

**根因分析**：组件在 `AddComponents()` 中无条件注册，但组件内部没有做模式判断。

**解决方案**（二选一）：

```csharp
// 方案一：条件装配（推荐，零开销）
// 在 BattleRole.AddComponents() 中：
if (WarData.Is{ModeName}Mode) {
    AddComponent<BattleRole{ModeName}Component>();
}

// 方案二：组件内部守卫（适合轻量级组件）
protected override void OnInit() {
    if (!WarData.Is{ModeName}Mode) return;
    // 仅在该模式下执行初始化
}
```

> ⚠️ 已有的 44 个组件中，大部分是无条件注册的。仅 `BattleRoleEnergyBattleComponent` 等少数组件使用了条件装配。新增模式专属组件推荐使用条件装配。

### 6.6 扣血链路中的检查被短路

**问题现象**：某些攻击类型的伤害无法生效

**根因分析**：`RoleLogicServer.ServerDownHp()` 中有大量前置检查，常见的短路原因：
- 角色在装甲校车上（`noBulletHurt = true`）但攻击类型不在白名单
- 角色进入武林客栈（`IsEnterWuLinHotel`）
- 角色处于飞行状态（`IsStartFly`）
- 角色已死亡（`IsDead`）

**解决方案**：
1. 排查顺序：`CmdDownHp` → `CheckNetState` → `CheckDownHpValue` → `ServerDownHp` 前置检查
2. 新增攻击类型时需在 `ServerDownHp` 的各个检查分支中添加白名单
3. 使用 `SERVER_LOGIC` 宏的日志输出跟踪伤害链路

### 6.7 Clear 时遗漏事件注销导致回调异常

**问题现象**：角色被清除后仍收到事件回调，触发 NullReferenceException

**根因分析**：在 `OnInit()` 中注册了 `gameWorld.RegisterMessage` 但在 `OnClear()` 中没有对应的 `UnregisterMessage`。

**解决方案**：

```csharp
protected override void OnInit() {
    gameWorld.RegisterMessage<int>(msgId, OnHandler);
}

protected override void OnClear() {
    // ★ 必须配对注销
    if (gameWorld != null) {
        gameWorld.UnregisterMessage<int>(msgId, OnHandler);
    }
    base.OnClear();
}
```
