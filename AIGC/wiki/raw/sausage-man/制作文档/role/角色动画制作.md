# 1 代架构角色动画制作规范

> **适用范围**：基于 `AnimatorControl / SausagePlayable / AnimatorData / AnimatorEnum` 的角色动画系统开发与扩展（新增动画状态、扩展 Check 条件、接入 Playable/AnimGraph 等）
> **不适用**：2 代架构动画系统（Biubiubiu2/）— 此文档不涵盖
> **参考实现**：AnimatorControlBaseCheck（BaseCheck 范例）、AnimatorControlAimCheck（AimCheck 范例）、SausagePlayable（Playable 系统范例）
> **公共框架依赖**：AnimatorControl → RoleControl → BattleRole；SausagePlayable → PlayableController → AnimLayerData

---

## 一、架构概述

### 1.1 三套动画后端

角色动画系统提供三套可切换的动画后端，通过 `SausagePlayable._animType` 全局静态字段控制：

```csharp
// Assets/Script/Data/PlayableAnimData/SausagePlayable.cs lines 10-14
public enum AnimTypeEnum {
    Animator = 0,    // 标准 Unity Animator FSM（Legacy 默认）
    Playable = 1,    // 自研 PlayableGraph 系统（主力方案）
    AnimGraph = 2,   // 高性能原生方案（仅 PartyMode）
}
```

**切换规则**：
- **Playable（主力）**：默认方案，初始化时 `animator.runtimeAnimatorController = null` 禁用 FSM
- **Animator（回退）**：跳舞动画 `_isDance` 时自动回退到标准 Animator
- **AnimGraph（限定）**：仅 `WarData.Game_Mode == PartyMode` 时启用，大人数场景性能优化

### 1.2 核心类依赖

```
AnimatorControl (核心控制器, ~3600行)
│   ├── AnimatorControlBaseCheck     — Base 层：全身动画选择
│   ├── AnimatorControlAimCheck      — Aim 层：上半身/武器动画 (500+行)
│   ├── AnimatorControlRunAddCheck   — RunAdd 层：移动叠加
│   └── AnimatorControlDecorator     — Decorator 基类

├── SausagePlayable                   — Playable 系统入口
│   ├── PlayableController            — 图管理
│   ├── Playable_Anim_HTR             — 动画节点
```

### 3.4 优先级配置规则

- `SOAnimatorBasePriorityConfig`：控制 BaseCheck 中所有 `CheckBase{Name}` 方法的遍历顺序
- `SOAnimatorAimPriorityConfig`：控制 AimCheck 中所有 `CheckAim{Name}` 方法的遍历顺序
- **每帧按优先级从高到低遍历**，命中即停（短路求值）
- 修改优先级时需注意：高优先级动画可能遮蔽低优先级动画

### 4.1 Decorator 模式检查链

动画系统使用装饰器模式组织三层 Check 逻辑：

```
AnimatorControl (核心, ~3600行)
  ├── AnimatorControlBaseCheck — 全身动画选择
  ├── AnimatorControlAimCheck  — 上半身/武器动画 (500+行)
  └── AnimatorControlRunAddCheck — 移动叠加
```

文件路径：
- `Assets/Script/GamePlay/Client/Motion/AnimatorControl.cs`
- `Assets/Script/GamePlay/Client/Motion/AnimatorControlBaseCheck.cs`
- `Assets/Script/GamePlay/Client/Motion/AnimatorControlAimCheck.cs`
- `Assets/Script/GamePlay/Client/Motion/AnimatorControlRunAddCheck.cs`
- `Assets/Script/GamePlay/Client/Motion/AnimatorControlDecorator.cs`

#### 4.1.1 反射初始化机制

Check 类使用反射自动发现条件方法和播放方法的配对关系：

```csharp
// AnimatorControlDecorator.cs — 反射注册
animatorControl.CheckMethodToDic("CheckBase", this, GetType(), dicCheckAnim, list);
// 自动发现 CheckBase{Name}Condition() + CheckBase{Name}() 方法对
```

**命名约定（★ 强制）**：
- 条件方法：`Check{Layer}{Name}Condition()` → 返回 `bool`
- 播放方法：`Check{Layer}{Name}()` → 执行动画播放
- 两个方法必须成对出现，且 `{Layer}{Name}` 部分完全一致

#### 4.1.2 BaseCheck 条件示例

```csharp
// AnimatorControlBaseCheck.cs

// 站→趴过渡条件
bool CheckBaseStandToProneCondition() {
    return stance == 1 && nextStance == 3;
}

// 跳跃条件
bool CheckBaseJumpCondition() {
    return jumpState != 0;
}

// 游泳条件
bool CheckBaseSwimCondition() {
    return animatorControl.getIsSwim();
}
```

#### 4.1.3 AimCheck 条件示例

```csharp
// AnimatorControlAimCheck.cs

// 换弹条件（排除 OpenClose 类型）
bool CheckAimReloadCondition() {
    return GetIsReload() && weaponEquip.reloadAction != OpenClose;
}

// 左侧瞄准条件
bool CheckAimLeftAimCondition() {
    return GetIsAim() && nowSideValue == -1;
}

// 持握投掷物条件
bool CheckAimHoldGrenadeCondition() {
    return !GetProneMove() && GetHoldOn();
}

// 近战轻攻击条件
bool CheckAimAttacklightCondition() {
    return GetInteger(ID_meleeState) == 1;
}
```

#### 4.1.4 RunAddCheck 条件示例

```csharp
// AnimatorControlRunAddCheck.cs

// 左侧移动条件
bool CheckRunAddLeftSideCondition() {
    return GetIsAim() && GetMoveState() && GetSideShoot() == -1;

// 基础移动条件（复合判断）
bool CheckRunAddMoveCondition() {
    // 不在趴姿+开火、正确姿态、未跳跃、有武器
```

## 五、常见问题与踩坑记录

### 5.1 动画状态不生效

**症状**：新增的动画条件方法不被调用

**原因**：反射初始化依赖方法命名约定。如果 `Condition` 方法和 `Play` 方法名不匹配，`CheckMethodToDic` 无法配对。

**解决**：严格遵循 `Check{Layer}{Name}Condition()` + `Check{Layer}{Name}()` 命名约定。

### 5.2 优先级冲突导致动画被遮蔽

**症状**：某个动画永远不触发

**原因**：更高优先级的条件方法总是先命中（短路求值），导致低优先级动画被遮蔽。

**解决**：
1. 检查 `SOAnimatorBasePriorityConfig` / `SOAnimatorAimPriorityConfig` 中的排序
2. 确认高优先级条件方法的退出条件是否正确

### 5.3 Playable 模式下 Animator Controller 失效

**症状**：Playable 模式启动后，Animator Controller 中的状态机不工作

**原因**：`AnimType == AnimTypeEnum.Playable` 时，初始化会执行 `animator.runtimeAnimatorController = null`，主动禁用 FSM。

**解决**：这是预期行为。Playable 模式下所有动画由 SausagePlayable 驱动，不依赖 Animator FSM。

### 5.4 跳舞动画回退

**症状**：Playable 模式下跳舞动画切回了 Animator

**原因**：`_isDance` 为 true 时系统自动回退到标准 Animator，因为舞蹈动画使用独立 Controller。

**解决**：这是设计决策。跳舞动画的复杂混合逻辑更适合 Animator Controller 驱动。

### 5.5 AnimGraph 模式下缺少动画

**症状**：PartyMode 中某些动画不播放

**原因**：AnimGraph 使用 Slot 映射，新增动画必须在 `SausagePlayable_AnimGraph.Slot` 中注册 AUID。

**解决**：在 Slot 类中添加对应的 `public static AUID` 字段。

### 5.6 IK 手臂抖动

**症状**：瞄准时左手 IK 目标点抖动

**原因**：`WeaponIKTrans` 的位置/旋转在某些动画过渡帧中不稳定。

**解决**：检查武器 IK 骨骼的动画曲线，确保过渡期间 IK Target 平滑。

### 5.7 NPC 动画突然消失

**症状**：NPC 在一定距离后动画停止

**原因**：`NpcAnimatorControl` 的 50m 距离裁剪机制（1 秒检测频率）。

**解决**：这是性能优化的预期行为。如需调整裁剪距离，修改 `NpcAnimatorControl` 中的距离阈值。

### 5.8 三套后端不一致

**症状**：同一动画在 Animator/Playable/AnimGraph 下表现不同

**原因**：三套后端需要独立维护，新增动画时可能遗漏某套后端的适配。

**解决**：严格按照 §2.1 Checklist 执行，确保三套后端都完成适配。
