> **适用范围**：基于 `AbsModeManager` 四层架构的玩法模式开发（DefusalMode / GoldDash / EscapeMode 等），包含所有 21 个子玩法模式
> **不适用**：2 代架构模式 — 此文档不涵盖
> **参考实现**：爆破模式（DefusalMode），路径 → `Client/Modules/Mode/DefusalMode/`
> **各模式专属文档**：每个子玩法均有独立制作文档（见 §1.8 模式清单），包含该模式特有的架构、Checklist、配置和踩坑记录

## 一、架构概述

### 1.1 四层架构体系

```
AbsModeManager（模式总管理器）— 继承自 AbsExtendGameWorldFeature
    ├── ModeStageCollection       ← 阶段集合（有序）
    │   └── IModeStage 实例       ← OnInit/OnEnter/OnQuit/OnUpdate
    ├── ModeLogicCollection       ← 逻辑组件集合
    │   └── IModeLogic 实例       ← OnInit/OnClear（无 Update）
    └── ModeDataCollection        ← 数据容器集合
        └── IModeData 实例        ← OnInit/OnClear
```

关键特点：

- **Stage** 是唯一有 OnUpdate 驱动的组件（当前运行的 Stage 每帧 Update）
- **Logic** 没有 Update，仅在 OnInit 时注册消息监听，被动响应
- **Data** 是纯数据容器
- Manager 通过 `ChangeStage<T>()` 切换阶段，流程：旧Stage.OnQuit() → 获取新Stage → 新Stage.OnEnter() → OnChangeStage回调

### 1.2 三端对应关系（C/S/H）

| 层级 | Host（接口定义） | Client | Server |
|------|-----------------|--------|--------|
| Manager | AbsModeManager | ClientModeManager | ServerModeManager |
| Stage | AbsModeStage | ClientModeStage | ServerModeStage + ServerModeBornStage + ServerModeOverStage |
| Logic | AbsModeLogic | ClientModeLogic | ServerModeLogic + ServerModeAwardLogic + ServerModeStatisticsLogic + ServerModeRoleLogic + ServerModeNsqDataLogic |
| Data | AbsModeData | ClientModeData | ServerModeData |

Server 端额外提供的基类：

- `ServerModeBornStage` — 出生阶段模板（计时、人数检测、无敌Buff）
- `ServerModeOverStage` — 结束阶段模板（GameOver、奖励计算、MVP、数据上报）
- `ServerModeAwardLogic` — 奖励逻辑基类
- `ServerModeNsqDataLogic` — 数据上报逻辑基类
- `ServerModeStatisticsLogic` — 统计逻辑基类（可能存在，按实际代码）
- `ServerModeRoleLogic` — 角色事件逻辑基类（死亡、击杀等）

### 1.5 Factory 创建机制

```csharp
// ClientModeFactory.cs
public static void InitMode(BattleWorld gameWorld) {
    switch (WarData.Game_Mode) {
        case WarData.GameMode.{GameModeEnum}:
            gameWorld.AddExtendFeature<Client{ModeName}Mgr>();
            break;
    }
}

// ServerModeFactory.cs — 同理
```

### 1.6 Client-Server 阶段同步机制

**核心原理**：Server 驱动阶段切换，Client 被动跟随

```
Server: ChangeStage<ServerXxxStage>()
    → OnChangeStage() 
    → ClientRpc(RpcModeStageChange { stage="ServerXxxStage" })
    
Client: OnModeStageChange() 收到消息
    → stage.Replace("Server","Client")  // "ServerXxxStage" → "ClientXxxStage"
    → ChangeStage("ClientXxxStage")     // 按名字查找并切换
```

**关键约束**：Client 和 Server 的 Stage 类名必须对称！（Server 前缀替换为 Client 前缀）

### 1.7 禁止修改的文件

- **`AbsModeManager.cs` / `AbsModeStage.cs` / `AbsModeLogic.cs` / `AbsModeData.cs`** — Host 基类，所有模式共用

**Manager 内部标准组装顺序**：

```csharp
protected override void OnInit() {
    base.OnInit();
    config = LoadConfig<T>(configSign);     // ① 加载 SO 配置
    data   = AddData<T>();                  // ② 注册数据容器（必须在 Logic 前）
    AddLogic<T>();                          // ③ 注册逻辑组件（被动响应，无 Update）
    AddStage<T>();                          // ④ 注册阶段（有序驱动，唯一有 Update）
    ChangeStage<T>();                       // ⑤ 进入初始阶段（仅 Server 端）
    ControllerManager.Instance.Open<T>();   // ⑥ 打开 UI 控制器（仅 Client 端）
}
```

## 三、配置文件详解

### 3.1 GameMode.txt

**路径**：`Assets/ToBundle/Config/Txt/GameMode.txt`

```
格式：ID|Name|Type|Rule|Icon|...
示例：28|GoldDash|1|...|icon_golddash|...
```

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | int | 模式 ID，对应 GameMode 枚举值 |
| Name | string | 模式标识名 |
| Type | int | 模式类型分类 |
| Rule | string | 规则描述 |

### 3.2 ShowMode.txt（展示模式）

### 3.3 MatchMode.txt（匹配模式配置）

**路径**：`Assets/ToBundle/Config/Txt/MatchMode.txt`

定义每一个可匹配的具体模式实例（含地图变体）。一个 ShowMode 可对应多条 MatchMode。新模式上线必须在此表中注册才能进入匹配。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 匹配模式唯一 ID |
| sign | string | 匹配模式标识（如 `WAR_SCORE`、`DEFUSAL_1`） |
| description | string | 中文描述（如 "经典-战斗岛"） |
| game_mode | int | 游戏模式 ID，对应 `GameMode.txt` 的 ID（即 `WarData.Game_Mode`） |
| map_mode | int | 地图模式 ID，对应 `GameMap.txt` 的 ID |
| show_mode | int | 展示模式 ID，对应 `ShowMode.txt` 的 ID，决定前端归属分类 |
| match_server_type | sbyte | 匹配服务器类型（0=普通, 1=专用服） |
| icon | string | 入口 UI 图标资源名 |
| history_description | string | 历史战绩描述文本，`;` 分隔多行，`{0}` 为动态参数占位 |
| friends_description | string | 好友列表中显示的模式简称 |
| game_over_description | string | 结算界面描述文本，`{0}` 为动态参数占位 |
| is_show_group | sbyte | 是否显示队伍人数（0=关闭, 1=开启） |
| record_historical_data | sbyte | 是否记录历史数据（0=不记录, 1=记录） |

| pet_war | int | 战场宠物配置（0=无, 1=普通战场, 2=特殊战场） |
| enable_match | bool | 是否激活匹配（0=关闭, 1=开启） |
| fill_member_policy | int | 补充队友策略（0=不补充, 1=正常补充, 2=特殊补充） |

**关键关系**：

```
ShowMode.txt (展示分类)          MatchMode.txt (具体实例)
┌──────────────────┐      ┌─────────────────────────────────┐

GameMode.txt (游戏逻辑)          MatchMode.txt
┌──────────────────┐      ┌─────────────────────────────────┐
│ id=1 经典吃鸡     │◀─────│ game_mode=1  WAR_SCORE          │
```

### 4.1 Manager 注册模板（Server 端）

**文件**：`Assets/Script/GamePlay/Server/Modules/Mode/{ModeName}/Server{ModeName}Mgr.cs`

```csharp
public class Server{ModeName}Mgr : ServerModeManager {
    private Server{ModeName}Data data;
    public Server{ModeName}Data Data => data;

    protected override void OnInit() {
        base.OnInit();
        
        // ① 注册 Data（必须最先）
        data = AddData<Server{ModeName}Data>();
        
        // ② 注册 Logic（顺序无关）
        AddLogic<Server{ModeName}AwardLogic>();
        AddLogic<Server{ModeName}NsqDataLogic>();
        AddLogic<Server{ModeName}RoleLogic>();
        
        // ③ 注册 Stage（按游戏流程顺序）
        AddStage<Server{ModeName}BornStage>();
        AddStage<Server{ModeName}BattleStage>();
        AddStage<Server{ModeName}OverStage>();
        
        // ④ 进入初始阶段（必须最后）
        ChangeStage<Server{ModeName}BornStage>();
    }
    
    public override bool IsBattleStart() {
        return RunningStageIs<Server{ModeName}BattleStage>();
    }
}
```

### 4.2 Manager 注册模板（Client 端）

**文件**：`Assets/Script/GamePlay/Client/Modules/Mode/{ModeName}/Client{ModeName}Mgr.cs`

```csharp
public class Client{ModeName}Mgr : ClientModeManager {
```

## 五、常见问题与踩坑记录

### 5.1 Client 阶段切换失败

**问题现象**：Server 切换阶段后，Client 端无反应或报错 "Stage not found"

**根因分析**：Client 和 Server 的 Stage 类名不对称。Server 通过 `string.Replace("Server","Client")` 将 Stage 名称转换后发送给 Client。

**解决方案**：
1. 确保 Stage 命名严格对称：`ServerXxxStage` ↔ `ClientXxxStage`
2. 确保 Client Manager 的 `OnInit()` 中 `AddStage<>()` 注册了所有 Stage
3. 排查顺序：检查 ClientModeFactory case → 检查 Manager.AddStage → 检查类名对称

### 5.2 Logic 的 OnInit 中 GetData 返回 null

**问题现象**：在 Logic 的 `OnInit()` 中调用 `manager.GetData<T>()` 返回 null

**根因分析**：Manager 的 `OnInit()` 中注册顺序不正确。`AddData<>()` 必须在 `AddLogic<>()` 之前调用，因为 Logic.OnInit() 在 AddLogic 时立即执行。

**解决方案**：

```csharp
protected override void OnInit() {
    base.OnInit();
    data = AddData<T>();       // ① Data 最先
    AddLogic<T>();             // ② Logic 其次（此时 Data 已可用）
    AddStage<T>();             // ③ Stage 最后
    ChangeStage<T>();          // ④ 进入初始阶段
}
```

### 5.3 WarData.GameMode 与 GameMode.cs 的 GameMode 枚举混淆

**问题现象**：Factory 中 switch 使用了错误的枚举类型

**根因分析**：项目中存在两个名为 "GameMode" 的枚举：
- `WarData.GameMode` — 在 `Data/WarData.cs` 中，是 Factory switch 使用的枚举，表示模式**类别**
- `GameModeBase.GameMode` — 在 `Data/Base/GameMode.cs` 中，是自动生成的枚举，表示具体**地图变体**

**解决方案**：Factory 中始终使用 `WarData.GameMode`（带 `WarData.` 前缀）

### 5.4 多个 case 共享同一个 Manager

**问题现象**：某些模式在不同场景下使用相同的 Manager（如 GoldDash 和 GoldDashBossRushMode）

**根因分析**：这是设计意图。部分模式的变体仅在配置上有差异，共用同一套 Manager/Stage/Logic/Data。

**解决方案**：在 Factory 中多个 case 可以指向同一个 Manager：

```csharp
case WarData.GameMode.GoldDash:
case WarData.GameMode.GoldDashBossRushMode:
    gameWorld.AddExtendFeature<ServerGoldDashMgr>();
    break;
```

模式内部通过 `WarData.Game_Mode` 判断具体变体并调整行为。

### 5.5 CommonMode 继承时遗漏消息注册

**问题现象**：继承 CommonManager 的模式丢失了回合制/武器购买等功能

**根因分析**：CommonManager 的 OnInit 中注册了大量消息监听（动态数据同步、静态数据同步等）。如果子类 OnInit 没有调用 `base.OnInit()`，这些消息将不会被注册。

**解决方案**：继承 CommonManager 时必须在 OnInit 开头调用 `base.OnInit()`。
