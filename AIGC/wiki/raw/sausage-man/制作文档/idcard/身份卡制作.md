# 1 代架构身份卡（IdCard）制作规范

> **适用范围**：新增身份卡（IdCard）功能实现，含技能 BS 代码、BSO 配置、预制体、皮肤系统  
> **不适用**：修改身份卡框架层代码（如 `RoleSkill.cs`、`RoleLogicClient_IdCardSkin.cs`）；纯 UI 样式调整  
> **参考实现**：简单卡 → `SandPlatform`（1 技能、完整三端）；复杂卡 → `Clown`（5 子功能、三端）；纯 BSO 卡 → `Neptune`

---

## 一、架构概述

### 1.1 系统分类

身份卡系统由 **两层** 组成：

| 层级 | 说明 | 修改频率 |
|------|------|---------|
| **框架层**（Infrastructure） | 配置解析、皮肤/时装替换、技能 UI、捡取/丢弃逻辑、网络同步 | ❌ 不修改 |
| **卡实现层**（Per-Card） | 每张卡的 BS 技能类（C/S/H 三端）+ BSO ScriptableObject 配置 | ✅ 新增修改 |

**技能实现分两种模式：**

| 模式 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **纯 BSO 配置** | 仅创建 BSO `.asset` + 炸弹预制体，复用通用 BS 基类 | 简单投掷/状态技能 | Neptune、CaoCao、Sungod |
| **自定义 BS 代码** | 创建 BS{SkillName}{Client/Server/Host}.cs 三端代码 + BSO | 需要自定义逻辑的技能 | Hades、Clown、Kitty |

### 1.2 核心类依赖

```
[框架层 — 禁止修改]
├── SORoleSkillConfig.cs ─────── 技能配置表（23字段，SkillCardType绑定身份卡）
├── IdCardSkinConfig.cs ──────── 身份卡皮肤配置（id, IdCardSign, Clips）
├── IdCardSkinFashionConfig.cs ─ 皮肤时装配置（12个部位）
├── RoleSkill.cs ─────────────── 技能管理器（OnPickIDCard/OnRemoveIDCard）
├── RoleSkillBase.cs ─────────── 技能表现基类（Init/OnDown/OnDrag/OnUp/CmdUseSkill）
├── RoleSkillEffect.cs ────────── 头部特效管理
├── RoleLogicClient_IdCardSkin.cs 皮肤替换系统（8种替换类型）
└── UIRoleSkillMgr.cs ─────────── 技能UI管理

[卡实现层 — 新增区域]
├── BuffScriptableObject/
│   └── BSO{SkillName}.cs ─────── BSO配置类（继承 BuffSOBase）
├── Host/Modules/Buff/BuffSystem/
│   └── BS{SkillName}.cs ──────── Host端入口（继承 BuffSystemBase）
├── Client/Modules/Buff/BuffSystem/
│   └── BS{SkillName}Client.cs ── 客户端表现（继承 BuffSystemClientBase）
└── Server/Modules/Buff/BuffSystem/
    └── BS{SkillName}Server.cs ── 服务端逻辑（继承 BuffSystemServerBase）
```

### 1.3 预制体与资源加载 ★强制

| 资源类型 | 路径规范 | 加载方式 |
|---------|---------|---------|
| **身份卡道具预制体** | `Assets/ToBundle/Items/Equipment/FunctionalGarment/IDCard_{CardName}.prefab` | `ItemAsset` 配置表注册 → `AssetManager` 按 Sign 加载 |
| **技能炸弹预制体** | `Assets/ToBundle/Items/Stunt/Bomb/{SkillName}.prefab` | BSO 配置中的 `PrefabName` 字段引用 → `BuffControl.PlayBuff` 时加载 |
| **BSO 配置文件** | `Assets/ToBundle/ScriptableObject/Buff/Skills/{SkillName}.asset` | `BuffControl` 通过 SkillBuffSign 查找 → `BuffSOBase.init()` 实例化 |
| **皮肤替换资源** | `Assets/ToBundle/Items/Equipment/FunctionalGarment/Skins/` | `RoleLogicClient_IdCardSkin` 按命名规范 `{原始标识}_Skin{索引}` 加载 |
| **技能头部特效** | 由 `RoleSkillEffect` 管理 | `SkillEffect.OnEquipIDCard()` 时加载 |
| **技能图标** | 由 `SORoleSkillConfig.IconName` 指定 | UI 层按图标名加载 |

**命名规范：**
- 身份卡预制体：`IDCard_{CardName}`（CardName 首字母大写驼峰）
- 技能炸弹预制体：`{SkillName}`（与 SORoleSkillConfig.PrefabName 一致）
- BSO 配置：`BSO{SkillName}.asset` 或 `{SkillName}.asset`（两种命名均存在）
- 皮肤资源命名：`{原始标识}_Skin{皮肤索引}`（如 `NinjaHookFly_Skin1`）

## 二、新建身份卡 Checklist

### Phase 1：配置表填写

| 步骤 | 操作 | 配置文件 | 说明 |
|------|------|---------|------|
| 1.1 | 注册 ItemAsset | `ItemAsset.txt` | 添加身份卡道具条目，Type 设为身份卡类型 |
| 1.2 | 注册 SORoleSkill | `SORoleSkill.txt` | 为每个技能添加一行（通常 2 行），**SkillCardType 列必须填写新卡的唯一类型编号** |
| 1.3 | 注册 IdCardSkin | `IdCardSkin.txt` | 添加皮肤映射条目（id, IdCardSign, Clips） |
| 1.4 | 注册 IdCardSkinFashion | `IdCardSkinFashion.txt`（可选） | 如需时装替换，添加 12 部位配置 |

**★ 关键**：`SORoleSkill.txt` 的 `SkillCardType`（第 18 列，索引 17）将技能绑定到身份卡。同一张卡的两个技能必须使用相同的 `SkillCardType` 值。当前已使用的编号：1-10, 15-16, 18-24。

### Phase 2：BSO 配置类 + 资产

| 步骤 | 操作 | 说明 |
|------|------|------|
| 2.1 | 创建 BSO 类 | `Assets/Script/GamePlay/Host/Modules/Buff/BuffScriptableObject/BSO{SkillName}.cs` |
| 2.2 | 创建 BSO 资产 | Unity Editor → Create → War/Buff/BSO{SkillName}，保存至 `Assets/ToBundle/ScriptableObject/Buff/Skills/` |
| 2.3 | 填写 BSO 参数 | 在 Inspector 中配置技能数值（伤害、范围、CD 等） |

### Phase 3：BS 技能代码（三端）

| 步骤 | 操作 | 路径 |
|------|------|------|
| 3.1 | 创建 Host 端入口 | `Assets/Script/GamePlay/Host/Modules/Buff/BuffSystem/BS{SkillName}.cs` |
| 3.2 | 创建 Server 端逻辑 | `Assets/Script/GamePlay/Server/Modules/Buff/BuffSystem/BS{SkillName}Server.cs` |
| 3.3 | 创建 Client 端表现 | `Assets/Script/GamePlay/Client/Modules/Buff/BuffSystem/BS{SkillName}Client.cs` |

**注意**：如果技能不需要自定义逻辑（如纯投掷炸弹），可跳过 Phase 3，仅使用 BSO 配置 + 通用 BS 基类。

### Phase 4：预制体资源

| 步骤 | 操作 | 说明 |

| 4.1 | 创建身份卡预制体 | `Assets/ToBundle/Items/Equipment/FunctionalGarment/IDCard_{CardName}.prefab` |

| 4.4 | 准备皮肤资源 | 如有皮肤变体，按 `{原始标识}_Skin{索引}` 命名 |

### Phase 5：测试验收

| 步骤 | 操作 | 说明 |
|------|------|------|
| 5.1 | 本地运行捡取测试 | 验证捡取后 UI 显示两个技能按钮 |

## 五、常见问题与踩坑记录

### 5.1 SkillCardType 编号冲突

**症状**：新卡技能在其他身份卡上触发  
**原因**：`SORoleSkill.txt` 中 `SkillCardType` 使用了已有编号  
**解决**：新卡必须使用未使用的编号。当前已用：1-10, 15-16, 18-24。建议新卡从 25 开始或使用 11-14, 17 中的空位  
**预防**：新增前先搜索 `SORoleSkill.txt` 确认编号未被占用

### 5.2 BSO init() 返回类型不匹配

**症状**：`NullReferenceException` 在 `BuffControl.PlayBuff` 时  
**原因**：BSO 的 `init()` 方法中实例化的类名与 Host 端 BS 类名不一致  
**解决**：确保 `BSO{SkillName}.init()` 中 `new BS{SkillName}()` 的类名与 `BS{SkillName}.cs` 文件中的类名完全一致  
**预防**：BSO 类、Host 类、Server 类、Client 类四者命名必须遵循 `BSO{SkillName}` / `BS{SkillName}` / `BS{SkillName}Server` / `BS{SkillName}Client` 规范

### 5.3 Host 端缺少 RequestGameLoop 调用

**症状**：Server 或 Client 端的 `Init()` / `OnUpdate()` 不执行  
**原因**：Host 端 `BS{SkillName}.cs` 的 `InitServer` / `InitClient` 中未调用 `RequestGameLoop<T>()`  
**解决**：确保 `InitServer` 调用 `RequestGameLoop<BS{SkillName}Server>()`，`InitClient` 调用 `RequestGameLoop<BS{SkillName}Client>()`  
**预防**：直接复制 §4.2 模板

### 5.4 Server/Client 端未正确注册 Logic 引用

**症状**：Host 端无法访问 Server/Client 端逻辑  
**原因**：Server/Client 的 `Init()` 中未将自身赋值给 Host 端的 `ServerLogic` / `ClientLogic` 属性  
**解决**：在 `Init()` 中添加 `((BS{SkillName}) buffSystem).ServerLogic = this;`  
**预防**：直接复制 §4.3 / §4.4 模板

### 5.5 皮肤资源命名不规范导致加载失败

**症状**：切换皮肤后角色外观不变  
**原因**：皮肤资源未按 `{原始标识}_Skin{索引}` 规范命名  
**解决**：确认皮肤资源命名与 `RoleLogicClient_IdCardSkin.cs` 中的命名规范一致  
**预防**：参考 §1.3 命名规范

### 5.6 RoleSkill 模块与 BuffSystem 模块路径混淆

**症状**：BS 类放错目录导致无法正确加载  
**原因**：部分历史卡（如 Geed、Zero、Zeta、WolfMan）使用 `RoleSkill` 模块路径而非 `BuffSystem` 模块路径  
**解决**：**新卡统一使用 BuffSystem 模块路径**（`Modules/Buff/BuffSystem/`），不再使用 `Modules/RoleSkill/` 路径  
**预防**：旧卡使用 RoleSkill 路径是历史遗留，新卡不要参考这些卡的路径
