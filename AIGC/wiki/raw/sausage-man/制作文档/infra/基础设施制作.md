# 1 代架构基础设施制作规范

> **适用范围**：Utils 工具库、Config 配置系统、Data 数据层、Controller 控制器层 — 新增工具类/配置表/数据结构/对象池使用
> **不适用**：GamePlay 战斗逻辑 → 归各功能 feature；UI 视图 → 归 UI 系统；网络协议 → 归 [[网络消息制作]]
> **参考实现**：ConfigManager（配置加载典型）、GameObjectPool（对象池典型）、LocalSave（本地存储典型）

### 1.2 ConfigManager 加载机制

```
游戏启动 → ConfigManager.Instance 初始化
  │
  ├── 注册所有 Config 类型 (反射/手动注册)
  │
  └── 按需懒加载:
        首次调用 ConfigManager.Get<PickItemDataConfig>()
          ├── [txt 模式] 读取 Assets/ToBundle/Config/Txt/PickItemData.txt
          │     → 按行解析 Tab 分隔字段
          │     → 构建 Dictionary<int, PickItemDataConfig> (以 Sign 为 key)
          │     → 缓存到 ConfigManager 内部字典
          │
          └── [binary 模式] 读取 ByteBufferUnsafe 二进制数据
                → ByteBufferUnsafe.ReadInt/ReadFloat/ReadString...
                → 构建同样的 Dictionary
                → 比 txt 解析更快（发布版使用）

        后续调用 → 直接返回缓存实例
```

### 1.3 GameObjectPool 对象池

```
GameObjectPool (核心对象池系统)
  │
  ├── Get(string path) [同步]
  │     → 查 freeList[path] → 有则复用 (SetActive(true), 移到 activeList)
  │     → 无则 AssetManager.Load(path) → Instantiate → 加入 activeList
  │
  ├── GetAsync(string path, Action<GameObject> callback) [异步]
  │     → 查 freeList[path] → 有则复用
  │     → 无则 AssetManager.LoadAsync(path) → 异步回调
  │
  ├── Release(GameObject go) [回收]
  │     → 从 activeList 移到 freeList
  │     → go.transform.position = hidePoint (-5000, 0, 0)
  │     → go.SetActive(false)
  │     → 开始 lifeTime 计时（超时自动 Destroy）
  │
  └── 自动卸载
        → freeList 中超过 lifeTime 的对象自动 Destroy
        → 释放 AssetBundle 引用
```

### 1.4 预制体与资源加载（★）

| 资源 | 路径 | 加载方式 | 时机 |
|------|------|---------|------|
| **配置表 .txt** | `Assets/ToBundle/Config/Txt/*.txt` | ConfigManager.Get<T>() 懒加载 | 首次访问 |
| **配置表 binary** | 构建后路径 | ConfigManager.Get<T>() 二进制 | 发布版首次访问 |
| **SO 配置** | `Assets/ToBundle/ScriptableObject/` | AssetsLoad.GetSO<T>() | 按需 |
| **对象池资源** | 各目录 Prefab | GameObjectPool.Get/GetAsync | 按需 |
| **LocalSave** | PlayerPrefs | 系统 API | 任意时刻 |

### 1.5 禁止修改的文件

- **ConfigManager.cs 加载流程** — 影响所有配置表加载
- **GameData.cs 已有静态属性** — 全局引用，修改影响面极大
- **Config/ 下自动生成的文件** — 手动修改会被工具覆盖
- **GameObjectPool.cs 核心 Get/Release 逻辑** — 影响所有对象池使用者

## 三、配置文件详解

### 3.1 配置表 .txt 格式

**路径**：`Assets/ToBundle/Config/Txt/{TableName}.txt`

```
# 格式：Tab 分隔，第一行字段名，后续行数据
# 字段类型由生成工具自动推断

Sign	Name	Value	Type	Description
10001	金币	100	1	基础金币
10002	钻石	50	2	高级货币
```

**自动生成的 Config 类**：

```csharp
// {TableName}Config.cs — 自动生成，勿手动编辑
public class {TableName}Config : IConfig {
    public int Sign;
    public string Name;
    public int Value;
    public int Type;
    public string Description;
    
    // 查询接口
    public static {TableName}Config GetBySign(int sign) { ... }
    public static List<{TableName}Config> GetAll() { ... }
    public static {TableName}Config GetByIndex(int index) { ... }
}
```

### 3.2 ConfigManager 使用方式

```csharp
// 获取配置实例（懒加载，线程安全）
var config = ConfigManager.Get<PickItemDataConfig>();

// 查询单条
var item = PickItemDataConfig.Instance.GetBySign(10001);
string name = item.Name;       // "金币"
int value = item.Value;        // 100

// 查询全部
var allItems = PickItemDataConfig.Instance.GetAll();
foreach (var item in allItems) {
    Debug.Log($"{item.Sign}: {item.Name}");
}
```

### 3.3 LocalSave 使用方式

**路径**：`Assets/Script/Utils/LocalSave/LocalSave.cs`

```csharp
// 基本读写
LocalSave.SetInt("key", 100);
int val = LocalSave.GetInt("key", defaultValue: 0);

// Bool 扩展
LocalSave.SetBool("isFirstPlay", true);
bool first = LocalSave.GetBool("isFirstPlay");

// Vector3 扩展（序列化为 3 个 float）
LocalSave.SetVector3("lastPosition", new Vector3(1, 2, 3));
Vector3 pos = LocalSave.GetVector3("lastPosition");

// ⚠️ PlayerPrefs 底层限制：
// - key 字符串长度有限
// - 不适合存大量数据（> 100KB）
// - 不支持并发写入
// - iOS 可能被系统清理
```

### 3.4 MonoObjectPool<T> 泛型池

```csharp
// 创建泛型池（非 GameObject 的组件级池化）
var pool = new MonoObjectPool<BulletTracer>(capacity: 50);

// 预分配
pool.PreAllocate(20);  // 提前创建 20 个实例

// 使用
var tracer = pool.Get();
tracer.Init(startPos, endPos);
// ... 使用完毕
pool.Release(tracer);

// 与 GameObjectPool 区别：
// GameObjectPool: 管理 GameObject（带 AssetBundle 加载/卸载）
// MonoObjectPool<T>: 管理任意类型实例（纯内存，无IO）
```

## 五、常见问题与踩坑记录

### 5.1 配置表加载 NullReferenceException

**现象**：`ConfigManager.Get<T>()` 返回 null 或字段值全为 0/空

**根因**：
- .txt 文件编码不是 UTF-8（BOM 干扰解析）
- Tab 字符被替换为空格（编辑器自动替换）
- 字段数量与 Config 类不匹配（.txt 改了但没重新生成 .cs）

**解决方案**：
1. 确保 .txt 使用 UTF-8 无 BOM 编码
2. 确保分隔符是 Tab（\t），不是空格
3. 修改 .txt 后必须重新运行配置生成工具
4. 检查 Console 日志中 ConfigManager 的加载错误信息

### 5.2 对象池泄漏

**现象**：运行一段时间后内存持续增长，FrameDebugger 显示大量隐藏对象

**根因**：
- 使用 `Object.Destroy()` 而非 `GameObjectPool.Release()` 回收对象
- Release 后仍持有引用，阻止 GC
- lifeTime 设置过长，freeList 堆积

**解决方案**：
1. 所有通过 GameObjectPool.Get 获取的对象必须用 GameObjectPool.Release 回收
2. Release 后将引用置 null
3. 检查 lifeTime 配置是否合理（推荐 30-60 秒）

### 5.3 LocalSave 数据丢失

**现象**：重启游戏后 LocalSave 数据消失

**根因**：
- iOS 系统清理（PlayerPrefs 可能被清理）
- key 拼写不一致（存储用 "abc"，读取用 "Abc"）
- 未调用 PlayerPrefs.Save()（Android 崩溃时丢失）

**解决方案**：
1. 重要数据不要仅依赖 LocalSave，需有服务端备份
2. key 使用常量管理，避免拼写错误
3. 关键数据修改后调用 PlayerPrefs.Save() 强制写盘

### 5.4 Config 与 SO 混淆使用

**现象**：同一数据同时在 .txt 和 SO 中配置，导致数值冲突

**根因**：未明确数据归属 — .txt 适合大批量数据（策划配表），SO 适合少量可视化配置（程序调参）

**解决方案**：
1. **大批量数据**（道具/Buff/技能参数）→ .txt 配置表
2. **少量可视化参数**（镜头/物理/美术参数）→ SO
3. 同一数据不要在两处重复配置
4. 如有冲突，以 .txt 为准（策划优先）

### 5.5 Controller 事件未注销

**现象**：UI 面板关闭后仍收到事件回调，导致 NullReferenceException

**根因**：OnShow() 中注册了事件监听，但 OnHide() 中忘记注销

**解决方案**：
1. OnShow/OnHide 中事件注册/注销必须成对
2. 使用 `UnregisterAll()` 在 OnHide 中统一注销
3. 避免在 Controller 中持有已销毁的 GameObject 引用
