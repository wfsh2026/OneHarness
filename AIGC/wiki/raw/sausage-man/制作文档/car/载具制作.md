# 1 代架构载具制作规范

> **适用范围**：基于 `MotorCarController` 物理栈的载具开发（Jeep / Buggy / PonyVehicle / MotoSheep / JetCar / HoverBoard 等）
> **不适用**：GPO 载具（Tank / Helicopter / Peterosaur）— 属于 2 代架构，此文档不涵盖
> **参考实现**：暴躁绵羊（MotoSheep），技术文档 → [[暴躁绵羊-载具系统]]

---

## 一、架构概述

### 1.1 两套载具体系对比

| 维度 | 1 代架构（MotorCarController） | GPO 架构（Tank/Helicopter） |
|------|------|------|
| 物理驱动 | `MotorCarController`（WheelCollider） | `CharacterController` / 自定义 |
| 管理方式 | `Car.cs` + `CarNet` 直接管理 | System/Component 体系 |
| 网络同步 | `CarNetServer` / `CarNetClient` | NetworkTransform + GPO 同步 |
| 技能系统 | `VehicleStateButtonControl` → `SM_Ability.PlayAbility` | GPO 事件链 |
| 创建流程 | `StartGame.AddCarForData()` → 预制体实例化 | `GPOManager.CreateGPO()` → System 注册 |
| 预制体位置 | `Assets/ToBundle/Skin/Cars/{Sign}/` | `Assets/ToBundle/Biubiubiu2/GamePlay/AI/`（2 代路径） |

### 1.2 核心类依赖

```

```

#### 加载器源码

Assets/Script/Asset/GameObjectPools/CarPool.cs  ← 对象池管理（实际加载实现）

#### 核心预制件

| 方法 | 资源路径 | 职责 |
|------|---------|------|
| `AssetsLoad.GetCar(carSign, carName)` | `Assets/ToBundle/Skin/Cars/{path}/{name}.prefab` | 载具主预制体（通过 CarPool 对象池） |

【客户端生成】

### 1.4 禁止修改的文件

- **`MotorCarController.cs`** — 核心物理控制器，影响所有载具

## 三、配置文件详解

### 3.1 SOCarData.txt — 载具数值

```
Id         CarSign    HP    Oil    CarRoleNum    BoomDamage    BoomRadius    skill1
{Sign}     {Sign}     1230  5000   2             300           6             AB_{SkillSign}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `Id` | string | 载具唯一 ID，通常与 CarSign 相同 |
| `CarSign` | string | 载具标识，必须与 `ItemData.{Sign}` 一致 |
| `HP` | int | 最大血量 |
| `Oil` | int | 油箱容量（油耗速率由 CarShift 全局控制） |
| `CarRoleNum` | int | 最大乘坐人数（1=单人，2=双人） |
| `BoomDamage` | int | 爆炸伤害值 |
| `BoomRadius` | float | 爆炸半径（米） |
| `skill1` | string | 技能 1 的 Ability Sign（无技能则留空） |

### 3.2 SOCreateObjData — 地图载具生成概率

```yaml
vehicleCreateRatio:
  - carSign: {Sign}
    Ratio: 20
```

- **Ratio 是权重值**，非百分比。所有载具 Ratio 之和不必为 100，系统按相对比例随机选取。
- 每个地图模式对应一个 `.asset` 文件，路径：`Assets/ToBundle/ScriptableObject/SOCreateObjData/`
- **⚠️ 新载具必须添加到所有目标地图的 `.asset` 中**，否则该地图不会生成此载具。
- 空数组 `vehicleCreateRatio: []` 表示该地图不刷任何载具，无需添加。

### 3.3 CarItemAsset.txt — 皮肤 Bundle 路径

```
id                  path                      name
{Sign}              {Sign}/{Sign}             {Sign}
{Sign}_Low          {Sign}/{Sign}             {Sign}_Low
{Sign}_Spoiled      {Sign}/{Sign}             {Sign}_Spoiled
```

- `path` 相对于 `Assets/ToBundle/Skin/Cars/`
- 每个载具至少需要 3 条：常规 + 低配 + 损毁

### 3.4 SOCarSkinData.txt — 皮肤映射

```
id       CarSpoiledSign       CarSign    moveEff               shiftEff             isLow
{Sign}   {Sign}_Spoiled       {Sign}     {Sign}_Effect_loop    {Sign}_Effect_UI     {Sign}_Low
```

- `moveEff` / `shiftEff`：特效名称，无自定义特效时可复用同类型载具的特效（如 PonyVehicle_Effect_loop）

### 3.5 SOCarSkill.txt — 技能配置

```
Id               CarSign    SkillCD  SkillTime  ShowImg         Posx   Posy   Scale
AB_{SkillSign}   {Sign}     30       5          {Sign}_Skill    -445   420    0.7
```

- `SkillCD`：冷却时间（秒），测试期可降为 10s
- `ShowImg`：War 图集中的 Sprite 名称，需美术提供

## 六、常见问题与踩坑记录

### 6.1 载具不在地图中生成

**原因**：未在 `SOCreateObjData/{地图名}CreateData.asset` 的 `vehicleCreateRatio` 数组中添加条目。

**解决**：编辑 `.asset` 文件（YAML 格式），在 `vehicleCreateRatio` 数组末尾添加：
```yaml
  - carSign: {Sign}
    Ratio: 20
```

**注意**：需在**所有目标地图**的 `.asset` 中添加，不同地图使用不同的 `.asset` 文件。

### 6.2 编译报错 CS1061 / CS0103

**原因**：`ItemData.{Sign}` 常量未定义或拼写错误。

**解决**：检查 `ItemData.cs` 中是否存在 `public const string {Sign} = "{Sign}";`。

### 6.3 上车后无技能按钮

**原因**：`VehicleStateButtonControl.cs` 中未添加 `case ItemData.{Sign}` 分支。

**解决**：在 switch 中添加对应 case，包含 `InputSkill(N)` 调用。

### 6.4 技能释放无效果

**排查顺序**：
1. `SOCarSkill.txt` 是否有 `{Sign}` 对应行
2. `SOCarData.txt` 的 `skill1` 字段是否填写了正确的 Ability Sign
3. `CarNetServer.cs` 是否有 `On{Sign}UseSkill()` 方法
4. `ServerAbilityManager_SwitchAB.cs` 是否有该 Ability 的 switch case

### 6.5 AutoWar 模式替换

**注意**：`AddCarAutoWar.cs` 中硬编码了 `"MotoSheep" → "PonyVehicle"` 替换。如果新载具在自动战斗中需要特殊处理，需在该文件中添加对应逻辑。

### 6.6 SystemBase.AddComponent 返回 void

**设计原则**：`AddComponent<T>(data)` 返回 `void`，System 不应持有 Component 引用。Component 通过 `OnSetEntityObj()` 自驱动初始化。`GetComponent<T>()` 在 SystemBase 中被注释掉。
