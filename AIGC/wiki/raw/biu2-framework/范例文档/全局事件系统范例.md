## 1. 系统概述

**EventDirector（全局事件系统）** 是 BiuBiuBiu2 游戏内面向玩法内容的动态事件驱动框架。它与架构内的 `MsgRegister.Register` / `mySystem.Register` 完全不同——后者是底层消息总线，而 EventDirector 是**游戏玩法层面的高阶事件编排系统**，专门为策划/开发提供"在游戏运行中按需触发玩法内容"的扩展接口。

### 核心定位

| 维度 | 说明 |
|------|------|
| **作用范围** | 游戏内玩法内容，如机制触发、怪物生成、增益/减益效果 |
| **驱动方式** | 时间窗口 + 目标主体 + 条件判断 → 动作执行 |
| **数据驱动** | 所有配置基于 Unity ScriptableObject（.asset），无需改代码即可新增事件 |
| **网络同步** | 服务端主导逻辑，通过 TargetRpc 协议将状态同步给对应客户端 |
| **登录补偿** | 玩家登录时服务端自动补发当前正在进行的事件、条件、动作状态 |

│  3. 全部加载完成后 Dispatch → SE_EventDirector.SetEventList       │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│              ServerEventDirectorCore                             │
│  接收 SetEventList → 为每个事件创建 EventDirectorInstance         │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                      ┌─────────▼──────────┐
                      │ EventDirectorInstance│  ← 每个事件一个实例
                      │  每帧 Update (1s间隔)│
                      └───────┬────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        ┌──────────┐  ┌──────────────┐  ┌──────────────┐
        │   Time   │  │   Subject    │  │  Condition   │
        │  时间检查 │  │  目标主体扫描  │  │  条件逻辑判断  │
        └──────────┘  └──────────────┘  └──────┬───────┘
                                               │ 条件满足
                                               ▼
                                       ┌──────────────┐
                                       │    Action    │
                                       │  动作执行逻辑  │
                                       └──────┬───────┘
                                              │
                          ┌───────────────────┼───────────────────┐
                          ▼                   ▼                   ▼
               SM_EventDirector       TargetRpc (网络)     QuitCondition
               (内部服务端消息)      同步给客户端             退出条件监听
```

### 完整生命周期时序

```
StartMode
  └─► GetData.LoadSOConfig()
        └─► SE_EventDirector.SetEventList
              └─► Core.CreateInstance()   [每个事件创建 EventDirectorInstance]
                    └─► Instance.Update() [每秒轮询]
                          ├─► CheckTime()
                          │     └─► IsInTime=true → 初始化 Subject
                          └─► CheckCondition()
                                ├─► CheckEnterCondition()  [进入条件]
                                │     └─► 条件满足 → CreateAction()
                                │                └─► WaitAction → EnterAction
                                │                      └─► (服务端执行)
                                │                            └─► TargetRpc → 客户端
                                │           └─► CreateQuitCondition()
                                └─► CheckQuitCondition()   [退出条件]
                                      └─► 条件满足 → QuitAllAction()
```

## 4. 核心设计：Time · Subject · Condition · Action

EventDirector 的核心设计理念是将"**何时生效 → 作用于谁 → 满足什么条件 → 执行什么**"四个维度正交拆分，通过 ScriptableObject 自由组合，实现游戏内任意玩法事件的数据驱动配置。

### 4.1 Time（时间窗口）

**设计含义**：控制事件在何时段内处于"激活"状态，时间未满足则整个事件暂停轮询，节省性能开销。

```
时间类型（TimeType）
│
├── AnyTime            任何时候都生效（不填时间时默认）
├── GameStartTime      从游戏开始经过指定时间段（StartTime ~ EndTime，单位秒）
├── RoundStartTime     从本回合开始经过指定时间段（StartTime ~ EndTime）
└── RoundIndex         指定第 N 回合才激活（TODO：预留扩展）
```

- **逻辑关系**（`TimeLogicType`）：当配置多个时间段时，支持 `And`（全满足）/ `Or`（任一满足）/ `Random`（随机选一个）三种组合逻辑。
- **实现机制**：`EventDirectorTime` 基类 + 各子类覆写 `CheckInTime()`。时间不满足时清理 Subject 和 Condition，时间恢复时重新初始化。

### 4.2 Subject（目标主体）

**设计含义**：定义事件"作用于谁"的作用域。Subject 负责从游戏对象（GPO）列表中筛选出符合条件的目标，并将其注册到后续的 Condition 和 Action 中，同时动态跟踪目标的进入/离开。

```
主体类型（SubjectType）
│
├── World                  全局（无具体主体，事件作用于整个世界）
├── Player                 单个玩家（按玩家 GpoID 分组，每个玩家独立条件实例）
├── PlayerAndPlayerAI      单个玩家 + 其控制的 AI
├── AI                     单个怪物
├── PlayerGroup            所有玩家作为一个整体组
├── PlayerAndPlayerAIGroup 所有玩家+AI 作为一个整体组
├── AIGroup                所有怪物作为一个整体组
├── PlayerTeam             玩家队伍（按队伍 ID 分组）
├── GPOMId                 指定模板 ID 的 GPO（精确指定某只怪物）
├── GPOMTypeId             指定模板类型 ID 的 GPO（某类型所有怪物）
└── GPOMIdGroup            指定模板 ID 的 GPO 组
```

- **分组机制**：Subject 返回 `subjectId` 作为分组 Key，相同 `subjectId` 的 GPO 共享同一套条件实例，不同分组独立检测，互不干扰。
- **动态响应**：Subject 监听 `SM_GPO.AddGPOEnd` / `SM_GPO.RemoveGPOEnd`，实时维护目标列表。

### 4.3 Condition（触发条件）

**设计含义**：定义"什么行为/状态下触发事件"。条件分为 **进入条件（Enter）** 和 **退出条件（Quit）**，进入条件满足后执行 Action，退出条件满足后结束 Action。

```
条件类型（ConditionType）
│
├── 行为统计类
│   ├── FireCount           开火次数达到阈值
│   ├── SlideCount          滑铲次数达到阈值
│   ├── KillAI              击杀怪物数量达到阈值
│   ├── KillMTypeAI         击杀指定类型怪物数量
│   ├── KillQualityAI       击杀指定品质怪物数量
│   └── KillRangePointAI    击杀指定位置范围内的怪物数量
│
├── 状态检测类
│   ├── HasItem             玩家拥有指定道具
│   ├── HasBoss             场上是否存在 Boss
│   ├── GPOMDead            指定模板 ID 的 GPO 死亡
│   ├── GPOMTypeDead        指定模板类型 ID 的 GPO 死亡
│   ├── TeamMasterAINum     相同 AI 队伍数量
│   └── ModeMaxTeamScore    队伍/个人积分最大值达到阈值
│
├── 空间触发类
│   └── EnterArea           进入指定区域
│
└── 时间等待类
    └── WaitTime            等待指定时间（秒）
```

- **比较类型**（`CompareType`）：每个条件可配置 `Equal`（=）/ `NotEqual`（≠）/ `Greater`（>）/ `Less`（<），灵活控制触发阈值方向。
- **逻辑关系**（`EnterConditionLogicType` / `QuitConditionLogicType`）：多个条件支持 `And`（全满足）/ `Or`（任一满足）/ `Random`（随机选一个）。
- **进度同步**：条件实现 `SyncConditionProgress()` 返回进度数据，通过网络协议同步到客户端用于 UI 展示。

### 4.4 Action（执行动作）

**设计含义**：定义"条件满足后做什么"。Action 是系统对玩法世界的实际操作，执行完毕后自动调用 `QuitAction()` 结束，或持续到退出条件触发。

```
动作类型（ActionType）
│
├── 怪物相关
│   ├── SpawnAI                    在指定点生成怪物
│   ├── SpawnTriggerGPOTeamAI      在触发者位置生成队伍怪物
│   └── SpawnTriggerGPOTeamMasterAI 在触发者位置生成队伍主怪物
│
├── 角色相关
│   └── UpHp                       为主体 GPO 列表中的角色恢复血量
│
└── 模式相关
    ├── ModeAddScoreRateUp         提升得分倍率（积分模式专用）
    └── ModeUnlimitedFire          开启无限弹药（无限开火模式）
```

- **延迟执行**：`WaitTime` 字段支持在进入动作前等待若干秒，同时通知客户端播放等待动画/提示。
- **使用次数限制**：`UseLimitCount` 控制动作可触发次数（`-1` = 无限次）。
- **随机选择**：`IsActionRandom = true` 时，从多个 Action 中随机选一个执行。

### 设计总结图

```
                            EventDirector 事件
                                    │
          ┌─────────────────────────┼──────────────────────┐
          │                         │                      │
      [Time]                   [Subject]              [MainLoop]
   时间窗口约束              目标主体作用域           逻辑关系/提示配置
   AnyTime / 游戏时间         Player / AI 等
   / 回合时间                  World / Team
          │                         │
          │        当 Time 满足时     │
          └──────────► 激活 Subject 扫描 GPO
                                    │
                                    ▼
                            [EnterCondition]  进入条件
                           FireCount / KillAI / ...
                            逻辑: And / Or / Random
                                    │
                              条件满足时
                                    │
                                    ▼
                              [Action] 执行
                           UpHp / SpawnAI / ...
                           支持 WaitTime / 次数限制
                                    │
                             同时监听 ──────────────────────────┐
                                    │                          │
                                    ▼                     [QuitCondition]
                              Action 持续中               退出条件检测
                                    │                    条件满足 → QuitAction
                                    └────────────────────────────┘
```

## 5. SO 配置文件体系

### 5.1 主循环配置（EventDirector_MainLoop）

每个事件的入口 SO，对应 `Assets/Bundle/Configs/EventDirector/Events/<事件名>/MainLoop_<事件名>.asset`。

| 字段 | 类型 | 说明 |
|------|------|------|
| `EventName` | string | 事件显示名称（用于 UI/调试） |
| `IsShowConditionProgress` | bool | 是否在 UI 上展示条件达成进度 |
| `TimeLogicType` | LogicType | 时间段逻辑关系（And/Or/Random） |
| `Times` | EventDirector_TimeData[] | 时间段配置数组（可为空，空=AnyTime） |
| `Subject` | EventDirector_SubjectData | 目标主体配置（必填） |
| `EnterConditionLogicType` | LogicType | 进入条件逻辑关系 |
| `EnterConditions` | EventDirector_ConditionData[] | 进入条件数组（可为空，空=无条件立即触发）|
| `IsActionRandom` | bool | true=随机执行一个动作，false=全部执行 |
| `EnterActionTipType` | ShowTipType | 进入动作时的 UI 提示类型 |
| `QuitActionTipType` | ShowTipType | 退出动作时的 UI 提示类型 |
| `Actions` | EventDirector_ActionData[] | 动作配置数组（必填） |
| `QuitConditionLogicType` | LogicType | 退出条件逻辑关系 |
| `QuitConditions` | EventDirector_ConditionData[] | 退出条件数组（可为空，空=动作自行结束）|

### 5.2 配置类层级结构

```
ScriptableObject

## 6. SO 文件生成方式（Unity Editor）

### 6.1 在 Unity 中右键创建

所有配置 SO 均通过 `[CreateAssetMenu]` 注册到 Unity 的 Assets 菜单。

在 Project 窗口中，对目标目录**右键 → Create → EventDirector / ...** 即可创建：
AI 可直接创建 .asset 文件

| 菜单路径 | 说明 |
|----------|------|
| `EventDirector/MainLoop/MainLoop_Base` | 创建主循环配置（入口） |
| `EventDirector/Time/Time_GameStartTime` | 创建游戏开始时间段条件 |
| `EventDirector/Time/Time_RoundStartTime` | 创建回合开始时间段条件 |
| `EventDirector/Subject/Subject_World` | 创建全局主体 |
| `EventDirector/Subject/Subject_Player` | 创建玩家主体 |
| `EventDirector/Subject/Subject_AI` | 创建 AI 主体 |
| `EventDirector/Subject/Subject_...` | 其他主体类型 |
| `EventDirector/Condition/Condition_FireCount` | 创建开火次数条件 |
| `EventDirector/Condition/Condition_SlideCount` | 创建滑铲次数条件 |
| `EventDirector/Condition/Condition_...` | 其他条件类型 |
| `EventDirector/Action/Action_UpHp` | 创建回血动作 |
| `EventDirector/Action/Action_SpawnAI` | 创建生成怪物动作 |
| `EventDirector/Action/Action_...` | 其他动作类型 |

### 6.2 标准创建流程（新增一个事件）

```
步骤 1：在 Assets/Bundle/Configs/EventDirector/Events/ 下新建事件子目录
         例如：Assets/Bundle/Configs/EventDirector/Events/MyNewEvent/

步骤 2：创建 MainLoop_MyNewEvent.asset
         Right-click → Create → EventDirector/MainLoop/MainLoop_Base

步骤 3：创建 Subject（或复用 Shared/ 中的共享主体）
         如果使用全局 Subject，直接引用 Shared/Subject/Subject_World.asset

步骤 4：按需创建 Time、EnterCondition、Action、QuitCondition 对应的 .asset 文件

步骤 5：将 Time、Subject、Condition、Action .asset 文件拖入 MainLoop 对应字段

步骤 6：在 EventDirectorSet（Template SO 数据表）中注册事件 ID 和 SO 路径
         （见第 14 节完整扩展流程）
```

### 6.3 关键注意事项

- **主体推荐复用 Shared/**：Subject 类型的 SO（如 `Subject_Player.asset`）建议全局共享，多个事件可引用同一个 Subject.asset 文件，节省资源。
- **条件和动作每个事件独立**：Condition/Action 的 SO 字段值（如 `TriggerCount`）通常各事件不同，需各自创建。
- **MainLoop 路径写法**：在代码注册时 `SoConfigPath` 填的是相对于 `EventDirector/Events/` 的路径，如 `"FireUpHp/MainLoop_FireUpHp"`（不含 .asset 后缀）。

## 7. SO 文件资源加载方式（运行时）

### 7.1 加载触发时机

```
SM_Mode.StartMode（游戏模式启动）
  └─► ServerEventDirectorGetData.OnStartMode()
        └─► EventDirectorData.GetEventListByMatchId(ModeData.MatchId)
              └─► EventDirectorData.LoadSOConfig(data, callback)   [异步加载]
                    └─► AssetManager.LoadEventEventDirectorConfig(path, callback)
```

### 7.2 加载实现（EventDirectorData.cs）

```csharp
// 异步加载 SO（带缓存）
public static void LoadSOConfig(EventDirector data, Action<EventDirector_MainLoop> callBack) {
    EventDirector_MainLoop SOConfig;
    // 命中缓存直接返回
    if (LoadedSoConfigs.TryGetValue(data.Id, out SOConfig)) {
        callBack?.Invoke(SOConfig);
        return;
    }
    // 通过 AssetManager 异步加载
    AssetManager.LoadEventEventDirectorConfig(data.SoConfigPath, so => {
        SOConfig = (EventDirector_MainLoop)so;
        LoadedSoConfigs[data.Id] = SOConfig;  // 写入缓存
        callBack?.Invoke(SOConfig);
    });
}

// 从缓存同步获取（战场内使用）
public static EventDirector_MainLoop GetSOConfigToPool(int id) {
    LoadedSoConfigs.TryGetValue(id, out var SOConfig);
    return SOConfig;
}
```

### 7.3 资源路径规范

| 字段 | 说明 | 示例 |
|------|------|------|
| `EventDirector.SoConfigPath` | 相对于事件目录的 SO 路径（不含扩展名）| `"FireUpHp/MainLoop_FireUpHp"` |
| `AssetManager.LoadEventEventDirectorConfig` | 底层加载实现，通常对应 Bundle 或 Resources 加载 | — |

### 7.4 加载完成后的处理

```
所有事件 SO 加载完成
    └─► mySystem.Dispatcher(SE_EventDirector.SetEventList { List = dataList })
          └─► ServerEventDirectorCore 接收 → 为每个事件创建 EventDirectorInstance
                └─► EventDirectorInstance.Init(data, eventIndex)
                      └─► EventDirectorData.GetSOConfigToPool(data.Id)  [同步从缓存取]
```

### 7.5 客户端数据预加载

客户端 `ClientEventDirectorGetData` 组件也会在模式启动时预加载同一批 SO 配置，确保客户端可以通过 `EventDirectorData.GetSOConfigToPool()` 获取 SO 数据（如事件名称、提示类型等，用于 UI 显示）。

## 9. 网络协议层

### 9.1 Proto_EventDirector（ModID = 17）

服务端 → 客户端（TargetRpc，Reliable）

| 协议 | FuncID | 触发时机 | 关键字段 |
|------|--------|----------|----------|
| `TargetRpc_StartEvent` | 4 | 第一个条件开始时，通知客户端事件已启动 | `eventId`（运行时 ID），`eventDataId`（配置 ID）|
| `TargetRpc_StartCondition` | 5 | 某个条件开始监听（GPO 加入时） | `eventId`, `directorEventId`, `conditionType`, `triggerType` |
| `TargetRpc_QuitCondition` | 6 | 某个条件停止监听（GPO 离开时） | `directorEventId` |
| `TargetRpc_ConditionProgress` | 7 | 条件进度更新（如开火次数变化） | `directorEventId`, `Proto`（嵌套进度协议） |
| `TargetRpc_ConditionComplete` | 8 | 条件完成状态变化 | `directorEventId`, `isComplete`, `lastTriggerGpoId` |
| `TargetRpc_WaitAction` | 1 | 动作处于等待延迟阶段 | `eventId`, `directorEventId`, `waitTime`, `actionType`, `TriggerGpoId` |
| `TargetRpc_EnterAction` | 2 | 动作正式开始执行 | `eventId`, `directorEventId`, `actionType`, `TriggerGpoId` |
| `TargetRpc_QuitAction` | 3 | 动作结束 | `directorEventId` |

### 9.2 Proto_EventCondition（ModID = 18）

条件进度专用协议，嵌套在 `TargetRpc_ConditionProgress` 内的 `Proto` 字段传输。

| 协议 | FuncID | 用途 | 字段 |
|------|--------|------|------|
| `TargetRpc_SlideCount` | 1 | 滑铲次数进度 | `limitCount`, `nowCount` |
| `TargetRpc_FireCount` | 2 | 开火次数进度 | `limitCount`, `nowCount` |
| `TargetRpc_ModeMaxTeamScore` | 3 | 积分进度 | `MaxScore`, `NowScore` |

> **注意**：`TargetRpc_ConditionProgress` 在序列化时会先写入嵌套协议的 `FuncID`（1字节），反序列化时通过 `Proto_EventCondition.ReadRpcBuffer(protoFuncId)` 动态构建具体类型。

### 9.3 登录补偿机制

当玩家断线重连/中途加入时，`ServerEventDirectorCore.OnCharacterLoginCallBack` 会：

1. 查找该玩家 GPO 对应的 `playingEventDict` 记录
2. 重新发送 `TargetRpc_StartEvent`
3. 重新发送所有进行中的 `TargetRpc_StartCondition` + `TargetRpc_ConditionProgress` + `TargetRpc_ConditionComplete`
4. 重新发送所有进行中的 `TargetRpc_WaitAction`（等待时间用实时剩余时间 `WaitToTime - Time.realtimeSinceStartup`）

## 10. 服务端实现详解

### 10.1 EventDirectorCore 的 playingEventDict

```csharp
// key = GpoID（玩家角色的 GPO ID）
// value = 该玩家正在参与的事件列表
Dictionary<int, List<PlayingEventInfo>> playingEventDict

// PlayingEventInfo 结构
{
    int EventIndex;                                   // 运行时事件唯一 ID
    EventDirector EventData;                          // 事件配置数据
    Dictionary<int, PlayingEventAction> ActionData;   // 正在执行的动作（key=directorEventId）
    Dictionary<int, PlayingEventCondition> ConditionData; // 正在监听的条件
}
```

这是客户端状态同步的核心数据结构，决定了登录补偿时的数据重建。

### 10.2 EventDirectorInstance 更新机制

```
每帧 Update(deltaTime)
  └─► updateInterval += deltaTime
        └─► 每满 1 秒触发一次轮询
              ├─► CheckTime()         → 更新 IsInTime 状态
              └─► 若 IsInTime == true
                    └─► CheckCondition()
                          ├─► CheckQuitCondition()  → 退出条件先检查
                          └─► CheckEnterCondition() → 进入条件后检查
```

### 10.3 Condition 与 Subject 的绑定关系

- Subject 每识别一个 GPO，就调用 `CheckAddEnterCondition(subjectId, gpo)` 
- 若该 subjectId 的条件列表不存在，则根据 `EnterConditions` SO 创建对应的条件实例列表
- 条件实例通过 `OnSubjectSetGpo(gpo)` 注入 GPO，在 `OnSetGpo` 中注册具体游戏事件监听（如 `SE_Weapon.Event_FireEnd`）

### 10.4 Action 执行后的退出条件

- 进入条件满足并触发 Action 后，系统自动调用 `CreateQuitCondition(subjectId, gpoList)`
- 退出条件使用与进入条件相同的 GPO 列表，独立监听
- 退出条件满足后调用 `QuitAllAction(subjectID)` → 所有正在进行的 Action 调用 `QuitAction()`

// Assets/Scripts/GamePlay/Server/EventDirector/Components/Behaviour/Condition/Condition_EnterArea.cs
public class Condition_EnterArea : EventDirectorCondition {
    private ConditionInitData_EnterArea useInData;
    private bool isEntered = false;

    protected override void OnAwake() {
        useInData = (ConditionInitData_EnterArea)inData;
    }

    protected override void OnSetGpo(IGPO gpo) {
        gpo.Register<SE_Area.Event_EnterArea>(OnEnterAreaCallBack);
    }

    protected override void OnRemoveGpo(IGPO gpo) {
        gpo.Unregister<SE_Area.Event_EnterArea>(OnEnterAreaCallBack);
    }

    private void OnEnterAreaCallBack(ISystemMsg body, SE_Area.Event_EnterArea ent) {
        if (ent.AreaId == useInData.AreaId) {
            isEntered = true;
            SetTriggerGPO(body.GetGPO());
            UpdateConditionProgress();
        }
    }

    public override bool OnCheckCondition() {
        return isEntered;
    }
}
