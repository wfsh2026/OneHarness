## 1. 总则

### 1.1 AI 可以做什么

| 操作类型 | 说明 | 示例 | 需修改的文件 |
|---------|------|------|------------|
| **调参** | 修改现有载具模板属性 | “把坦克移速调快一点” | `GPOM_Tank.cs` 或 `GPOM_Helicopter.cs` 对应数据行 |
| **新增同类载具** | 基于现有载具模板新增一条数据（不新增 GPO 类型） | “新增一辆轻型坦克” | `Template/gpo/GPOM_*.cs` 新增配置行 |
| **扩展驾驶行为** | 在载具或角色侧新增定制组件 | “驾驶中低血自动下车” | 新增 `ServerAI*` / `ClientAI*` 组件并在对应 System 注册 |
| **扩展载具攻击表现** | 在现有协议上扩展动画/炮塔旋转/开火逻辑 | “坦克驾驶时增加炮塔俯仰逻辑” | 载具 Attack/HeadRota 组件 + `Proto_Drive` 相关调用链 |

**唯一限制**：不修改框架层/底层代码（Base/World/Manager/Switch 分发核心类）。

**工程上已支持的通用能力（可直接复用）**：

| 能力 | 工程机制 | 关键类/消息 |
|------|---------|-----------|
| **进出载具关系维护** | 载具侧维护驾驶关系，角色侧感知状态 | `ServerAIDrive` / `ServerGPODrivingVehicle` / `CharacterLocalDrive` |
| **驾驶广播同步** | 服务器广播驾驶载具 ID，本地补充初始位置 | `Proto_Drive.Rpc_DriveGPOID` / `TargetRpc_DriveGPOID` |
| **载具控制权切换** | 驾驶中由驾驶员驱动位置，同步开关自动切换 | `SE_Network.Event_EnabledSyncNetworkTransform` |
| **驾驶输入转发** | 角色输入转发为载具移动/开火指令 | `CE_AI.Event_MoveDir` / `MoveUp` / `MoveDown` / `Proto_Drive.Cmd_DeviceFire` |
| **炮塔旋转同步** | 本地角度上送服务器并广播表现 | `Proto_Drive.Cmd_SyncTankUpperBodyRota` |

### 1.2 系统职责

载具系统负责“可驾驶 GPO”的服务端逻辑、客户端表现和驾驶关系同步。它与以下系统协作：

- **GPO 系统**：载具本质属于 GPO（如 Tank/Helicopter），由 AI System 驱动实体与组件生命周期。
- **3C 系统**：本地角色输入来源于 Character 组件，驾驶后输入设备切换到载具。
- **网络系统**：通过 `Proto_Drive` 完成驾驶关系、动画、炮塔旋转与开火请求同步。
- **能力/武器系统**：载具攻击组件内部可能触发技能或弹道逻辑，驾驶只负责触发入口。
- **模式系统**：载具的重生、刷点、胜负判定由模式系统负责，载具系统仅提供可驾驶单位能力，不直接决定模式结算。

### 1.3 载具与模式系统联动边界

| 场景 | 归属系统 | 说明 |
|------|---------|------|
| 载具单位创建/销毁 | 载具 + GPO | 由 GPO/AI 系统完成实体生命周期 |
| 玩家上车/下车同步 | 载具 | `SE_GPO.Event_DrivingVehicle` + `Proto_Drive` |
| 玩家死亡后是否可重生 | 模式 | 按模式的重生规则（如 `RelifeData`） |
| 载具出生点/刷点规则 | 模式 | 由模式出生点组件管理 |
| 胜负判定（积分/回合/时间）| 模式 | 不在载具系统内实现 |

### 1.4 数据层结构

```
数据层
├── Template/gpo/GPOM_Tank.cs         ← 坦克模板（Hp/Atk/MoveSpeed/RotaSpeed 等）
├── Template/gpo/GPOM_Helicopter.cs   ← 直升机模板（MaxFlyHeight/HeightAdjustSpeed 等）
└── Message/Network/12_Proto_Drive.cs ← 驾驶相关网络协议
```

## 2. 载具模板库

### 2.1 当前可用模板

| 模板ID | 类型 | 数据结构 | 状态 | 特点 |
|--------|------|---------|------|------|
| `V01` | 坦克 | `GPOM_Tank` | 🟢 稳定 | 地面可驾驶，支持炮塔旋转与开火 |
| `V02` | 直升机 | `GPOM_Helicopter` | 🟢 稳定 | 空中可驾驶，支持飞行高度控制 |

### 2.2 模板字段差异

| 模板 | 通用字段 | 特有字段 |
|------|---------|---------|
| `GPOM_Tank` | `Hp` `Atk` `AttackIntervalTime` `AttackRange` `MaxAttackDistance` `MoveSpeed` `RotaSpeed` `AiBehavior` `PetBehavior` `Quality` | `MaxGroundHeight` `TrajectoryPointCount` |
| `GPOM_Helicopter` | `Hp` `Atk` `AttackIntervalTime` `AttackRange` `MaxAttackDistance` `MoveSpeed` `RotaSpeed` `AiBehavior` `PetBehavior` `Quality` | `MaxFlyHeight` `HeightAdjustSpeed` |

### 2.3 使用建议

| 场景 | 推荐模板 |
|------|---------|
| 地面载具对战/炮塔射击 | `V01 Tank` |
| 空中机动/飞行压制 | `V02 Helicopter` |
| 玩家召唤可骑乘单位（已绑定 Master）| 优先复用现有 `PetBehavior` + `ServerAIDrive` |

## 3. 参数规范

> ⚠️ AI 必须将输入数值裁剪到边界范围，超出范围时自动修正并明确告知用户。

### 3.1 通用战斗参数（Tank / Helicopter）

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认参考 | 单位 | 说明 |
|--------|-------|---------|--------|---------|------|------|
| `Hp` | 500 | 2000~12000 | 30000 | Tank=8000 / Helicopter=5000 | 点 | 载具耐久 |
| `Atk` | 50 | 100~1500 | 5000 | Tank=1000 / Helicopter=200 | 点 | 攻击力 |
| `AttackIntervalTime` | 0.02 | 0.1~1.5 | 5.0 | Tank=1.0 / Helicopter=0.025 | 秒 | 攻击间隔 |
| `AttackRange` | 1.0 | 3.0~15.0 | 50.0 | 5.0 | 米 | 近战/判定范围 |
| `MaxAttackDistance` | 5.0 | 20.0~80.0 | 150.0 | Tank=30 / Helicopter=100 | 米 | 最远攻击距离 |
| `MoveSpeed` | 1.0 | 4.0~10.0 | 20.0 | 6.0 | 米/秒 | 位移速度 |
| `RotaSpeed` | 30 | 80~180 | 360 | 100 | 度/秒 | 转向速度 |

### 3.2 坦克专属参数（`GPOM_Tank`）

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认值 | 说明 |
|--------|-------|---------|--------|-------|------|
| `MaxGroundHeight` | 0.5 | 2.0~5.0 | 12.0 | 3.0 | 可通过地形高度阈值 |
| `TrajectoryPointCount` | 2 | 6~20 | 40 | 10 | 轨迹点采样数量 |

### 3.3 直升机专属参数（`GPOM_Helicopter`）

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认值 | 说明 |
|--------|-------|---------|--------|-------|------|
| `MaxFlyHeight` | 3.0 | 8.0~20.0 | 40.0 | 15.0 | 最大飞行高度 |
| `HeightAdjustSpeed` | 0.2 | 0.8~2.0 | 6.0 | 1.0 | 升降速度 |

### 3.4 驾驶同步约束（不可突破）

| 约束项 | 规则 |
|-------|------|
| 载具骨骼 | 载具实体必须存在 `GPOData.PartEnum.Driver` 座位骨骼 |
| 控制权切换 | 进入驾驶时关闭载具自动 NetworkTransform 同步，退出后恢复 |
| 驾驶状态广播 | 必须通过 `Proto_Drive.Rpc_DriveGPOID`（gpoId=0 表示退出） |
| 本地输入切换 | 驾驶建立后必须触发 `CM_InputPlayer.EnabledDevice { Device = driveGPO }` |

## 4. 载具行为预设包

### 4.1 预设包一览

| 预设码 | 名称 | 核心机制 | 关键字段 | 推荐范围 |
|--------|------|---------|---------|---------|
| **V-P01** | 重装坦克 | 高血低速地面压制 | `Hp↑` `MoveSpeed↓` | Hp 10000~18000, MoveSpeed 3~5 |
| **V-P02** | 轻型突击坦克 | 中血高速机动 | `MoveSpeed↑` `RotaSpeed↑` | MoveSpeed 7~10, RotaSpeed 140~220 |
| **V-P03** | 远程炮击坦克 | 远射程低射速 | `MaxAttackDistance↑` `AttackIntervalTime↑` | Distance 60~100, Interval 1.2~2.5 |
| **V-P04** | 低空武装直升机 | 中速低空压制 | `MaxFlyHeight` 中低 + `Atk` 中高 | Height 8~15 |
| **V-P05** | 高机动直升机 | 高速升降机动 | `MoveSpeed↑` `HeightAdjustSpeed↑` | MoveSpeed 8~14, HeightAdjustSpeed 1.5~3 |
| **V-P06** | 驾驶稳定型 | 低抖动、易操控 | `MoveSpeed` 与 `RotaSpeed` 收敛 | MoveSpeed 4~7, RotaSpeed 80~130 |

### 4.2 互斥规则

| 预设 A | 预设 B | 关系 | 说明 |
|--------|--------|------|------|
| V-P01（重装）| V-P02（轻突）| ❌ 互斥 | 速度与生存定位冲突 |
| V-P03（远炮）| V-P06（稳定）| ✅ 可组合 | 远程炮击可叠加稳控手感 |
| V-P04（低空）| V-P05（高机动）| ⚠️ 可组合 | 需限制 `MaxFlyHeight` 防止手感飘移 |

## 6. 意图理解规范

### 6.1 必须追问的场景

| 场景 | AI 必须追问 |
|------|-----------|
| 仅说“做个载具” | “要地面坦克还是空中直升机？” |
| 同时要求“超高血 + 超高机动” | “更偏生存还是机动？二者需权衡。” |
| 只说“要能驾驶”未说退出逻辑 | “退出驾驶是手动触发，还是血量阈值/时间自动退出？” |
| 提及“新协议” | “是否必须新增网络消息？可否优先复用 `Proto_Drive` 现有消息？” |

### 6.2 禁止规则

| 场景 | ❌ 禁止行为 | ✅ 正确做法 |
|------|-----------|----------|
| 需求不清 | 直接默认 Tank | 先追问载具类型 |
| 结构扩展 | 发明新的底层 Drive 框架 | 复用 `ServerAIDrive` 与 `ClientAIDrive` |
| 同步机制 | 跳过 `Rpc_DriveGPOID` 直接改本地状态 | 统一走协议广播 |
| 骨骼依赖 | 未检查 `Driver` 座位骨骼 | 明确前置条件并给出报错提示 |

## 7. AI 处理流程

### Step 1：识别请求类型

- 调参（仅改 GPOM 数据）
- 新增同类载具（新增数据行）
- 行为扩展（新增/注册组件）

### Step 2：选择模板与预设

按“地面/空中 + 生存/机动/火力”组合选择 `V01/V02` 与 `V-Pxx` 预设。

### Step 3：边界裁剪

对第 3 章的所有参数做裁剪并在输出中列出“原值 → 裁剪值”。

### Step 4：驾驶链路校验

确认以下链路完整：

1. `SE_GPO.Event_DrivingVehicle`
2. `Proto_Drive.Rpc_DriveGPOID / TargetRpc_DriveGPOID`
3. `CM_InputPlayer.EnabledDevice`
4. `SE_Network.Event_EnabledSyncNetworkTransform`

### Step 5：输出变更摘要

输出“改了什么文件、参数如何变化、驾驶链路是否变更、是否有待确认项”。

## 8. 代码模板

### 8.1 新增载具系统骨架（服务端）

```csharp
public class ServerAITankCustomSystem : S_AI_Base {
    private GPOM_Tank useMData;

    protected override void OnAwake() {
        useMData = (GPOM_Tank)MData;
        AddComponents();
    }

    protected override void AddComponents() {
        base.AddComponents();
        AddComponent<ServerAIBehaviour>(new ServerAIBehaviour.InitData {
            AIBehaviour = MasterGPO != null ? useMData.PetBehavior : useMData.AiBehavior,
        });
        AddComponent<ServerAIAttribute>(new ServerGPOAttribute.InitData {
            ATK = useMData.Atk,
            AttackRange = useMData.AttackRange,
            MaxHp = useMData.Hp,
            MoveSpeed = useMData.MoveSpeed,
        });
        AddComponent<ServerAIDrive>(); // 必须
    }
}
```

### 8.2 驾驶事件标准调用（服务端）

```csharp
masterGPO.Dispatcher(new SE_GPO.Event_DrivingVehicle {
    IsDriving = isDriver,
    DriveGPO = isDriver ? iGPO : null,
});
mySystem.Dispatcher(new SE_Network.Event_EnabledSyncNetworkTransform {
    IsTrue = !(isDriver && masterGPO.GetGPOType() == GPOData.GPOType.Role)
});
```

## 9. 通用组件 vs 定制组件

| 需求 | 优先方案 | 何时定制 |
|------|---------|---------|
| 普通进出载具 | `ServerAIDrive` + `ClientAIDrive` | 需要特殊上/下车条件时 |
| 本地驾驶输入 | `CharacterLocalDrive` | 输入映射发生重大变化时 |
| 载具位置跟随 | `ServerGPODrivingVehicle` | 非标准座位绑定或多座位时 |
| 驾驶协议同步 | `Proto_Drive` 现有消息 | 现有字段确实无法表达新需求时 |

## 10. 开发规范

1. 不修改 Base/Manager/World/Switch 核心分发代码。
2. 驾驶相关能力优先复用 `ServerAIDrive`/`ClientAIDrive`，不要重复造轮子。
3. 新增载具必须明确服务端与客户端 System 的组件注册对应关系。
4. 所有网络消息保持“先注册、再调用、再回调处理”的完整链路。
5. 文档中引用的路径和类名必须与工程真实文件一致。
