## 1. 总则

### 1.1 AI 可以做什么

| 操作类型 | 说明 | 示例 | 需修改的文件 |
|---------|------|------|------------|
| **调参（现有 AB/AE）** | 修改 CSV 数据中的参数值 | "把子弹伤害改成 200" | 对应 CSV 文件（如 `AbilityM_Bullet.csv`）|
| **基于现有模板组合新技能** | 将已有 AB/AE 类型组合成新技能行为，不新建系统类 | "创建一个低血量触发的范围爆炸技能" | 新增 CSV 行数据 + GPO 技能配置调用 |
| **新增 AB 类型（System）** | 新建 MData、Select、System、CSV，并更新 AutoGenerated 和 Switch 文件 | "新增一个扇形喷火技能" | 见第11、12章 |
| **新增 AE 类型（System）** | 新建 MData、Select、System、CSV，并更新 AutoGenerated 和 Switch 文件 | "新增一个攻击速度减益效果" | 见第11、12章 |
| **组件内嵌入常量参数** | 某 M_字段 CSV 无对应列时，直接在 System 里用常量 | — | 在 System 类内 `private const float xxx = N;` |

**核心限制：** 不修改架构底层文件（Base 类、Manager 核心类）。AutoGenerated 文件和 Switch 文件 AI 可追加内容，但不修改已有内容。完整规则见第12章。

### 1.2 Ability 系统已支持的通用能力

| 能力 | 实现机制 | 相关类 |
|------|---------|--------|
| **持续伤害（DoT）** | `AE_HurtGPOByTime` | `SAE_HurtGPOByTimeSystem` |
| **范围爆炸** | `AB_Explosive` + `AbilityIn_Explosive` | `SAB_ExplosiveSystem` |
| **追踪导弹** | `AB_TrackingMissle` | `SAB_TrackingMissleSystem` |
| **低血量触发额外技能** | `AB_PlayAbilitiesAfterLowHp` | `SAB_PlayAbilitiesAfterLowHpSystem` |
| **杀敌触发额外技能** | `AB_PlayAbilitiesAfterKillRole` | `SAB_PlayAbilitiesAfterKillRoleSystem` |
| **召唤 AI** | `AB_SummonAIByHeroAttr` | `SAB_SummonAIByHeroAttrSystem` |
| **回血（持续）** | `AE_RecoverGPOHpByTime` | `SAE_RecoverGPOHpByTimeSystem` |
| **移动加速/减速** | `AE_MoveSpeedRate` / `AE_MoveSpeedRateByTime` | 对应 SAE 类 |
| **增加最大 HP** | `AE_MaxHpRate` | `SAE_MaxHpRateSystem` |
| **武器攻击加成** | `AE_WeaponATKAddRate` | `SAE_WeaponATKAddRateSystem` |
| **禁用技能** | `AE_SkillDisabled` | `SAE_SkillDisabledSystem` |

## 2. 架构概览：AB 与 AE 的区别

```
                    ┌─────────────────────────────────────┐
                    │         ServerAbilityManager         │
                    │   (Manager - 仅管理System创建/销毁)   │
                    └──────────────┬──────────────────────┘
                                   │ SM_Ability.PlayAbility
                    ┌──────────────┴──────────────────────┐
          ┌─────────▼──────────┐           ┌──────────────▼────────────┐
          │  SwitchAB 分发器   │           │    SwitchAE 分发器         │
          │（按 TypeID 路由）   │           │   （按 TypeID 路由）        │
          └─────────┬──────────┘           └──────────────┬────────────┘
                    │                                      │
          ┌─────────▼──────────┐           ┌──────────────▼────────────┐
          │   SAB_XXXSystem    │           │     SAE_XXXSystem          │
          │  (继承 S_Ability_Base)│         │   (继承 S_Ability_Base)    │
          │  一次性行为（弹道/  │           │   持续效果（Buff/Debuff）   │
          │   爆炸/技能动画等） │           │   绑定 TargetGPO 生效       │
          └────────────────────┘           └───────────────────────────┘
```

| 维度 | AB（Ability） | AE（AbilityEffect） |
|------|--------------|-------------------|
| **全称** | Ability（主动行为） | AbilityEffect（持续效果） |
| **典型用途** | 子弹、爆炸、技能动画、召唤、位移 | Buff/Debuff：加速、减速、DoT、加攻、回血 |
| **ConfigId 范围** | 10000 ~ 19999（`AbilityConfig.StartIndex`） | 20000+（`AbilityEffectConfig.StartIndex`） |
| **TypeID 前缀** | `AB_XXX`（新式）/ `SAB_XXX`（旧式） | `AE_XXX` |
| **数据基类** | `AbilityMData` | `AbilityEffectMData`（继承自 `AbilityMData`） |
| **生命周期** | 一次性触发，用 `TimeReduce` 倒计时结束 | 持续生效，可被相同 ConfigId 重置(`ResetEffect`) |
| **绑定目标** | `FireGPO`（施放者）为主 | `FireGPO`（施放者）+ `TargetGPO`（受体）两者都有 |
| **触发消息** | `SM_Ability.PlayAbility` | `SM_Ability.PlayAbilityEffect` |
| **System 命名** | `SAB_XXXSystem` | `SAE_XXXSystem` |

## 4. AE 模板库（持续效果/Buff）

> AE ConfigId 从 20000 开始。每个 AE 挂载在 `TargetGPO` 上，生命周期结束后自动卸载。
> **同一 GPO 上相同 ConfigId+RowId 的 AE 不会叠加，会重置（刷新持续时间）。**

## 5. 技能行为预设包

> 玩家不需要了解 AB/AE 底层实现，只需描述"想要什么效果"。AI 根据以下预设包匹配并组合。

### 5.1 预设包总览

| 预设ID | 效果名称 | 玩家描述关键词 | AB/AE 组合 |
|--------|---------|-------------|-----------|
| `P01` | 燃烧弹 | 火焰子弹、点火、烧、燃烧攻击 | `AB_Bullet`（命中）→ `AE_HurtGPOByTime`（DoT，DamageType=Burn）|
| `P02` | 冰冻/减速 | 冰冻、冰弹、减速、结冰、变慢 | `AB_Bullet` 或 `AB_Explosive`（命中）→ `AE_MoveSpeedRate`（SpeedRate < 1.0）|
| `P03` | 毒素/中毒 | 毒、中毒、腐蚀、缓慢死亡 | `AB_Bullet`（命中）→ `AE_HurtGPOByTime`（DamageType=Normal, 持续时间长）|
| `P04` | 范围爆炸 | 爆炸、范围伤害、AOE、炸开 | `AB_Explosive`（In_Range 决定半径，In_Hurt 决定伤害）|
| `P05` | 持续回血 | 回血、再生、恢复、持续治疗 | `AE_RecoverGPOHpByTime`（M_RecoverRatio 决定比例）|
| `P06` | 召唤 AI | 召唤小弟、放出单位、生成帮手 | `AB_SummonAIByHeroAttr`（M_SummonAISign 指定 GPO Sign）|
| `P07` | 击杀回 CD | 杀敌回技能、击杀减冷却 | `AB_KillRecoverSkillCD`（监听击杀事件自动触发）|
| `P08` | 低血触发技能 | 快死了触发、血量低激活 | `AB_PlayAbilitiesAfterLowHp`（M_LowHpRatio 设定阈值）|
| `P09` | 位移冲锋 | 冲过去、瞬移、冲刺 | `AB_Displacement` / `AB_Charge`（根据是否需要持续运动区分）|
| `P10` | 武器加攻 | 武器更强、增加伤害、攻击加成 | `AE_WeaponATKAddRate`（M_AddRate > 0）|
| `P11` | 增加最大 HP | 血量上限提升、更多血、HP 成长 | `AE_MaxHpRate`（M_MaxHpRate > 1.0）|
| `P12` | 禁用技能（沉默）| 沉默、不能用技能、禁技能 | `AE_SkillDisabled` |
| `P13` | 追踪导弹 | 追踪导弹、锁定攻击、自动追人 | `AB_TrackingMissle`（M_TrackSpeed 决定追踪速度）|
| `P14` | 多重爆炸 | 重复爆炸、多次炸、轰炸覆盖 | `AB_RepeatBomb`（M_BombCount + M_BombInterval）|
| `P15` | 技能 CD 加速 | 快速冷却、CD 缩减、技能更快 | `AE_SkillCDRecoverRate`（`M_RecoverRate` / `M_DamageRecoverRate` 提升）|

### 5.2 复合预设包（常见技能组合）

| 组合名 | 拆解 | 描述关键词 |
|--------|------|-----------|
| **燃烧炸弹** | `P04` 爆炸 + `P01` 燃烧 | 爆炸后对范围内敌人施加持续燃烧 |
| **冰冻+爆炸** | `P02` 冰冻 + `P04` 爆炸 | 先减速再爆炸，或爆炸本身造成冰冻 |
| **追踪燃烧弹** | `P13` 追踪 + `P01` 燃烧 | 自动追踪+命中后燃烧 |
| **低血反击** | `P08` 低血触发 + `P04` 爆炸 | 血量低时自动释放范围爆炸 |
| **击杀回血** | `P07` 击杀 + `P05` 回血 | 击杀后获得回血效果 |

## 6. 数据层结构

### 6.1 两层数据模型

每个 Ability 有两种数据，AI 需要理解各自的来源：

| 数据层 | 接口 | 来源 | 包含内容 | AI 如何使用 |
|--------|------|------|---------|------------|
| **MData**（模板数据） | `IAbilityMData` | CSV 文件（异步加载） | 行为参数（伤害值、速度、范围、生命周期等）| 通过 `CreateForID(byte)` / `CreateForSign(string)` 创建并调用 `Select()` 加载 |
| **InData**（输入数据） | `IAbilityInData` | 运行时调用方传入 | 动态数据（起点/终点位置、武器 ID 等）| 由施放者填入后随 `SM_Ability.PlayAbility` 一起传入 |

### 6.2 MData 标识符体系

每个 MData 类有三种查询主键：

```csharp
// 方式1：按 ID 创建（对应 CSV 的 ID 列，最优先）
var mData = new AbilityM_HurtGPOByTime { K_ID = AbilityM_HurtGPOByTime.ID_Burn };
mData.Select(() => { /* 数据加载完成 */ });

// 方式2：按 Sign 创建（对应 CSV 的 RowSign 列）
var mData = AbilityM_MoveSpeedRate.CreateForSign("Slow_30");
mData.Select(() => { /* 数据加载完成 */ });

// 方式3：工厂方法按 ID 创建
var mData = AbilityM_Bullet.CreateForID(AbilityM_Bullet.ID_BulletRPG);
```

**字段命名约定：**

| 前缀 | 含义 | 示例 |
|------|------|------|
| `M_` | 模板数据字段（来自 CSV） | `M_Power`, `M_LifeTime`, `M_EffectSign` |
| `In_` | 输入数据字段（运行时传入） | `In_StartPoint`, `In_Speed`, `In_WeaponItemId` |
| `K_` | 查询主键字段 | `K_ID`, `K_RowSign`, `K_Sign` |
| `D_` | 派生计算字段（非 CSV，由代码计算） | `D_DamageType`, `D_FinalBombRadius` |

### 6.3 CSV 数据文件位置

- AB 类型的 CSV：`Assets/Bundle/Configs/Ability/AB/AbilityM_XXX.csv`
- AE 类型的 CSV：`Assets/Bundle/Configs/Ability/AE/AbilityM_XXX.csv`
- CSV 字段对应 MData 类中的 `M_*` 字段（字段名需完全匹配）

## 7. 触发方式与接入点

### 7.1 触发 AB 的消息

```csharp
// 触发一个 AB（一次性行为）
MsgRegister.Dispatcher(new SM_Ability.PlayAbility {
    FireGPO  = igpo,              // 施放者 GPO
    MData    = mData,             // AbilityMData（已 Select 或将异步加载）
    InData   = inData,            // 可选：运行时参数
    OR_CallBack = system => { }   // 可选：获得创建出的 System 引用
});
```

### 7.2 触发 AE 的消息

```csharp
// 触发一个 AE（持续效果）
MsgRegister.Dispatcher(new SM_Ability.PlayAbilityEffect {
    FireGPO   = attackerGpo,   // 施放者（施害方）
    TargetGPO = targetGpo,     // 受体（被施加效果的 GPO）
    MData     = effectMData,   // AbilityEffectMData
    InData    = inData,        // 可选：AbilityEffectInData
});
// ⚠️ 注意：同一 TargetGPO 上相同 ConfigId+RowId 的 AE 不会重复创建，而是调用 ResetEffect() 刷新
```

### 7.3 从 GPO Component 中触发（最常见场景）

GPO Component 通过 `SE_Skill.Event_CastAbility` 事件触发，由 `ServerGPOSkillAbilityCaster` 统一分发：

```csharp
// 在 GPO 的 Custom Component 中触发技能
Dispatcher(new SE_Skill.Event_CastAbility {
    ConfigId  = AbilityEffectConfig.MoveSpeedRate,   // 填 AE 的 ConfigId
    RowId     = AbilityM_MoveSpeedRate.ID_XXX,       // CSV 行 ID
    SkillIndex = 0,                                   // 技能槽位
});
```

框架会自动判断：
- 若 ConfigId < 20000 → 走 `SM_Ability.PlayAbility`（AB）
- 若 ConfigId ≥ 20000 → 走 `SM_Ability.PlayAbilityEffect`（AE）

### 7.4 常见触发场景汇总

| 触发时机 | 触发方式 | 典型 AB/AE |
|---------|---------|-----------|
| 玩家主动技能按键 | `SE_Skill.Event_CastAbility` → `ServerGPOSkillAbilityCaster` | `AB_SummonAIByHeroAttr`, `AB_RepeatRangeAttack` |
| 子弹命中 | `ServerAbilityHurtGPO` 组件内部发送 | `AE_HurtGPOByTime`（燃烧弹命中后挂DoT）|
| 被动触发（低血量） | `AB_PlayAbilitiesAfterLowHp` 在 HP 检测时发送 | `AE_MoveSpeedRate`（低血加速逃跑）|
| 击杀奖励 | `AB_PlayAbilitiesAfterKillRole` 监听击杀事件 | `AB_KillRecoverSkillCD` |
| GPO 出生时挂初始 Buff | `ServerCharacterInitAbility` 组件在 Awake 时 | `AE_MaxHpRate`, `AE_WeaponATKAddRate` |

## 8. AI 意图识别增强规则

### 8.1 量词与程度词的数值映射

玩家描述效果强度时常用模糊词，AI 应将其映射到具体倍率（相对该 AB/AE 字段的推荐默认值）：

| 程度词 | 数值倍率 | 示例（AE 移速倍率默认 0.7） |
|--------|---------|--------------------------|
| 一点点 / 稍微 | ×1.3（加成）/ ×0.85（减益） | 减速 → SpeedRate ≈ 0.85 |
| 比较 / 有点 | ×1.5 / ×0.7 | 减速 → SpeedRate ≈ 0.7 |
| 很 / 挺 | ×2.0 / ×0.5 | 减速 → SpeedRate ≈ 0.5 |
| 非常 / 超级 | ×3.0 / ×0.3 | 减速 → SpeedRate ≈ 0.3 |
| 完全 / 彻底 | 取极限值（裁剪到边界）| 完全停止 → SpeedRate = 0.1（不设为0）|
| 持续很长时间 | LifeTime × 3.0 | 燃烧默认 3 秒 → 9 秒 |
| 快速 / 短暂 | LifeTime × 0.3 | 燃烧默认 3 秒 → 1 秒 |

> 程度词叠加取最高一档（"非常非常强" = ×3.0，不累乘）

### 8.2 效果描述词 → AB/AE 类型映射

| 玩家效果描述 | 第一推荐 | 第二推荐 | 歧义处理规则 |
|------------|---------|---------|------------|
| 燃烧/着火/火焰伤害 | `AE_HurtGPOByTime`（DamageType=Burn）| — | — |
| 中毒/腐蚀/持续掉血 | `AE_HurtGPOByTime`（DamageType=Normal）| `AE_SkillHurtGPOByTime` | 技能释放后挂上用 SkillHurt |
| 冰冻 | `AE_MoveSpeedRate`（SpeedRate=0.1）| `AE_SkillDisabled` | **必须追问**：是"完全无法移动"还是"大幅减速"？完全停止→SkillDisabled；减速→MoveSpeedRate |

| 沉默/禁用技能 | `AE_SkillDisabled` | — | — |
| 增加武器伤害 | `AE_WeaponATKAddRate` | `AE_HurtValueRate` | 全武器加成→ATKAddRate；特定伤害类型加成→HurtValueRate |
| 吸血/命中回血 | `AE_WeaponLifeStealRate` | — | — |
| 射速加快/连射更快 | `AE_ShootIntervalRate`（Rate<1.0）| — | ShootInterval 变小 = 射得更快 |
| 换弹更快 | `AE_ReloadRate`（Rate<1.0）| — | — |
| 技能 CD 缩短 | `AE_SkillCDRecoverRate` | `AB_KillRecoverSkillCD` | 被动加速→CDRecoverRate；击杀触发→KillRecoverCD |
| 爆炸/范围伤害 | `AB_Explosive` | `AB_RangeFlash` | 有命中判定用Explosive；纯特效范围用RangeFlash |
| 子弹/射击 | `AB_Bullet` | — | 有弹道轨迹用Bullet；落点AOE用Explosive |
| 追踪/锁定 | `AB_TrackingMissle` | — | — |

| 击杀触发 | `AB_PlayAbilitiesAfterKillRole` | — | — |

### 8.3 技术安全底线（不可绕过）

| 规则 | 原因 |
|------|------|
| System 的 `OnAwake` 注册事件，`OnClear` 必须注销 | 防止内存泄漏 |
| 不得在 `Update` 中使用 `new` / `GetComponent` / LINQ | 性能规范 |
| 所有新 System 必须有 `namespace Sofunny.BiuBiuBiu2.ServerGamePlay` | 命名规范 |
| `M_DeltaTime`（DoT 间隔）不得小于 0.2 秒 | 性能规范，过短导致大量 Tick |
| AE 的 LifeTime = -1 需程序审核 | 永久 AE 必须确保有明确的移除逻辑 |
| 不得修改 Base 类 / Manager 类 / Switch 分发类 | 架构边界（详见第12章）|

| 歧义描述 | AI 必须问的问题 |

**禁止的处理方式：**
- ❌ 遇到歧义直接选一个"感觉合理"的实现
- ❌ 生成代码后在注释里说"假设是 X"
- ✅ 一次性列出所有疑问，等待用户回答

**第三步：新建 Select 分部类（完整模板，可直接使用）**
```csharp
// 文件：Assets/Scripts/Data/Configs/Ability/AB/TemplateM/Select/AbilityM_XXX_Select.cs
using System;
using System.Collections.Generic;
using Sofunny.BiuBiuBiu2.Asset;
using UnityEngine;

namespace Sofunny.BiuBiuBiu2.Data {
    public partial class AbilityM_XXX {
        public const string AbilityTypeID = AbilityConfig.AB_XXX;
        public const ushort ConfigId      = AbilityConfig.XXX;

        private static Dictionary<byte, AbilityM_XXX>   idCache           = new();
        private static Dictionary<string, AbilityM_XXX> signCache         = new();
        private static List<AbilityM_XXX>               loadingCallbacks  = new();
        private static bool IsCsvLoaded = false;
        private static bool isLoading   = false;
        private Action callBack;
        private bool IsSetCsvData = false;

        public override string GetTypeID()   => AbilityTypeID;
        public override ushort GetConfigId() => ConfigId;
        public override byte   GetRowID()    => K_ID;
        public override string GetRowSign()  => K_RowSign;

        public const byte ID_Default = 1;

        [NonSerialized] public byte   K_ID      = 0;
        [NonSerialized] public string K_RowSign = "";
        [NonSerialized] public string K_Sign;

        public static void ClearCache() {
            idCache.Clear(); signCache.Clear(); loadingCallbacks.Clear();
            IsCsvLoaded = false; isLoading = false;
        }

        public override void Select(Action callBack) {
            if (IsSetCsvData) { callBack?.Invoke(); return; }
            this.callBack = callBack;
            if (IsCsvLoaded) { DoSelectFromCache(); return; }
            loadingCallbacks.Add(this);
            if (isLoading) return;
            LoadCsvAndCacheAll(OnLoadComplete);
        }

        private static void OnLoadComplete() {
            foreach (var m in loadingCallbacks) m.DoSelectFromCache();
            loadingCallbacks.Clear(); isLoading = false;
        }

        private void DoSelectFromCache() {
            AbilityM_XXX target = null;
            if (K_ID != 0)            idCache.TryGetValue(K_ID, out target);
            else if (K_RowSign != "") signCache.TryGetValue(K_RowSign, out target);
            else                      target = FindByMultiKeys(K_Sign);
            if (target != null) { CopyInstanceData(target); IsSetCsvData = true; }
            else Debug.LogError($"AbilityM_XXX 未找到：K_Sign={K_Sign} K_ID={K_ID} K_RowSign={K_RowSign}");
            callBack?.Invoke(); callBack = null;
        }

        private static AbilityM_XXX FindByMultiKeys(string k_Sign) {
            foreach (var inst in idCache.Values) if (inst.K_Sign == k_Sign) return inst;
            return null;
        }

        private static void LoadCsvAndCacheAll(Action onLoadComplete) {
            isLoading = true;
            AssetCsvManager.GetAbilityABAllCsvRows("AbilityM_XXX", allRows => {
                if (allRows == null || allRows.Count == 0) {
                    Debug.LogError("全量加载失败：AbilityM_XXX"); onLoadComplete?.Invoke(); return;
                }
                idCache.Clear(); signCache.Clear();
                foreach (var row in allRows) {
                    if (!byte.TryParse(AssetCsvManager.GetCsvRowValue(row, "ID"), out byte rowId)) continue;
                    if (idCache.ContainsKey(rowId)) continue;
                    var rowSign  = AssetCsvManager.GetCsvRowValue(row, "RowSign");
                    var instance = new AbilityM_XXX();
                    instance.K_ID      = rowId;
                    instance.K_RowSign = rowSign;
                    instance.M_Sign       = AssetCsvManager.ParseValue<string>(AssetCsvManager.GetCsvRowValue(row, "K_M_Sign"));
                    instance.M_EffectSign = AssetCsvManager.ParseValue<string>(AssetCsvManager.GetCsvRowValue(row, "M_EffectSign"));
                    instance.M_LifeTime   = AssetCsvManager.ParseValue<float> (AssetCsvManager.GetCsvRowValue(row, "M_LifeTime"));
                    instance.M_Power      = AssetCsvManager.ParseValue<int>   (AssetCsvManager.GetCsvRowValue(row, "M_Power"));
                    instance.K_Sign       = instance.M_Sign;
                    instance.IsSetCsvData = true;
                    idCache[rowId] = instance; signCache[rowSign] = instance;
                }
                IsCsvLoaded = true; onLoadComplete?.Invoke();
            });
        }

        private void CopyInstanceData(AbilityM_XXX src) {
            K_Sign = src.K_Sign;
            M_Sign = src.M_Sign; M_EffectSign = src.M_EffectSign;
            M_LifeTime = src.M_LifeTime; M_Power = src.M_Power;
        }

        public static AbilityM_XXX CreateForID(byte id) {
            if (IsCsvLoaded && idCache.TryGetValue(id, out var c)) return c;
            var d = CreateSO(); d.K_ID = id; return d;
        }

        public static AbilityM_XXX CreateForSign(string sign) {
            if (IsCsvLoaded && signCache.TryGetValue(sign, out var c)) return c;
            var d = CreateSO(); d.K_RowSign = sign; return d;
        }

        private static AbilityM_XXX CreateSO() {
#if UNITY_EDITOR
            var url = $"{AssetURL.AbilitySO}SO/AB/AbilityM_XXX.asset";
            var so  = UnityEditor.AssetDatabase.LoadAssetAtPath<AbilityM_XXX>(url);
            if (so != null && so.IsEditorUseSO) { so.IsSetCsvData = true; return so; }
#endif
            return new AbilityM_XXX();
        }
    }
}
```

## 12. 文件创建与修改规则

### 12.1 AI 负责管理的文件全列表

新增一个 AB/AE 类型，AI 需要创建或修改以下所有文件：

| 文件路径 | 操作 | 说明 |
|---------|------|------|
| `Data/Configs/Ability/AB/TemplateM/AbilityM_XXX.cs` | **新建** | MData 数据类，定义 M_ 字段 |
| `Data/Configs/Ability/AB/TemplateM/Select/AbilityM_XXX_Select.cs` | **新建** | Select 分部类，包含完整 CSV 异步加载逻辑和 AbilityTypeID 常量 |
| `GamePlay/Server/Ability/System/SAB/SAB_XXXSystem.cs` | **新建** | 服务端 System 实现类 |
| `Bundle/Configs/Ability/AB/AbilityM_XXX.csv` | **新建** | CSV 数据文件（写入表头 + 初始数据行） |
| `Data/Configs/Ability/AbilityConfig_AutoGenerated.cs` | **追加** | 追加 ConfigId 常量 + TypeID 字符串常量 + 两处 switch case |
| `GamePlay/Server/Ability/ServerAbilityManager_SwitchAB.cs` | **追加** | 追加一个 case 分发新 System |

AE 类型对应的差异：MData 继承 `AbilityEffectMData`，System 为 `SAE_XXXSystem`，修改 `AbilityEffectConfig_AutoGenerated.cs` 和 `ServerAbilityManager_SwitchAE.cs`。

### 12.2 追加 AbilityConfig_AutoGenerated.cs 的规则

文件由三个区块组成，新增时各追加一行/一组：

**区块1：ConfigId 常量**（按字母序插入，或追加到末尾）
```csharp
public const ushort XXX = 10042;  // 当前最大值+1，值为连续整数
```

**区块2：TypeID 字符串常量**
```csharp
public const string AB_XXX = "AB_XXX";
```

**区块3：两个 switch 方法各追加一个 case**
```csharp
// GetAbilityConfig(string configSign, string rowSign) 中：
case AB_XXX:
    mData = AbilityM_XXX.CreateForSign(rowSign);
    break;

// GetAbilityConfig(ushort configId, byte rowId) 中：
case XXX:
    mData = AbilityM_XXX.CreateForID(rowId);
    break;
```

> ⚠️ ConfigId 值必须唯一。新增前查看文件中当前最大值，+1 赋值。当前 AB 最大 = 10041，AE 最大参考 `AbilityEffectConfig_AutoGenerated.cs`。

### 12.3 追加 SwitchAB/SwitchAE 的规则

在 switch 块最后一个 `case ... break;` 之后、`}` 之前插入：
```csharp
case AbilityM_XXX.AbilityTypeID:
    system = AddSystem<SAB_XXXSystem>(callBack);
    break;
```

> ⚠️ case 的 key 是 `AbilityM_XXX.AbilityTypeID`（Select 分部类中定义的字符串常量），不是 ConfigId。
