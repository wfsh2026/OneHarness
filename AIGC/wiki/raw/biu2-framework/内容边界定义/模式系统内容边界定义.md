## 1. 总则

### 1.1 AI 可以做什么

| 操作类型 | 说明 | 示例 | 需修改的文件 |
|---------|------|------|------------|
| **调参** | 修改现有模式的参数数值 | "把 5V5 的每回合时间改成 3 分钟" | `ModeData.cs` 对应 switch 行 |
| **创建通用模式** | 基于现有通用组件组合新模式，不需要新建专属 System | "创建一个团队积分战模式" | 新增 `ModeEnum` 枚举 + `ModeData.Init()` 配置 + `ServerModeSystem.InitModeComponent()` switch 分支 |
| **创建特化模式** | 需要全新玩法逻辑的模式（占点/夺旗等） | "创建一个移动占点模式" | 新建 `ServerXxxMode.cs` + `ClientXxxMode.cs` + 独立消息文件 + 注册 |
| **参数微调** | 玩家觉得模式"太快结束"或"太慢"时的调整 | "把夺金模式的回合时间调长一倍" | 仅 `ModeData.cs` 对应字段 |

**唯一限制**：不修改框架层/底层代码（`ServerModeMainLoop`、`ClientModeMainLoop`、`ServerModeCharacter`、`ServerModeScore`、`ServerModeSystem` 的 `AddComponents()` 方法等底层组件）。此规则已在`core-rules.md`明确，本文档不重复约束。

**工程上已支持的通用能力（可在新模式中直接复用）**：

| 能力 | 工程机制 | 关键组件/字段 |
|------|---------|-------------|
| **多回合管理** | `ServerModeMainLoop` 回合状态机 | `ModeData.Data.MaxRoundCount` |
| **倒计时控制** | `ServerModeMainLoop` 定时器 | `ModeData.Data.RoundTime` |
| **积分获取** | `ServerModeScore` | `SM_Mode.AddScore / SM_Mode.SetScore` |
| **AI 生成队列** | `ServerModeCreateAI` | `SE_Mode.Event_OnSetCreateAIList` |
| **物品掉落** | `ServerModeDropItem` | `SM_Mode.Event_DropItem` |
| **重生机制** | `RelifeData` 结构体（各模式自实现）| `SE_GPO.Event_ReLife` |
| **无敌保护** | `SE_GPO.Event_BecomeAttackProtectTime` | `ProtectTime = 3f`（秒）|
| **自动拾取** | `ServerModeAutoPickUpItem` | 与夺金模式配合 |
| **出生点管理（队伍）** | `ServerTeamModeSpawnPoint` | 自动监听 spawn 事件 |
| **出生点管理（个人）** | `ServerPersonalModeSpawnPoint` | `sqrLimitSpawnRadius` |
| **服务器时钟同步** | `ServerModeClockSync` | 自动广播 Unix 时间戳 |

### 1.2 模式系统职责

模式系统负责管理游戏的回合生命周期、胜负判定、玩家数据同步。它与以下系统协作：

- **GPO 系统**：模式内的 AI 角色、Boss、道具均由 GPO 系统驱动；角色死亡/复活事件来自 `SE_GPO.Event_SetIsDead`
- **全局事件系统（EventDirector）**：胜负条件的复杂触发逻辑通过 EventDirector 编排
- **Ability 系统**：重生无敌保护（`SM_Ability.PlayAbilityEffect`）、死亡触发特殊效果（`ServerModeDeadPlayAbilities`）
- **枪械系统**：武器分配由模式驱动（`SE_GPO.Event_ModeEquipWeapon`）

### 1.3 数据层结构

```
数据层
├── Template/data/Mode.cs           ← 模式总表（Id, Name, Sign, Desc 等展示信息）
├── Template/data/ModeGameplay.cs   ← 模式玩法参数（MaxRoleNum, RoundTime, WinScore 等）
├── ModeData.cs                     ← 运行时模式全局状态（PlayMode, PlayGameState, PlayData）
└── ModeSet.cs / ModeGameplaySet.cs ← 常量 Id 映射与数据查询
```

> ⚠️ **重要**：`ModeData` 是全局静态类，`PlayMode`、`PlayGameState` 等属性在整个运行时共享，客户端和服务端都依赖它。修改 `ModeData` 必须格外谨慎。

### 2.2 模式分类体系

#### 🔵 A 类：通用对战模式（复用现有专属组件，调参即可）

不需要新建 System 类，仅修改 `ModeData.cs` 参数。

| 适合场景 | 推荐基础 | 调整方向 |
|---------|---------|---------|
| 团队击杀积分战 | `Mode5V5ReLife` | 调整 `RoundTime`、`WinScore`、`MaxRoundCount` |
| 个人生存/竞技 | `ModeGoldRush` | 调整 `ModeWinState`、积分渠道、重生时间 |
| 双方进攻防守 | `ModeMobileControlPoint` | 调整占点参数、计分方式 |
| PVE 协作推关 | `ModeExplore` / `ModeBoss` | 调整 AI 波次、Boss 数据 |

#### 🔴 B 类：特化模式（需要新建专属 Server/Client System）

需要全新玩法逻辑，**必须新建 `ServerXxxMode` 和（如有 UI）`ClientXxxMode`**，并在 `ServerModeSystem.InitModeComponent()` 注册。

| 适合场景 | 特化原因 | 参考基础 |
|---------|---------|---------|
| 夺旗/护送目标 | 旗帜对象状态、运送路径逻辑 | `ServerMobileControlPointMode` |
| 限时大逃杀/缩圈 | 安全区动态缩小逻辑 | `ServerGoldRushMode`（出生点基础）|
| 塔防玩法 | 防线血量、波次生成、失败条件 | `ServerExploreMode`（AI 波次基础）|
| 竞速/计时挑战 | 到达点计时、个人排名 | `ServerRangeMode`（单人基础）|

## 3. 参数规范

> ⚠️ **AI 必须将玩家描述的数值裁剪到以下范围内**，超出范围不报错，但自动调整并告知玩家。
> 例如："一个无限时间的回合" → `RoundTime = -1`（合法，表示无限制），提示"已设置为无限制回合时长"。

### 3.1 ModeData.Data 完整数据结构

```csharp
public class Data {
    public int Id;                             // 模式 Id（对应 ModeSet 配置表）
    public string ModeName;                    // 模式名称
    public ModeEnum Mode;                      // 模式枚举类型
    public int MaxRoleNum;                     // 最大玩家总数
    public int MaxRoleNumPerTeam;              // 每队最大人数
    public int MinStartModeTeamNum;            // 最少开始队伍数
    public int MinStartPlayCharacterNum;       // 最少开始人数
    public float StartModeDownTime;            // 达到最小人数后倒计时（秒）
    public float StartRoundDownTime;           // 每回合开始倒计时（秒）
    public float WaitNextRoundTime;            // 等待下一回合时间（秒）
    public float WaitModeOverTime;             // 等待结算时间（秒）
    public int RoundTime;                      // 每回合时长（-1=无限制，单位：秒）
    public int WinScore;                       // 胜利所需积分（-1=无积分限制）
    public int ModeWinRoundCount;              // 模式胜利所需回合数
    public int MaxRoundCount;                  // 最大回合数
    public bool PerRoundRandWeapon;            // 是否每回合随机武器
    public RoundWinStateEnum RoundWinState;    // 回合胜利判定方式
    public ModeWinStateEnum ModeWinState;      // 模式胜利判定方式
    public ScoreChannelData[] ScoreChannelDatas; // 积分来源配置
    public float SuperWeaponRecoverCDValueRatio; // 超级武器 CD 回复比例
    public float KillCDValueRatio;             // 击杀 CD 回复比例
}
```

### 3.2 回合与时间参数边界

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认值 | 单位 | 说明 |
|--------|-------|---------|--------|--------|------|------|
| `RoundTime` | -1 | 60~300 | 3600 | 180 | 秒 | -1=无限制 |
| `MaxRoundCount` | 1 | 1~5 | 20 | 1 | 回合 | 1=单回合模式 |
| `ModeWinRoundCount` | 1 | 1~3 | 10 | 1 | 回合 | 须 ≤ MaxRoundCount |
| `StartModeDownTime` | 0 | 5~30 | 120 | 10 | 秒 | 0=立即开始 |
| `StartRoundDownTime` | 0 | 3~10 | 30 | 5 | 秒 | 每回合开始前的读秒 |
| `WaitNextRoundTime` | 0 | 5~15 | 60 | 10 | 秒 | 两回合间隔 |
| `WaitModeOverTime` | 0 | 5~10 | 30 | 5 | 秒 | 结算等待时间 |

### 3.3 人数与队伍参数边界

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认值 | 说明 |
|--------|-------|---------|--------|--------|------|
| `MaxRoleNum` | 1 | 2~10 | 20 | 10 | 模式总容量 |
| `MaxRoleNumPerTeam` | 1 | 1~5 | 10 | 5 | 单队上限 |
| `MinStartModeTeamNum` | 1 | 1~2 | 4 | 2 | 至少需要多少队才开始 |
| `MinStartPlayCharacterNum` | 1 | 1~4 | 20 | 2 | 至少需要多少人才开始 |

### 3.4 积分参数边界

| 字段名 | 最小值 | 推荐范围 | 最大值 | 默认值 | 说明 |
|--------|-------|---------|--------|--------|------|
| `WinScore` | -1 | 10~50 | 9999 | -1 | -1=无分数限制（靠时间/回合判定）|
| 每渠道 `Score` | 1 | 1~5 | 100 | 1 | 单次得分 |

### 3.5 胜负判定枚举

#### 回合胜利条件（RoundWinStateEnum）

| 枚举值 | 值 | 说明 | 适用场景 |
|-------|----|------|---------|
| `PersonalScoreTop` | 1 | 个人积分最高者获胜 | 1V1、个人竞技 |
| `TeamScoreTop` | 2 | 队伍积分最高（支持平局）| 5V5、团队模式 |
| `UniqueTeamScoreTop` | 3 | 队伍积分最高（不支持平局，必分胜负）| 占点、夺金 |

#### 模式胜利条件（ModeWinStateEnum）

| 枚举值 | 值 | 说明 | 适用场景 |
|-------|----|------|---------|
| `PersonalScoreTop` | 1 | 个人总积分最高 | 个人竞技 |
| `TeamScoreTop` | 2 | 队伍总积分最高 | 队伍对抗 |
| `RoundWinTop` | 3 | 回合胜利次数最高 | 多回合 BO3/BO5 |

### 3.6 积分来源渠道（GetScoreChannelEnum）

| 渠道枚举 | 说明 | 推荐分值 |
|----------|------|---------|
| `KillRole` | 击杀玩家 | 1 |
| `KillRoleAI` | 击杀玩家 AI | 1 |
| `KillBoss` | 击杀 Boss | 5~10 |
| `KillAI` | 击杀普通怪物 | 1 |
| `KillMasterAI` | 击杀宠物怪物 | 1 |
| `NaturalResource` | 采集资源 | 1 |
| `FinalSurvivalTeam` | 最终存活队伍 | 5~20 |

## 4. 模式行为预设包

### 4.1 预设包一览

| 预设码 | 名称 | 核心机制 | 关键参数 | 推荐范围 |
|--------|------|---------|---------|---------|
| **M01** | 限时积分战 | 时间结束计总积分 | `RoundTime` + `WinScore=-1` | RoundTime=60~300s |
| **M02** | 先到积分 | 率先达到目标分获胜 | `WinScore` + `RoundTime=-1` | WinScore=10~50 |
| **M03** | 多回合 BO 制 | 多回合胜场制胜 | `MaxRoundCount` + `ModeWinRoundCount` + `ModeWinState=RoundWinTop` | BO3: Max=3, Win=2 |
| **M04** | 复活重生 | 死亡后倒计时重生 | `RelifeData.relifeTimer`（模式专属）| 3~10 秒 |
| **M05** | 无复活淘汰 | 死亡不重生，存活者获胜 | 无 RelifeData，`ModeWinState=TeamScoreTop` | — |
| **M06** | PVE 协作 | 所有玩家同队打 AI | `MaxRoleNumPerTeam=MaxRoleNum`，积分渠道 KillAI/KillBoss | — |
| **M07** | 物品掉落 | 击杀掉落可拾取物品 | `ServerModeDropItem` 组件 | — |
| **M08** | 自动拾取 | 进入范围自动拾取金币 | `ServerModeAutoPickUpItem` 组件 | — |
| **M09** | 无限火力 | 弹夹无限，武器不换弹 | `ModeData.IsUnlimitedFireMode()`（返回 true）| 已有变体枚举 |

### 4.2 预设包参数互斥规则

| 预设 A | 预设 B | 关系 | 说明 |
|--------|--------|------|------|
| M01（限时）| M02（先到分）| ⚠️ 可组合 | 同时设置：率先到分 **或** 时间耗尽均结算 |
| M03（BO 制）| M02（先到分）| ✅ 推荐组合 | 每回合内先到分，多回合 BO 制 |
| M04（复活）| M05（无复活）| ❌ 互斥 | 选其一 |
| M06（PVE）| M04（复活）| ✅ 推荐组合 | PVE 模式中通常有复活 |
| M07（掉落）| M08（自动拾取）| ✅ 可组合 | 掉落后自动拾取（夺金模式） |

### 4.3 复合预设组合示例

| 需求描述 | 预设组合 | 关键参数 |
|---------|---------|---------|
| "5V5 对枪，先到 10 杀获胜" | M02 + M04 | `WinScore=10`, `RoundTime=-1`, `KillRole=1`, 复活 |
| "团队 3 回合制，时间到算总积分" | M01 + M03 | `RoundTime=120`, `MaxRoundCount=3`, `ModeWinRoundCount=2` |

| "PVE 打怪积分，有复活" | M06 + M04 | `MaxRoleNumPerTeam=5`, `KillAI=1`, `KillBoss=5`, 复活 |
| "夺金：捡金币，先到 50 分赢" | M02 + M04 + M07 + M08 | `WinScore=50`, 死亡掉金，自动拾取 |

## 5. AI 意图识别增强规则

### 5.1 程度词→参数映射

| 程度词 | 含义 | RoundTime 处理 | WinScore 处理 | MaxRoleNum 处理 |
|--------|------|---------------|-------------|----------------|
| 很快/很短 | ×0.5 | ×0.5（更短）| ×0.5 | — |
| 比较短 | ×0.7 | ×0.7 | ×0.7 | — |
| 标准/默认 | ×1.0 | 保持默认 | 保持默认 | 保持默认 |
| 比较长/久 | ×1.5 | ×1.5 | ×1.5 | — |
| 很长/很久 | ×2.0 | ×2.0 | ×2.0 | — |
| 超级大/超多人 | — | — | — | 取最大值 20 |

**示例**：
- 输入："一个回合时间很长的 5V5 模式"
  - `RoundTime`: 180s（默认）× 2.0 = **360s**（裁剪至最大值 3600s 内，合法）

### 5.2 玩法描述词→模式类型映射

| 玩家描述 | 映射模式类型 | 推荐基础 | 关键特征 |
|---------|------------|---------|---------|
| 团队对战/5V5/对枪 | VS 复活模式 | `Mode5V5ReLife` 调参 | 复活，队伍积分，击杀得分 |
| 1V1/单挑/单打 | 1V1 模式 | `Mode1V1` 调参 | 掉线保护，无复活，单回合 |
| 夺金/捡金币/拾取 | 夺金模式 | `ModeGoldRush/ModeTeamGoldRush` | 掉落金币，积分=金币数 |
| 占点/控制点/据点 | 移动占点 | `ModeMobileControlPoint` 调参 | 占领目标，时间积分 |
| Boss 战/打 Boss/副本 | Boss 模式 | `ModeBoss` 调参 | 协作，PVE，无积分对抗 |
| 探索/冒险/收集 | 探索模式 | `ModeExplore` 调参 | AI 波次，地图探索 |
| 靶场/练习/训练 | 靶场模式 | `ModeRange` 调参 | 假人靶，无对抗 |
| 大逃杀/吃鸡/缩圈 | 需特化 B 类 | `ServerGoldRushMode` 为基础 | 安全区逻辑需新建 |

| 竞速/赛跑/计时 | 需特化 B 类 | `ServerRangeMode` 为基础 | 到达逻辑需新建 |

### 5.3 行为描述词→预设包映射

| 玩家描述 | 映射预设 | 说明 |
|---------|---------|------|
| 时间到算分/限时 | M01 | `RoundTime > 0` |
| 先得到多少分赢/率先 | M02 | `WinScore > 0` |

| 场景 | ❌ 禁止行为 | ✅ 正确做法 |
|------|-----------|----------|

## 7. AI 处理流程

### Step 1：意图识别与分类

判断请求类型：
- **调参**：修改现有模式的数值（`RoundTime`、`WinScore` 等）
- **新建通用模式**：复用现有专属 System，仅配置参数
- **新建特化模式**：需要新建 `ServerXxxMode` System 类

### Step 2：模式类型判定

应用第 5.2 节"玩法描述词→模式类型映射"表，确定：
- A 类（通用）→ 复用已有 System，仅配置 ModeData
- B 类（特化）→ 需要新建专属 System，先询问用户确认

### Step 3：参数边界验证

提取所有数值参数，应用第 3 章边界表验证。检查互斥规则：
- `WinScore = -1` 且 `RoundTime = -1` → **无结束条件，必须告知用户**
- `ModeWinRoundCount > MaxRoundCount` → **逻辑错误，自动纠正**

### Step 4：预设包选择

应用第 5.3 节"行为描述词→预设包映射"，组合多个预设（如 M01 + M04），检查第 4.2 节互斥规则。

### Step 5：歧义检测与追问

检查是否触发第 6.2.1 节歧义场景。如有歧义，生成追问，等待玩家明确后再继续。

### Step 6：生成完整配置

- 输出 `ModeData.cs` 修改项（枚举 + Init switch 配置）
- 输出 `ServerModeSystem.cs` 修改项（`InitModeComponent()` switch 分支）
- 如需特化 System，输出新建 System 的代码框架（见第 8 章）

### Step 7：输出摘要与确认

生成人类可读摘要，示例：
```
✅ 已创建：4V4 团队积分战
- 类型：通用模式（复用 ServerVSReLifeMode）
- 人数：4V4（最多8人）
- 胜利条件：先到 15 杀 或 2 分钟结束时积分最高
- 复活：支持（5秒倒计时）
- 需修改文件：
  1. ModeData.cs — 新增枚举 + Init 配置
  2. ServerModeSystem.cs — InitModeComponent() switch 新增分支
```

#### Step 4：新建 ServerExampleMode.cs（模式专属逻辑）

```csharp
// Assets/Scripts/GamePlay/Server/Mode/Components/MainLoop/ServerExampleMode.cs
namespace Sofunny.BiuBiuBiu2.ServerGamePlay {
    public class ServerExampleMode : ComponentBase {
        private List<SE_Mode.PlayModeCharacterData> characters;
        private ModeData.GameStateEnum gameState = ModeData.GameStateEnum.None;

        // 重生机制（如需要）
        private struct RelifeData {
            public float relifeTimer;
            public IGPO relifeGpo;
        }
        private const float RELIFE_DURATION = 5f;       // 复活等待秒数
        private const float PROTECT_DURATION = 3f;      // 重生无敌秒数
        private readonly List<RelifeData> relifeList = new List<RelifeData>();

        protected override void OnAwake() {
            // 1. 响应回合状态变化
            Register<SE_Mode.Event_GameState>(OnSetGameState);
            // 2. 响应新角色加入
            Register<SE_Mode.Event_AddCharacterFinish>(OnAddCharacterFinish);
            // 3. 响应出生点请求
            MsgRegister.Register<SM_Mode.GetStartPoint>(OnGetStartPointCallBack);
            // 4. 响应模式启动
            MsgRegister.Register<SM_Mode.StartMode>(OnStartModeCallBack);
        }

        protected override void OnStart() {
            base.OnStart();
            AddUpdate(OnUpdate);
        }

        protected override void OnClear() {
            characters = null;
            relifeList.Clear();
            RemoveUpdate(OnUpdate);
            Unregister<SE_Mode.Event_GameState>(OnSetGameState);
            Unregister<SE_Mode.Event_AddCharacterFinish>(OnAddCharacterFinish);
            MsgRegister.Unregister<SM_Mode.GetStartPoint>(OnGetStartPointCallBack);
            MsgRegister.Unregister<SM_Mode.StartMode>(OnStartModeCallBack);
        }

        private void OnUpdate(float dt) {
            // 复活倒计时
            for (int i = relifeList.Count - 1; i >= 0; i--) {
                var data = relifeList[i];
                data.relifeTimer -= dt;
                if (data.relifeTimer <= 0) {
                    relifeList.RemoveAtSwapBack(i);
                    RelifeGpo(data.relifeGpo);
                } else {
                    relifeList[i] = data;
                }
            }
        }

        private void OnSetGameState(ISystemMsg body, SE_Mode.Event_GameState ent) {
            gameState = ent.GameState;
            if (ent.GameState == ModeData.GameStateEnum.RoundStart) {
                OnGameStart();
            }
        }

        private void OnStartModeCallBack(SM_Mode.StartMode ent) {
            mySystem.Dispatcher(new SE_Mode.Event_GetCharacterList {
                CallBack = list => { characters = list; }
            });
        }

        private void OnAddCharacterFinish(ISystemMsg body, SE_Mode.Event_AddCharacterFinish ent) {
            var gpo = ent.Data.CharacterGPO;
            // 装备武器
            gpo.Dispatcher(new SE_GPO.Event_ModeEquipWeapon {
                WeaponList = ent.Data.WeaponList,
            });
            // 监听死亡
            gpo.Register<SE_GPO.Event_SetIsDead>(OnCharacterDead);
        }

        private void OnGetStartPointCallBack(SM_Mode.GetStartPoint ent) {
            // 根据队伍分配出生点（如有 ServerTeamModeSpawnPoint，此处逻辑已自动处理）
        }

        private void OnGameStart() {
            // 回合开始时：重置角色位置、回满血
            if (characters == null) return;
            foreach (var data in characters) {
                Dispatcher(new SE_Mode.Event_ResetCharacterSpawnPoint {
                    IsGameStart = true,
                    CharacterGpo = data.CharacterGPO,
                });
                data.CharacterGPO.Dispatcher(new SE_GPO.Event_ReLife { UpHp = 9999999 });
            }
        }

        private void OnCharacterDead(ISystemMsg body, SE_GPO.Event_SetIsDead ent) {
            if (!ent.IsDead) return;
            relifeList.Add(new RelifeData {
                relifeTimer = RELIFE_DURATION,
                relifeGpo = body.GetGPO(),
            });
        }

        private void RelifeGpo(IGPO gpo) {
            Dispatcher(new SE_Mode.Event_ResetCharacterSpawnPoint {
                IsGameStart = false,
                CharacterGpo = gpo,
            });
            gpo.Dispatcher(new SE_GPO.Event_ReLife { UpHp = 9999999 });
            MsgRegister.Dispatcher(new SM_Ability.PlayAbilityEffect {
                TargetGPO = gpo,
                MData = AbilityM_ProtectGPO.CreateForID(AbilityM_ProtectGPO.ID_GoldRushProtect)
            });
        }
    }
}
```

| **新建特化模式** | 同通用 + 新建 `ServerXxxMode.cs` | `ClientXxxMode.cs` + `SM_Xxx.cs` + 专属战报 |

### 10.3 关键注意事项

1. **`ModeWinRoundCount` ≤ `MaxRoundCount`**：否则模式永远无法结束，必须在生成前验证
2. **`RoundTime = -1` 与 `WinScore = -1` 不能同时存在**：会导致无限局，需告知用户选择至少一个结束条件
3. **模式 `ModeEnum` 的枚举值不能重复**：新增枚举值必须在现有最大值（16）基础上累加
4. **客户端 `ClientModeSystem` 在 `OnAwake` 时读取 `ModeData.PlayMode`**：此时 `PlayMode` 必须已经确定，否则走 default（无专属组件）
5. **专属消息文件放独立 cs**：不污染 `SM_Mode.cs`，参考 `SM_ControlPoint.cs` 命名模式
