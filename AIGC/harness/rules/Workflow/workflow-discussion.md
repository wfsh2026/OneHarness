# 工作流：轻量讨论 (workflow-discussion.md)

> 工作流类型：轻量讨论
> 适用场景：技术核对、方案讨论、规范确认等非开发类对话。
> 通用 session 记录规范见：[[session-guide]]

---

## 一、session-state 建立规则

AI 按以下条件判断，并在**流程声明**中输出判断结果，用户可随时纠正：

| 条件 | 是否建立 session-state |
|------|----------------------|
| 讨论涉及规范变更 / 架构决策 | ✅ 建立 |
| 用户明说"下次继续" / "记录下来" | ✅ 建立 |
| 其余情况（单次问答、技术核对、内容确认等） | ❌ 不建立 |

> 判断结果必须在流程声明中透明输出，用户发现误判时一句话纠正即可。

---

## 二、完整流程图

```
  用户侧                                    AI 侧
  ──────                                    ─────

1. 发起讨论话题
        │
        ▼
                            2. 输出流程声明（含 session-state 判断结果）

                            3. 展开讨论
                            ├─ 每次重要决策 → 写入 active.md ADR（已建立时）
                            ├─ 每次重要推理 → 写入 session-log.md（已建立时）
                            └─ 遇到需要用户决策的点 → ask_user 等待
        │
        ▼（反复）
4. 用户回复推进话题
        │
        ▼
                            5. 达成结论或阶段性共识
                            ├─ 已建立 session-state → 更新 active.md 当前阶段
                            └─ 结论若涉及规范变更 → 写入对应 rules/ 文件
```

---

## 三、流程声明格式（进入 / 切换时必须输出）

```
→ 进入 [轻量讨论] 工作流
→ session-state：{不建立，单次技术核对 / 建立，涉及规范变更}
   如需持续跟踪记录，告诉我"记录下来"即可
```

---

## 四、强制等待原则

| 阶段 | 强制等待 | 禁止行为 |
|------|---------|---------|
| 任何需要用户决策的节点 | ask_user 等待，不得自行推进 | 不得猜测用户意图继续讨论 |
| 达成阶段性结论后 | ask_user 确认结论是否准确 | 不得直接写入规范文件 |

---

```markdown
| # | 议题 | 结论 | 状态 |
|---|------|------|------|
| 1 | {议题描述} | {结论} | ✅ / 🔄 / 📋 |

## 关键决策（ADR）

|---|-------|---------|------|

- {待用户确认的内容}
```
