# 安全规则 & AI 总体设计约束

> 此文件是 AI 行为的最高优先级约束，任何其他规范均不得与此冲突。
> **所有 Agent（DL/ GD）在任何任务前均须遵守本文件。**

---

## 一、AI 禁止行为（危险操作黑名单）

| 禁止操作 | 原因 |
|---------|------|
| `rm -rf` 类删除命令 | 不可逆，可能销毁项目文件 |
| 任何 `git` 写操作（`commit` / `push` / `merge` / `rebase` / `cherry-pick` 等） | 版本历史不可逆，必须由用户手动执行；AI 只输出待执行命令 |
| 同步完成后输出 git 操作提示 | 同步结果与 git 操作完全分离，AI 不提示用户执行 git |
| 未经用户确认直接执行 sync | diff 简报必须先内联输出至对话，用户回复确认后才可执行 sync |
| `git push --force` / `git push -f` | 强制覆盖远程历史，破坏协作 |
| `git reset --hard` | 不可逆丢弃本地变更 |
| `git clean -f` | 不可逆删除未追踪文件 |
| `sudo` 命令 | 权限过高，风险不可控 |
| 修改 `.env` 文件 | 可能泄露/损坏环境变量 |
| 修改任何 `Base` 类源码 | 见下方"不修改Base类"约束 |
| 新增框架父类（XXXBase/XXXFramework/XXXCore） | 见下方"不生成新父类"约束 |

---

## 二、AI 总体设计要求

- **AI 必须严格遵循项目现有架构，不得新增框架或修改底层系统。**
- **AI 开发过程需要以中文进行回答**
- **AI 设计方案文档需标记清楚需求的核心循环，并针对核心循环建立计划，优先完成核心循环的工作在扩充其他内容**
- **核心循环完成后，再根据需求补充其他功能，避免过早实现非核心内容导致时间不足**
- **核心循环必须包含完整用户交互路径**：玩家输入 → 客户端 UI 交互 → CMD 上传 → 服务端处理 → RPC 下发 → 客户端表现。凡涉及玩家主动操作的功能，均需在技术设计文档中绘制此链路，不得遗漏 UI 层。
