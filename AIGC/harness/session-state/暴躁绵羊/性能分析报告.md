# 暴躁绵羊 (MotoSheep) — 性能分析报告

> **分析范围**：彩虹飞跃技能全链路（客户端 Mesh 生成 → 服务端处理 → 网络传输 → 物理交互 → 每帧运行时开销）
> **基准环境**：MotorCarController 物理频率 50Hz，Mirror 网络框架

---

## 一、总览

| 维度 | 评级 | 关键指标 |
|------|------|---------|
| **Mesh 生成** | 🟢 优秀 | 6 顶点 / 4 三角面，静态数组复用，零 GC |
| **对象池化** | 🟢 优秀 | 静态 Mesh 池 + Entity 池，避免反复 new Mesh() |
| **网络开销** | 🟢 优秀 | CMD 10 字节，RPC 49 字节 |
| **服务端 CPU** | 🟢 优秀 | 每次技能 ~5-10 μs |
| **MeshCollider 烘焙** | 🟡 注意 | 每次激活 ~1-2 ms（同步主线程） |
| **Trigger 回调** | 🟡 注意 | GetComponentInParent ~100-300 μs / 次 |
| **GC 分配** | 🟡 注意 | 每次技能 4-5 个托管对象 + Lambda 闭包 |
| **每帧运行时** | 🟢 优秀 | extraEngineTorque 计算 ~0.2 μs / 帧 |
| **消散阶段** | 🟡 注意 | Fade 期间 ~4 alloc/帧（MPB.SetColor） |

## 二、客户端 Mesh 生成 (RainbowRoadMeshBuilder)

### 2.1 Mesh 规模

| 指标 | 值 | 评价 |
|------|---|------|
| 顶点数 | **6** | 极轻量（2 个四边形） |
| 三角面数 | **4** (12 indices) | 远低于性能阈值 |
| 内存占用 | ~1-2 KB | 可忽略 |

### 2.2 优化亮点 ✅

- **静态 Mesh 池**：`static Stack<Mesh>` 容量 4，复用 Mesh 实例，避免反复 `new Mesh()`
- **静态数组**：`s_Vertices[6]`、`s_Triangles[12]`、`s_Normals[6]`、`s_UVs[6]` 全局共用，**零 GC**
- **MaterialPropertyBlock**：避免材质实例化，共享同一材质

### 2.3 关注点 ⚠️

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **MeshCollider 同步烘焙** | 🟡 中 | `meshCollider.sharedMesh = mesh` 触发物理烘焙，约 **1-2 ms**。多人同时释放技能会叠加 |
| **RecalculateBounds** | 🟢 低 | 6 顶点的 bounds 计算极快，可优化但收益微 |

## 三、Entity 生命周期 (RainbowRoad_Entity)

### 3.1 生命阶段

```
创建(池化) → Init(配置参数) → 存续(5s, 无Update) → Fade消散(~1s) → 回池
```

### 3.2 各阶段开销

| 阶段 | CPU | GC | 频率 |
|------|-----|-----|------|
| Init | < 0.1 ms | 1 alloc (`WaitForSeconds`) | 每次技能 |
| 存续期 | **0** | **0** | — |
| Fade 消散 | ~0.1 ms/帧 | **~4 alloc/帧** (Color + MPB.SetColor × 渲染器数) | ~60帧 |
| 回池 | < 0.1 ms | 0 | 每次技能结束 |

### 3.3 关注点 ⚠️

| 问题 | 严重度 | 说明 |
|------|--------|------|
| **Fade 期间 GC** | 🟡 中 | 每帧 MPB.SetColor 产生少量装箱分配，持续约 60 帧 |

**优化建议**：考虑用 Shader `_Alpha` 属性 + MaterialPropertyBlock 一次性设置，或用 Tween 替代协程。

## 四、网络开销

### 4.1 数据包大小

| 方向 | 包类型 | 字段 | 大小 |
|------|--------|------|------|
| Client→Server | `CmdUseSkill` | carId + skillId + 协议头 | **~10 字节** |
| Server→All Clients | `Rpc_RainbowLeap` | configId + rowId + startPoint(V3) + forward(V3) + rampLength + sprintLength + halfWidth + duration | **~49 字节** |

### 4.2 带宽影响

| 场景 | 计算 | 带宽 |
|------|------|------|
| 1 人释放 1 次 | 10 + 49 = 59 bytes | 可忽略 |
| 50 人同局，每人 2 次/分钟 | 59 × 100 / 60 ≈ 98 B/s | 可忽略 |
| 峰值（10 人同时释放） | 49 × 10 × 50 clients = 24.5 KB | 可忽略 |

**结论**：网络开销极低，不构成瓶颈。

## 五、服务端处理

### 5.1 每次技能激活成本

| 步骤 | 耗时 | GC 分配 |
|------|------|---------|
| 瞬时速度计算 (OnMotoSheepUseSkill) | ~2-3 μs | 0 |

| RPC 序列化与发送 | ~2-3 μs | 1 对象 (Rpc_RainbowLeap) |
| **合计** | **~8-13 μs** | **4-5 对象** |

| 状态 | 射线数 | 耗时 |
|------|--------|------|

## 六、物理交互 (Trigger 回调)

### 6.1 OnTriggerEnter/Exit 链路

```
Physics Engine 触发
  → Car.OnTriggerEnter(collider)
    → DispatchCommand(TriggerEnter)          // 命令分发
    → HandleRainbowRoadEnter(collider)
      → GetComponentInParent<RainbowRoad_Entity>()  // 组件查找（仅 Enter）
      → 4× Set Extra (MaxSpeed/ShiftSpeed/EngineTorque/ShiftEngineTorque)
      → CarShift.FreeShiftOil = true
      → FOV 变化
  → Car.OnTriggerExit(collider)
    → HandleRainbowRoadExit(collider)
      → IsChildOf(currentRainbowRoad.transform)     // ✅ 已优化：替代 GetComponentInParent
      → 4× Reset Extra → 0
      → CarShift.FreeShiftOil = false
      → 还原 FOV
```

### 6.2 热点分析

| 操作 | 耗时 | 频率 | 风险 |
|------|------|------|------|
| `GetComponentInParent<RainbowRoad_Entity>()` | **100-300 μs** | 仅 Enter | 🟢 低（已优化，Exit 不再调用） |
| `IsChildOf(currentRainbowRoad.transform)` | **~1-5 μs** | 仅 Exit | 🟢 低（✅ P0-1 已实施） |
| 4× SetExtra 调用 | ~1 μs | 每次 Enter/Exit | 🟢 低 |
| FOV SetCameraRatio | ~5 μs | 每次 Enter/Exit (仅本地) | 🟢 低 |

**✅ 已优化**：Exit 中的 `GetComponentInParent` 已替换为 `IsChildOf`（纯层级指针比较，省 100-300 μs/次）。

## 七、每帧运行时开销 (MotorCarController)

### 7.1 FixedUpdate 物理循环

| 计算 | 调用 | 耗时 | 频率 |
|------|------|------|------|
| `GetEngineTorque()` | `return EngineTorque + extraEngineTorque` | ~0.1 μs | 每物理帧 (50Hz) |
| `GetMaxSpeed()` | `return maxSpeed + extraMaxSpeed` | ~0.1 μs | 每物理帧 |
| `GetShiftEngineTorque()` | `return ShiftEngineTorque + extraShiftEngineTorque` | ~0.1 μs | 仅氮气时 |
| `GetShiftSpeed()` | `return shiftSpeed + extraShiftSpeed` | ~0.1 μs | 仅氮气时 |

### 7.2 多载具规模预估

| 载具数 | 每帧额外开销 | 占帧预算 (16.6ms) |
|--------|------------|-------------------|
| 1 辆 | ~0.4 μs | 0.002% |
| 10 辆 | ~4 μs | 0.024% |
| 50 辆 | ~20 μs | 0.12% |

**结论**：extraEngineTorque 机制的每帧开销**完全可忽略**。

### 7.3 内存占用

| 新增字段 | 大小 | 位置 |
|---------|------|------|
| `extraEngineTorque` | 4 bytes | MotorCarController |
| `extraShiftEngineTorque` | 4 bytes | MotorCarController |
| `_lastEstimateTime` | 4 bytes | CarNetServer |
| **合计** | **12 bytes / 载具实例** | — |

## 八、GC 分配汇总

### 每次技能激活

| 来源 | 分配数 | 大小估计 | 可优化 |
|------|--------|---------|--------|
| PlayAbility + InData + MData 消息 | 3 | ~200 bytes | 用对象池 |
| ServerRainbowLeapObstacleDetect InitData | 1 | ~100 bytes | 用结构体 |
| TimeReduce Lambda 闭包 | 1 | ~80-150 bytes | 用静态回调 |
| Rpc_RainbowLeap 序列化 | 1 | ~60 bytes | 框架层面 |
| WaitForSeconds (Entity) | 1 | ~20 bytes | 缓存实例 |
| **合计** | **~7** | **~460-530 bytes** | — |

### Fade 消散期间 (约 60 帧)

| 来源 | 每帧分配 | 总计 |
|------|---------|------|
| MPB.SetColor × 渲染器数 | ~4 | ~240 次 |

### 评估

- 技能 CD 30 秒，**GC 频率极低**（~0.5 KB / 30s = 17 B/s）
- Fade 期间的 MPB 分配是主要 GC 来源，但持续时间短

## 十一、结论

**整体评价：🟢 性能良好，无阻塞性问题**

- 核心 Mesh 生成系统设计优秀（静态池、静态数组、MPB），是该类功能的典范实现
- 网络开销极低（CMD 10B + RPC 49B），不会成为瓶颈
- extraEngineTorque 每帧计算开销可忽略（50 辆载具仅 20 μs）
- ✅ P0 优化已全部实施：Exit 的 GetComponentInParent → IsChildOf（省 100-300μs）、WaitForSeconds 静态缓存（省 1 alloc/次）
- 剩余优化空间在 **Fade GC 消除**（P1，15 行代码）
- 障碍检测启用后需关注射线开销，建议预留 Job System 异步化方案
