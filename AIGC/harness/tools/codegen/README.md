# 代码生成工具 (harness/tools/codegen/)

AI 在开发 Ability / GPO / GPOM 功能时，**必须优先调用对应的生成脚本**，而非手动编写模板代码。

## 工具列表

| 脚本 | 用途 | 输出 |
|------|------|------|
| `ability-gen.sh` | 新建 Ability (AB/AE) | 6个文件 + 5处注册 |
| `gpo-gen.sh` | 新建 GPO Server/Client System | 2个文件 + 4处注册 |
| `gpom-gen.sh` | 新建 GPOM 模板数据 | 1个文件 |
| `scene-gen.sh` | 新建完整场景（全链路注册） | 1个场景 + 1个 SceneConfig + 2处注册 + 服务端转换 |
| `scene-server-gen.sh` | 客户端场景转服务端（单独使用） | 1个场景 + BuildSettings 注册 |
| `mode-gen.sh` | 新建 Mode 全套 | 2个文件 + 4处注册 |
| `component-gen.sh` | 新建 Component 模板 | 1个文件 |

## 运行环境

- **Shell**: bash (Mac/Linux, 或 Git Bash on Windows)
- **依赖**: awk, grep, sort, tail (POSIX 标准工具)

## 路径映射（path-config.sh）

所有工具在启动时自动 source `path-config.sh`，根据项目目录结构自动选择路径前缀，**无需手动指定**。

| 项目布局 | 检测条件 | SCRIPTS_BASE | SCENES_RUNTIME | BUNDLE_CONFIGS |
|---------|---------|-------------|----------------|----------------|
| **sausage-man-2022** | `Assets/Script/Biubiubiu2/` 存在 | `Assets/Script/Biubiubiu2` | `Assets/Scenes/Biubiubiu2/Runtime` | `Assets/ToBundle/Biubiubiu2/Configs` |
| **通用（默认）** | 默认 | `Assets/Scripts` | `Assets/Scenes/Runtime` | `Assets/Bundle/Configs` |

> 如需扩展新项目布局，编辑 `path-config.sh` 添加对应的 `if` 分支即可。

## ability-gen.sh

生成完整的 Ability 技能全套文件和注册。

### 参数

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `--name` | ✅ | 技能名称 (PascalCase) | `Bomb` |
| `--type` | ✅ | AB 或 AE | `AB` |
| `--fields` | ✅ | M_ 字段 (名:类型) | `"M_Power:int,M_Speed:float"` |
| `--csv-fields` | ✅ | CSV 列名列表 | `"M_Power,M_Speed"` |
| `--primary-keys` | | 主键字段 | `"M_Sign"` |
| `--sync-client` | | 同步客户端 (默认 true) | `true` |
| `--in-fields` | | AB InData 字段 | `"In_StartPoint:Vector3"` |
| `--project-root` | | 项目根目录 | `.` |

### 生成的文件

```
Assets/Scripts/Data/Configs/Ability/{AB|AE}/TemplateM/AbilityM_{Name}.cs
Assets/Scripts/Data/Configs/Ability/{AB|AE}/TemplateM/Select/AbilityM_{Name}_Select.cs
Assets/Scripts/GamePlay/Server/Ability/System/S{AB|AE}/S{AB|AE}_{Name}System.cs
Assets/Scripts/GamePlay/Client/Ability/System/C{AB|AE}/C{AB|AE}_{Name}System.cs
Assets/Scripts/Message/Network/Ability/{AB|AE}/Rpc_{Name}.cs
Assets/Bundle/Configs/Ability/{AB|AE}/AbilityM_{Name}.csv
```

### 修改的注册文件

- `AbilityConfig_AutoGenerated.cs` / `AbilityEffectConfig_AutoGenerated.cs` — 4处 (const ushort, const string, 2个 switch case)
- `ServerAbilityManager_Switch{AB|AE}.cs` — 1处 switch case
- `ClientAbilityManager_Switch{AB|AE}.cs` — 1处 switch case (仅 sync-client)
- `14_Proto_AbilityAB_Auto.cs` / `15_Proto_AbilityAE_Auto.cs` — 2处 (FuncID + switch case)

### 示例

```bash
bash aigc/harness/tools/codegen/ability-gen.sh \
  --name Bomb --type AB \
  --fields "M_Sign:string,M_Power:int,M_LifeTime:float,M_EffectName:string" \
  --csv-fields "M_Sign,M_Power,M_LifeTime,M_EffectName" \
  --primary-keys "M_Sign" \
  --sync-client true \
  --in-fields "In_StartPoint:Vector3"
```

## 新建 GPO 完整工作流

新建一个完整 GPO 类型时，按顺序执行：

```bash
# 1. 创建 GPOM 模板数据
bash aigc/harness/tools/codegen/gpom-gen.sh --name NewBoss --display-name "新Boss" \
  --custom-fields "Hp:int,Atk:int,MoveSpeed:float"

# 2. 创建 Server/Client System + 注册（默认 Graybox 占位体）
bash aigc/harness/tools/codegen/gpo-gen.sh --name NewBoss --display-name "新Boss"

# 3. 按需生成 Component（使用模板）
bash aigc/harness/tools/codegen/component-gen.sh --name NewBossMove --side server --type ai --template move
bash aigc/harness/tools/codegen/component-gen.sh --name NewBossFindTarget --side server --type ai --template findtarget
bash aigc/harness/tools/codegen/component-gen.sh --name NewBossLifetime --side server --type ai --template lifetime

# 4. 手动完善业务逻辑
# - 在 GPOM_NewBossSet 的 Data 数组中填入 CSV 数据
# - 在 ServerAINewBossSystem.AddComponents() 中添加组件（使用 Step 3 生成的组件）
# - 在 ClientAINewBossSystem.AddComponents() 中添加表现组件
```

## AI 使用规则

1. **新建 Ability** → 必须调用 `ability-gen.sh`，禁止手动创建 AbilityM/Select/RPC/注册
2. **新建 GPO** → 必须调用 `gpo-gen.sh` + `gpom-gen.sh`，禁止手动创建 System/注册
3. **新建场景** → 必须调用 `scene-gen.sh`（两步强制流程，见下方），禁止手动创建 SceneConfig 或注册 Map.cs/SceneData.cs
4. **重新生成服务端场景** → 调用 `scene-server-gen.sh`（单独使用时）
5. **新建 Mode** → 必须调用 `mode-gen.sh`，禁止手动创建 Mode 文件或修改 ModeData.cs 注册
6. **新建 Component** → 必须调用 `component-gen.sh`，AI Component 优先使用 `--template`（findtarget/lifetime/move/rotate/scale），禁止手动创建组件模板
7. **场景创建 = 两步强制流程**：bash 脚本 → MCP 执行。**服务端场景不可跳过**，已存在则删除重建
8. **修改现有内容** → 如果只是添加字段或调整逻辑，可以直接编辑文件，无需重新运行工具
9. **脚本具有幂等性** → 重复运行会检测到已注册并跳过，不会重复写入

## scene-gen.sh

一键创建新场景的完整注册链路（Map.cs + SceneData.cs + SceneConfig.asset + 场景复制 + 服务端转换）。

### 参数

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `--name` | ✅ | 场景名 | `MapTDM_07_NewCity` |
| `--display-name` | ✅ | 中文显示名 | `"新城市"` |
| `--sign` | ✅ | Map Sign 标识符 | `NewCity` |
| `--project-root` | ✅ | 项目根目录 | `.` |
| `--map-id` | | Map ID（自动递增） | `15` |
| `--res-sign` | | Map ResSign（默认=sign） | `NewCity` |
| `--res-icon` | | Map ResIcon（默认 "MapNew"） | `MapNew` |
| `--mode-switch-res` | | Map ModeSwitchRes（默认=sign） | `NewCityLarge` |
| `--mode` | | SceneConfig Mode 整数（默认 5） | `5` |
| `--weapon1` | | 武器1 ID（默认 14） | `14` |
| `--weapon2` | | 武器2 ID（默认 43） | `43` |
| `--super-weapon` | | 超级武器 ID（默认 10） | `10` |
| `--sort` | | Map 排序值（默认 0） | `3` |
| `--is-default` | | 是否默认地图（flag） | |
| `--copy-from` | | 从指定场景复制 .unity | `LevelTest_02` |
| `--scene-dir` | | 场景目录 | `Assets/Scenes/Runtime` |
| `--stage-sign` | | SceneData StageSign（默认=name） | |
| `--element-config` | | SceneData ElementConfig（默认=name） | |
| `--festival-asset` | | StageSign 使用 FestivalAssetData 包装 | |
| `--skip-map` | | 跳过 Map.cs 注册 | |
| `--skip-scene-data` | | 跳过 SceneData.cs 注册 | |
| `--skip-config` | | 跳过 SceneConfig.asset 创建 | |

> ⚠️ **服务端场景生成为强制步骤，没有 skip 选项。** 如果已有同名服务端场景，Unity 会自动删除并重建。

### 注册点

| 文件 | 修改内容 |
|------|----------|
| `Map.cs` | Id 常量 + Data 数组条目 |
| `SceneData.cs` | Data 条目 |
| `SceneConfig.asset` | 新建 YAML 文件（最小模板） |
| `EditorBuildSettings` | 由 Unity MCP 自动注册 |

### AI 工作流（两步强制，缺一不可）

```bash
# Step A: 创建场景全套注册（bash）
bash aigc/harness/tools/codegen/scene-gen.sh \
  --name MapTDM_07_NewCity \
  --display-name "新城市" \
  --sign NewCity \
  --copy-from LevelTest_02 \
  --project-root /path/to/project

# Step B: Unity MCP 执行服务端优化（强制，不可跳过）
execute_menu_item "Tools/功能/场景/AI场景转换"
# Unity 自动：删除旧 Server 场景(如有) → 优化 → 保存 → 注册 BuildSettings

# Step C: 在 Unity 中填入 SceneConfig 出生点等详细数据
```

## scene-server-gen.sh

将客户端场景转换为服务端优化场景（双步骤工具）。适用于**单独重新生成服务端场景**场景（如客户端场景更新后）。

> 如果是**新建场景**，请使用 `scene-gen.sh`（包含完整注册链路）。

### 架构说明

本工具是**唯一需要两步执行**的工具（因为场景 Prefab 组件操作必须通过 Unity Editor API）：
1. Bash 脚本：复制场景 + 写入配置
2. Unity MCP：执行 `Tools/功能/场景/AI场景转换` 菜单

### 参数

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `--scene-name` | ✅ | 目标场景名（不含路径/扩展名） | `LevelTest_02_Temp` |
| `--copy-from` | | 源场景名（可选，用于复制） | `LevelTest_02` |
| `--project-root` | ✅ | 项目根目录 | `.` |
| `--scene-dir` | | 场景目录（默认 `Assets/Scenes/Runtime`） | |

### AI 工作流

```bash
# Step 1: Bash
bash aigc/harness/tools/codegen/scene-server-gen.sh \
  --scene-name LevelTest_02_Temp \
  --copy-from LevelTest_02 \
  --project-root /path/to/project

# Step 2: Unity MCP
execute_menu_item "Tools/功能/场景/AI场景转换"
```

### 场景优化内容

| 操作 | 说明 |
|------|------|
| 移除 MeshRenderer | 渲染组件 |
| 移除 MeshFilter | 网格数据 |
| 移除 ParticleSystem | 粒子特效 |
| 移除 LODGroup | LOD 层级 |
| 移除 LineRenderer | 线渲染 |
| 移除 Light (整个 GO) | 灯光及其 URP 依赖组件 |
| SceneGPOEntity.IsServer = true | 标记为服务端 |
| 添加 HitType (Layer=Ignore) | 碰撞体跳过子弹 |
| 注册 EditorBuildSettings | 自动添加客户端+服务端场景 |

## component-gen.sh

生成 Component 模板文件（支持 5 种系统类型 × 2 侧 = 10 种组合）。

### 参数

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `--name` | ✅ | 组件名 (PascalCase) | `ServerAICyberBubbleMove` |
| `--side` | ✅ | server 或 client | `server` |
| `--type` | ✅ | ai\|ability\|weapon\|character\|mode | `ai` |
| `--has-init-data` | | 生成 InitData 结构体 | |
| `--has-update` | | 生成 OnUpdate (默认关) | |
| `--no-entity` | | 不生成 OnSetEntityObj (默认开) | |
| `--has-network` | | 强制生成 OnSetNetwork | |
| `--no-network` | | 不生成 OnSetNetwork | |
| `--has-sync` | | 生成 SyncData (仅 server) | |
| `--template` | | 使用预置模板 (仅 server+ai) | `move` |
| `--desc` | | 中文描述 | `"泡泡移动组件"` |
| `--dry-run` | | 仅预览 | |

### 类型行为

| Type | Server 基类 | 系统引用 | 字段 |
|------|------------|----------|------|
| ai | ServerNetworkComponentBase | S/C_AI_Base | mAI |
| ability | ComponentBase (默认) | S/C_Ability_Base | mAbility |
| weapon | ComponentBase (默认) | S/C_Weapon_Base | mWeapon |
| character | ServerNetworkComponentBase | S/C_Character_Base | mCharacter |
| mode | ComponentBase | (无) | — |

- **OnSetNetwork 默认**: client=auto开, server=auto关
- **OnSetEntityObj**: 默认开
- **方法生成顺序**: OnAwake → OnStart → OnClear → OnSetEntityObj → OnSetNetwork → SyncData → OnUpdate

### 示例

```bash
# Server AI 全功能
bash aigc/harness/tools/codegen/component-gen.sh \
  --name ServerAICyberBubbleMove --side server --type ai \
  --has-init-data --has-update --has-sync \
  --desc "泡泡移动组件"

# Client Mode 标准
bash aigc/harness/tools/codegen/component-gen.sh \
  --name ClientModeLobbyTimer --side client --type mode \
  --has-init-data --has-update \
  --desc "大厅倒计时"

# 使用模板（自动启用 has-update + has-init-data + entity）
bash aigc/harness/tools/codegen/component-gen.sh \
  --name TestMove --side server --type ai --template move

bash aigc/harness/tools/codegen/component-gen.sh \
  --name TestRotate --side server --type ai --template rotate

bash aigc/harness/tools/codegen/component-gen.sh \
  --name TestScale --side server --type ai --template scale
```

### 预置模板 (`--template`)

仅限 `--side server --type ai` 使用。模板自动启用 `has-update`、`has-entity`，部分模板还启用 `has-init-data`。

| 模板 | 用途 | InitData 字段 | 核心逻辑 |
|------|------|--------------|----------|
| `findtarget` | 周期索敌 | `CheckDistance`, `ScanInterval` | 遍历 GPOList 找最近敌方 → Dispatcher 事件 |
| `lifetime` | 倒计时自毁 | — | `remainTime -= delta` → `Event_RemoveAI` |
| `move` | 前进移动 | `MoveSpeed` | `iEntity.SetPoint(rootTran.forward * speed * delta)` |
| `rotate` | A→B 旋转 | `StartRota`, `EndRota`, `RotaSpeed` | `Quaternion.Slerp` → `iEntity.SetRota()` → 完成后 RemoveUpdate |
| `scale` | A→B 缩放 | `StartScale`, `EndScale`, `Duration` | `Vector3.Lerp` → `iEntity.SetLocalScale()` → 完成后 RemoveUpdate |

**模板组合示例（新建 AI GPO 的标准三件套）：**

```bash
# 1. 生成 GPO 全套（System + 注册）
bash aigc/harness/tools/codegen/gpo-gen.sh --name CyberBubble --display-name "赛博泡泡"

# 2. 生成 GPOM 模板数据
bash aigc/harness/tools/codegen/gpom-gen.sh --name CyberBubble --display-name "赛博泡泡" \
  --custom-fields "Hp:int,MoveSpeed:float"

# 3. 按需生成 Component（使用模板）
bash aigc/harness/tools/codegen/component-gen.sh --name CyberBubbleMove --side server --type ai --template move
bash aigc/harness/tools/codegen/component-gen.sh --name CyberBubbleRotate --side server --type ai --template rotate
bash aigc/harness/tools/codegen/component-gen.sh --name CyberBubbleScale --side server --type ai --template scale
bash aigc/harness/tools/codegen/component-gen.sh --name CyberBubbleFindTarget --side server --type ai --template findtarget
bash aigc/harness/tools/codegen/component-gen.sh --name CyberBubbleLifetime --side server --type ai --template lifetime

# 4. 在 System.AddComponents() 中组装各 Component
```

## UGC 模式

所有 codegen 脚本均支持 `--ugc` 标志。详见 **[ugc/README.md](ugc/README.md)**。
