# 交付规则

开发交付物的最小必填内容：

- 本轮目标。
- 实施内容。
- 修改文件。
- 验证结果。
- 自检触发判断和自检结果。
- 风险、限制或未完成事项。
- Wiki 或项目记录写入判断。

## 按需补充

命中以下情况时，必须补充对应内容：

| 情况 | 补充内容 |
| --- | --- |
| 涉及输入、参数或边界条件 | 无效输入测试结果。 |
| 发生方案取舍 | 关键决策。 |
| 实际比较并放弃过方案 | 被否决方案。 |
| 产生可复用认知 | 经验教训或建议 wiki 沉淀。 |
| 影响项目文档 | 建议文档更新。 |
| 影响 OneHarness 自身文档、规则、配置或工具 | 按 `self-check.md` 运行的自检命令和结果。 |
| 存在阻塞性歧义 | 需要用户确认的问题。 |
| 启用多个执行者或 SubAgent | 多执行者采纳记录。 |

## 状态限制

- 验证未完成时，不能标记为完成。
- 有关键待确认问题时，不能把相关内容写成稳定事实。
- 临时调试过程不进入 wiki，只能保留在交付物或运行记录中。
