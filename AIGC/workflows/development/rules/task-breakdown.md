# 开发任务拆解规则

开发任务必须满足：

- 一个任务对应一个清晰目标。
- 写入范围明确。
- 文件归属明确。
- 输入和输出明确。
- 成功标准可验证。
- 包含有效输入和无效输入验证。
- 能追溯到用户请求、策划案或已确认决策。

## 禁止

- 把模糊目标包装成开发任务。
- 把多个无关目标塞进同一个任务。
- 为一次性实现制造复杂抽象。
- 把未确认事项写成任务事实。
- 让多个执行者同时写入同一个文件。

## 探索型任务

如果任务是验证新功能、新交互或新方向，必须额外写明：

- 待验证假设。
- 验证方式。
- 成立后写入位置。
- 不成立时的记录位置。
