# 开发执行工作流

## 目标

把已确认的需求、策划案或修复目标转成最小可验证改动，并把交付结果、验证记录和可沉淀知识同步到目标项目适配层。

## 激活条件

用户明确表达以下任一意图时激活：

- 实现一个已确认功能。
- 修复一个明确漏洞。
- 执行已有策划案或开发任务。
- 在确认边界内重构、补文档或补测试。
- 持续推进到最小可试用闭环。

## 前置条件

- 已确认目标项目根目录。
- 已确认本轮修改边界。
- 已确认成功标准和验证方式。
- 如需写入项目记录或项目 wiki，必须先建立目标项目适配层。

## 默认读取

1. 本文件。
2. `../session-visible-state.md`。
3. `rules/INDEX.md`。
4. `agents/INDEX.md`。
5. 当前阶段需要的 agent `DEFINITION.md` 和 `RULE.md`。
6. `../../wiki/INDEX.md`。
7. 需要项目适配时读取 `../../projects/INDEX.md`。
8. 需要目标项目事实时读取目标项目 `{project_aigc_root}/ADAPTER.md` 和 `{project_wiki_root}/INDEX.md`。

## 阶段

| 阶段 | 输出 | 验证 |
| --- | --- | --- |
| 输入确认 | 开发任务摘要 | 目标、边界、禁止事项、成功标准、验证方式和项目 wiki 状态已明确。 |
| 任务拆解 | 开发任务分发单 | 每个任务独立、可验证、写入范围清楚。 |
| 实施 | 最小代码或文档改动 | 只修改完成任务必须修改的文件。 |
| 验证 | 验证记录 | 有效输入、无效输入和回归检查已有结果或说明。 |
| 交付 | 开发任务交付物 | 修改文件、验证结果、风险、未完成事项完整。 |
| Wiki 同步 | 写入计划或架构知识页 | 项目事实进入目标项目 wiki，通用架构知识进入 `AIGC/wiki/architecture/`。 |

## Agent

| Agent | 职责 |
| --- | --- |
| `coordinator` | 接收用户目标、确认是否进入开发执行、同步阻塞和交付。 |
| `lead-developer` | 评估开发输入、拆任务、定义验收和验证要求。 |
| `developer` | 执行明确任务、最小修改、验证并输出交付物。 |
| `wiki-curator` | 判断开发结果中哪些内容需要写入通用 wiki 或项目 wiki。 |

## 完成标准

- 本轮目标、边界和验证方式有记录。
- 所有代码或文档改动都能追溯到用户请求或已确认任务。
- 验证通过；无法验证时已说明原因、影响和替代检查。
- 无效输入或失败路径已有测试或手动验证记录。
- 项目事实没有写入通用 AIGC。
- 项目适配层有运行记录和 wiki 同步结果。
- 需要项目事实时，已按 `../../projects/rules/project-wiki-retrieval.md` 查询项目 wiki；项目 wiki 缺失时，已按 `../../projects/rules/project-wiki-bootstrap.md` 建立或说明阻塞。
