# Unity UGUI UI 工作流

## 目标

把用户提供的 UI 截图、效果图或 UI 素材图，转成可在 Unity UGUI 中施工的交付物。工作流采用三角色流水线：

```text
用户输入 UI 图片
-> UI 策划分析
-> 交接给技术美术
-> 技术美术拆解与切图
-> 交接给 Unity 施工员
-> 生成 Prefab 方案、Editor 脚本和 Controller
-> Unity 截图校准并回派修正
```

本工作流不能承诺“单张效果图直接生成最终可交付 UI”。只有素材、分辨率、字体、交互、资源路径和项目设置齐全时，才进入 Prefab 与脚本施工；信息不足时，只输出估算值、待确认项和下一步输入要求。

## 激活条件

用户明确表达以下任一意图时激活：

- 根据 UI 截图、效果图或素材图生成 Unity UGUI 开发方案。
- 需要把 UI 图片拆成 UGUI 节点层级、切图清单、布局表或 Prefab 施工输入。
- 需要生成 UGUI Editor Prefab 创建脚本、运行时 Controller 或截图校准反馈。
- 需要 UI 策划、技术美术和 Unity 施工员分角色协作完成一个界面。

## 不适用条件

- 用户只要 UI 审美建议，不需要 Unity UGUI 落地。
- 用户指定 UI Toolkit、FairyGUI、Nova、NoesisGUI 或其他非 UGUI 技术路线。
- 用户没有提供图片，也没有描述界面结构。此时必须先补充输入。

## 输入完整度分级

| 等级 | 输入 | 可交付 | 禁止承诺 |
| --- | --- | --- | --- |
| L1 | 只有最终效果图 | UI 策划、技术美术拆解建议、UGUI 层级、素材切图清单、RectTransform 第一版估算、待确认项 | 精准像素还原、完整交互逻辑、完整 Prefab 绑定 |
| L2 | 效果图和拆分素材 | L1 内容、切图执行记录、素材拼接还原文档、导入设置、资源路径依赖表、Prefab 生成方案、Controller 结构 | 未确认交互、动态数据、字体和按钮状态不得写死 |
| L3 | 效果图、素材、项目设置和交互说明 | L2 内容、集中布局配置、`CreateXXXPrefab.cs`、`XXXPanelController.cs`、绑定字段表、运行检查清单 | 不得绕过截图校准直接声明最终还原 |

## 默认读取

默认只读本文件和 `rules/INDEX.md`。按阶段继续读取：

1. 需要判断输入能做到哪一步时，读取 `rules/input-completeness.md`。
2. 需要输出 UI 语义、状态和交互交接时，读取 `rules/ui-planning.md`。
3. 需要技术美术拆图、切图或拼接还原文档时，读取 `rules/technical-art-slicing.md`。
4. 需要生成 Unity C#、Prefab 创建脚本或 Controller 时，读取 `rules/unity-construction.md`。
5. 需要对比目标图和 Unity 截图并回派修正时，读取 `rules/screenshot-calibration.md`。
6. 需要交付报告结构时，读取 `templates/ui-ugui-delivery.md`。

## 角色边界

| 角色 | 职责 | 不负责 |
| --- | --- | --- |
| UI 策划 | 界面用途、玩家操作、元素语义、固定文本、动态数据、按钮行为、状态、跳转关系、验收标准和调度 | 切图坐标、Sprite 导入、Unity C#、具体 RectTransform 像素 |
| 技术美术 | 素材拆分、切图工具产物、拼接还原文档、资源命名、导入设置、Sprite 使用规则、字体字号颜色、按钮状态、UGUI 层级和布局表 | 重新设计功能、修改按钮含义、业务跳转逻辑、把全部内容做成死图 |
| Unity 施工员 | UGUI Prefab 层级、集中布局配置、Editor Prefab 创建脚本、运行时 Controller、按钮事件接口、绑定字段表、资源依赖表和运行检查 | 擅自改 UI 语义、换素材风格、把测试数据写死、把复杂业务写进 Controller |

## 执行阶段

| 阶段 | 输出 | 验证 |
| --- | --- | --- |
| 输入检查 | 输入完整度等级和待确认项 | 不足信息没有被编造，估算值已标注。 |
| UI 策划 | UI 策划输出和策划到技术美术交接表 | 元素语义、状态、动态数据和按钮行为清楚。 |
| 技术美术拆解 | 素材拆分清单、切图记录、拼接还原文档和布局表 | `preview_boxes.png` 已审核，`manifest.json` 已映射为语义资源。 |
| Unity 施工 | Prefab 施工方案、集中配置、Editor 脚本、Controller 和绑定表 | 每个 C# 文件只定义一个普通类；布局、资源路径和按钮配置集中。 |
| 截图校准 | 偏差表、修正参数和回派清单 | 目标图与 Unity 截图已完成至少一轮对比。 |

## 子任务隔离

完整执行三阶段、输入图片较多或包含切图产物时，应使用独立 subagent 或独立阶段隔离技术美术和 Unity 施工员。主会话只保留策划决策、交接包、最终风险和验收结论，不堆积完整切图日志、完整 `manifest.json` 或大段代码草稿。

## 完成标准

- 三角色输出边界清晰，没有互相越权。
- 所有可交互元素都能追溯到按钮行为说明。
- 所有 Image 都能追溯到资源路径、切片或占位路径。
- 所有 TMP 文本都标明固定文本或动态数据来源。
- 所有布局参数来自布局表或集中配置。
- 生成脚本符合 Unity 编译要求和每文件单类规则。
- 截图校准有明确回传格式、回派角色和下一轮修正表。
