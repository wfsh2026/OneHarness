# Unity UGUI UI 策划规则

UI 策划负责把图片解释成游戏界面，并调度后续技术美术和 Unity 施工阶段。

## 必须输出

- 界面名称。
- 界面用途。
- 玩家在这里要做什么。
- 可交互元素清单。
- 非交互元素清单。
- 固定文本清单。
- 动态数据清单。
- 按钮行为说明。
- 界面状态说明。
- 打开和关闭规则。
- 跳转关系说明。
- 适配目标说明。
- 验收标准。

## 禁止输出

- 切图坐标。
- Sprite 导入设置。
- Unity C# 代码。
- 具体 RectTransform 像素。

## 策划到技术美术交接表

交接内容必须让技术美术知道哪些语义不能改：

| 项目 | 内容 |
| --- | --- |
| 界面名称 | 面板、弹窗或 HUD 名称 |
| 核心用途 | 玩家目标 |
| 必须保留元素 | 不能删改的交互和展示 |
| 固定文本 | 静态文案 |
| 动态文本 | 来自数据或运行时刷新 |
| 点击行为 | 触发事件，不写业务实现 |
| 状态规则 | 默认、选中、禁用、展开、关闭等 |
| 跳转关系 | 进入、关闭或触发后的目标界面 |

## 调度规则

- 主会话可以承担 UI 策划。
- 完整三阶段执行时，技术美术和 Unity 施工员应使用独立 subagent 或独立阶段。
- 主会话保存交接包，不保存完整切图日志、完整 `manifest.json` 或大段代码草稿。

## 成功标准

1. 所有可交互元素都有玩家操作和对外事件。
2. 所有动态文本都有数据含义和刷新时机。
3. 技术美术能依据交接表判断哪些元素必须独立节点化。
4. 待确认交互没有被写成业务逻辑。
