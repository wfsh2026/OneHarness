# Ability 开发规范

> 参考范例：[[Ability 系统开发范例文档]]

---

## ⚠️ 强制工具规则

> **新建 Ability（AB/AE）时，AI 必须调用以下工具：**
> 1. `aigc/harness/tools/codegen/ability-gen.sh` — 生成全套文件和注册
> 2. `aigc/harness/tools/codegen/component-gen.sh` — 生成 Ability 专属 Component 模板（`--type ability`）
>
> 禁止手动创建 AbilityM、Select、RPC、CSV 或手动修改 AutoGenerated/Switch/Proto 注册文件。
> 仅在修改已有 Ability 的业务逻辑（如 AddComponents 内容）时可直接编辑。
> 详见 [[codegen/README]]。

---

## 一、新建 AB 必须创建的文件清单

> **AB（Ability）**：主动行为/一次性行为/触发器行为（如子弹、爆炸、位移、召唤）。
> **必须使用 ability-gen.sh 工具生成**，避免手工维护 AutoGenerated 文件。

### 📋 数据层（必须）

| 文件 | 操作 | 说明 |
|------|------|------|
| `Data/Configs/Ability/AB/TemplateM/AbilityM_XXX.cs` | **新建** | AB 模板数据类（定义 M_ 字段：血量/速度/特效 Sign 等） |
| `Assets/Bundle/Configs/Ability/AB/AbilityM_XXX.csv` | **新建** | AB 配置数据 CSV（数据行含 ID/RowSign/M_* 字段） |
| `Data/Configs/Ability/AbilityConfig_AutoGenerated.cs` | **修改**（ability-gen.sh 生成） | 注册 AB ConfigId（10000+）和类型常量 `AB_XXX` |

### 🔌 路由注册层（必须）

| 文件 | 操作 | 说明 |
|------|------|------|
| `GamePlay/Server/Ability/ServerAbilityManager_SwitchAB.cs` | **修改**：switch 新增 case | 服务端 AB TypeID → `SAB_XXXSystem` 路由 |
| `GamePlay/Client/Ability/ClientAbilityManager_SwitchAB.cs` | **修改**：switch 新增 case | 客户端 AB protoID → `CAB_XXXSystem` 路由（若有客户端表现） |

### 📡 网络协议层（必须，ability-gen.sh 生成）

| 文件 | 操作 | 说明 |
|------|------|------|
| `Message/Network/Ability/AB/Rpc_AB_XXX.cs` | **新建**（ability-gen.sh 生成） | AB 的网络数据结构 |
| `Message/Network/14_Proto_AbilityAB_Auto.cs` | **修改**（ability-gen.sh 生成） | 注册 AB FuncID 和反序列化入口 |

### 🖥️ 逻辑层（必须）

| 文件 | 操作 | 说明 |
|------|------|------|
| `GamePlay/Server/Ability/Systems/SAB/SAB_XXXSystem.cs` | **新建** | 继承 `S_Ability_Base`，服务端逻辑（判断/伤害/状态） |

## 三、触发入口（不需要新建文件，调用现有接口）

```csharp
// 触发 AB
MsgRegister.Dispatcher(new SM_Ability.PlayAbility {
    FireGPO = iGPO,
    MData   = AbilityM_XXX.CreateForSign("DefaultXXX"),
    InData  = new AbilityIn_XXX { ... },
});

// 触发 AE（施加到目标 GPO）
MsgRegister.Dispatcher(new SM_Ability.PlayAbilityEffect {
    FireGPO   = iGPO,
    TargetGPO = targetGpo,
    MData     = AbilityM_XXX.CreateForSign("DefaultXXX"),
    InData    = new AbilityIn_XXX { ... },
});
```

## 四、Component 开发规范

### 4.1 Component 内访问 MData / InData

```csharp
protected override void OnAwake() {
    base.OnAwake();
    abSystem = (S_Ability_Base)mySystem;
    mData    = (AbilityM_XXX)abSystem.MData;
    inData   = (AbilityIn_XXX)abSystem.InData;
}
```

### 4.2 延迟/定时回调

```csharp
UpdateRegister.AddInvoke(OnDelayedHit, mData.M_DelayTime);  // 延迟单次
AddUpdate(OnUpdate);  // 周期更新（OnClear 中必须 RemoveUpdate）
```

### 4.3 触发链式 Ability 必须传入 OR_ParentAB

```csharp
MsgRegister.Dispatcher(new SM_Ability.PlayAbility {
    FireGPO     = abSystem.FireGPO,
    MData       = AbilityM_Meteor.CreateForSign("DefaultMeteor"),
    InData      = new AbilityIn_Meteor { In_LandPoint = landPoint },
    OR_ParentAB = abSystem,   // ← 必须传，标记父 Ability 引用
});
```

### 4.4 AE 效果作用于受体 GPO

不应在 SAE System 上建立 `public static` 容器。通过 `SM_Ability.PlayAbilityEffect` 在 TargetGPO 上叠加 AE，伤害管线自动加成。

> **规则核心**：Component 之间**只能**通过事件通信，禁止跨 System/Component 的直接字段引用（包括 `static`）。

## 五、AE 去重行为

同一 `TargetGPO + ConfigID + RowId` 再触发 AE 时，框架走 `ResetEffect()` 刷新，**不会新建实例**。若出现叠加异常，检查触发参数是否真的一致。

## 六、GPO 伤害倍率 AE 选型规则 ⚠️

> 经验教训（坦克大乱斗 SuperBuff Phase 3）：对 GPO AI 单位施加伤害增益，不能用玩家武器 AE，必须用 GPO 专属 AE。

### 6.1 两套伤害增益体系

| 体系 | AE 类型 | 效果 Component | 适用对象 |
|------|---------|---------------|---------|
| **玩家武器** | `AbilityM_WeaponATKAddRate` | `EffectWeaponATKAddRate` → `GpoWeaponATKAddRate` | 玩家角色持枪武器（`SE_Weapon.Event_GetATK`） |
| **GPO 输出** | `AbilityM_HurtValueRate` | `EffectHurtValueRate` → `GpoExplosiveHurtValueRate` | GPO AI 单位炮弹/技能（`Event_GetHurtRateByDamageType`） |

### 6.2 为什么 WeaponATKAddRate 对 GPO 无效

`EffectWeaponATKAddRate` 向 GPO 派发 `GpoWeaponATKAddRate` 事件，但 `ServerGPOAttribute.OnUpdateEffectCallBack()` 的 switch 中**没有** `GpoWeaponATKAddRate` 的 case —— 效果被静默忽略，不报错但不生效。

### 6.3 GPO 坦克伤害增益标准写法

```csharp
// ✅ 正确：坦克炮弹 DamageType=Explosive，用 HurtValueRate
MsgRegister.Dispatcher(new SM_Ability.PlayAbilityEffect {
    FireGPO   = iGPO,
    TargetGPO = tankGPO,
    MData     = AbilityM_HurtValueRate.CreateForSign("TankBattle_AtkBuff"),
});
```

CSV 配置要点（`Assets/Bundle/Configs/Ability/AE/AbilityM_HurtValueRate.csv`）：
- `M_DamageType = 2`（Explosive，坦克炮弹类型）
- `M_IsUseHeroATK = FALSE`（GPO 单位不用英雄 ATK 值）

```csharp
// ❌ 错误：对 GPO 坦克用玩家武器 AE，静默无效
MData = AbilityM_WeaponATKAddRate.CreateForSign("TankBattle_AtkBuff"),
```

## 六、⚠️ AB CSV 填写后强制自检清单

> AI 手动填写或修改 AB/AE 的 CSV 数据后，**必须逐项检查以下内容**，确认无误后才可继续。
> DL 验收代码时也需对照此清单复查。

| # | 检查项 | 说明 | 常见错误 |
|---|--------|------|---------|
| C1 | K_RowSign **非空** | 空 RowSign 会导致 `CreateForSign()` 查询失败 | 新建 CSV 行时忘记填 RowSign |
| C2 | M_ConfigSign **非空**且与 AB Sign 一致 | ConfigSign 是运行时查找 AB 配置的关键字段 | 复制粘贴后忘改 Sign |
| C3 | K_ID **在同一 CSV 内唯一** | 重复 ID 导致数据覆盖 | 复制已有行忘记递增 ID |
| C4 | 触发源引用的 AB Sign **有对应 CSV 文件** | 如 Slide CSV 引用 `AB_SummonXXX`，则 `AbilityM_SummonXXX.csv` 必须存在 | 先改触发源后忘建 CSV |
| C5 | 触发源引用格式正确：`ABSign\|RowSign` | 竖线分隔，两段都不能为空 | 只填 ABSign 漏了 RowSign |

## 八、⚠️ 新建 AB/AE 完成后必须执行：更新功能清单（强制）

> **此步骤不可跳过**，与提交代码同等优先级。

当任意新 AB 或 AE 开发完成并通过[项目负责人] Round 3 审核后，**Ability 工程师必须立即**在以下文件的"项目已有 Ability 功能清单"对应表格末尾追加新条目：

**目标文件**：[[Ability_Programmer]]（末尾"📦 项目已有 Ability 功能清单"章节）

**AB 追加格式**：
```
| `AbilityM_XXX` | `SAB_XXXSystem` | `CAB_XXXSystem`（或 ✗ 无） | [一句话功能描述] |
```

**AE 追加格式**：
```
| `AbilityM_XXX` | `SAE_XXXSystem` | `CAE_XXXSystem`（或 ✗ 无） | [一句话功能描述] |
```

**检查项（完成前自查）**：
- [ ] `AbilityM_XXX` 模板类名与实际文件一致
- [ ] Server 系统类名（`SAB_/SAE_`）填写准确
- [ ] Client 系统类名（`CAB_/CAE_`）若无则填 `✗ 无`
- [ ] 追加在对应区块（AB 追 AB 表，AE 追 AE 表）的最后一行之后
- [ ] 功能描述一句话可读，不超过 20 字

> **违反此规则的代价**：下一个开发类似效果的 Agent 无法发现已有 AB/AE，导致重复实现。
> **[项目负责人]注意**：Round 3 验收前，检查 Ability_Programmer.md 功能清单是否已更新，未更新不得通过。
