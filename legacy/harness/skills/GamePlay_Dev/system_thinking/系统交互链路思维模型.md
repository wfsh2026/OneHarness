# 系统交互链路思维模型

> 💡 **基于** [[technical-doc-format]] §S-06 提取的思维框架
> 
> 本文件是一个**认知框架（Skill）**，用于在设计任何交互功能时，先画出完整链路图，再开始编码。

---

## 核心思维模型

任何涉及玩家操作的功能，都必须能画出完整链路：

```
[玩家输入] → [客户端 UI 响应] → [CMD 消息] → [服务端处理] → [RPC 广播] → [客户端表现]
```

如果链路中任何一环缺失，说明功能设计不完整。

---

## 链路完整性检查

在设计任何交互功能时，逐环检查：

| 环节 | 必须回答的问题 | 缺失时的后果 |
|------|--------------|------------|
| 玩家输入 | 玩家通过什么操作触发？（按钮/手势/自动） | 功能无法启动 |
| 客户端 UI 响应 | 点击后界面有什么即时反馈？ | 玩家感知不到操作是否生效 |
| CMD 消息 | 客户端如何将操作通知服务端？消息格式是什么？ | 服务端无法收到玩家操作 |
| 服务端处理 | 服务端收到后如何验证和处理？状态如何更新？ | 逻辑无法执行 |
| RPC 广播 | 服务端如何将结果通知所有客户端？ | 其他玩家看不到变化 |
| 客户端表现 | 收到 RPC 后客户端显示什么？（动画/特效/UI更新） | 操作无可见反馈 |

---

## 使用方法

这是一种**思维检查工具**：

1. **设计阶段**：在设计任何交互功能时，先画出完整链路图
2. **审查阶段**：对照 6 环检查表，确认每一环都有明确定义
3. **编码阶段**：按链路顺序实现，不跳环
4. **验收阶段**：沿链路逐环测试，确认数据流畅通
