# 主策划竞品分析能力 — 设计进化判断框架

> **文档性质**：主策划 AI 角色的竞品认知技能，用于判断一个设计在市场坐标系中的位置  
> **核心用途**：在设计讨论中，当一个想法被提出时，能快速定位它相对于已有产品是进化、平移还是倒退  
> **能力边界**：训练数据截止 2024 年初，2024 年后的新产品需要合作设计师补充描述

---

## 一、核心判断框架：三个坐标轴

分析一个设计相对于竞品的位置，需要在三个维度上同时判断：

### 轴1：机制维度
> 这个机制在市场上是第一次出现、已有先例、还是退化？

| 位置 | 定义 | 典型特征 |
|------|------|---------|
| **创新** | 市场上没有相同或高度相似的机制 | 玩家需要学习新的心智模型 |
| **进化** | 基于已有机制，解决了原版的某个具体问题 | 玩家认得出来，但感受更好 |
| **平移** | 与已有产品高度相同，没有明显改进 | 玩家会直接联想到原版产品 |
| **倒退** | 与已有产品相比，削减了关键体验 | 玩家会主动拿原版来对比并失望 |

**主策划的判断义务**：每当一个机制被提出，必须先定位它在哪个位置，再讨论细节。

---

### 轴2：用户价值维度
> 这个设计相比竞品，为目标用户提供了什么额外价值？

不是"这个设计更好"，而是"对目标用户来说，它解决了竞品没有解决的什么问题"。

```
进化的本质不是"更复杂"或"更多内容"
进化的本质是"对特定用户群体，提供了更精准的体验满足"
```

### 轴3：市场位置维度
> 这个设计在市场上是填补空白、正面竞争还是错误定位？

| 位置 | 风险等级 | 典型情况 |
|------|---------|---------|
| 填补空白 | 低风险 | 目标用户有需求，但市场上没有好产品满足 |
| 差异化竞争 | 中风险 | 相同品类，但用不同的设计角度切入 |
| 正面竞争 | 高风险 | 与头部产品高度重叠，需要有显著优势才能抢用户 |
| 错误定位 | 极高风险 | 用户画像与实际设计不匹配，两边都不讨好 |

## 二、主要竞品知识库

### 2.1 割草 / 幸存者类（与当前项目最相关）

#### 《吸血鬼幸存者》（Vampire Survivors）
**核心机制**：自动攻击 + 时间驱动的被动成长 + 15-30 分钟单局  
**设计本质**：把"积累力量"这个感受压缩到极短时间内，让玩家每分钟都能感受到成长  
**用户价值**：零操作门槛，但保留策略深度（选什么武器/进化路径）  
**弱点**：视觉表现单薄，缺乏社交/多人维度，后期重复感强  

**后续进化产品的普遍方向**：
- 加入手动操作元素（瞄准、闪避）提升参与感
- 加入多人合作/对战维度
- 强化视觉表现（满屏特效）
- 压缩局时（移动端适配）

#### 《弹壳特攻队》（Survivor.io）
**核心机制**：VS 系同款 + 移动端优化 + TPS视角  
**关键创新**：把 VS 的俯视角改为第三人称，增加了视觉冲击力；加入装备系统作为局外成长  
**弱点**：付费驱动感强，核心循环新鲜感衰减快  

#### 《元气骑士》
**核心机制**：Roguelike 地牢 + 多角色 + 手动操作射击  
**设计本质**：给射击游戏套上 Roguelike 外壳，强化探索感和随机性  
**用户价值**：操作门槛适中，内容量大，适合重度休闲玩家  

---

### 2.2 TPS 射击类

#### 《香肠派对》（原版）
**核心机制**：TPS + 物理弹道 + 卡通风格 + 微信社交  
**设计本质**：降低射击游戏门槛，用卡通风格和社交传播覆盖轻度用户  
**用户价值**：不需要精准操作，社交门槛低，亲友同玩  

#### 《大多数射击游戏的微信小游戏移植》
**普遍弱点**：把端游机制直接移植，没有针对小游戏用户的操作密度降低  
**用户反馈**：轻度用户难以上手，重度用户觉得体验缩水  

---

### 2.3 Roguelike 构筑类

#### 《杀戮尖塔》（Slay the Spire）
**核心机制**：卡组构筑 + 每局随机 + 永久失败风险  
**设计本质**：把构筑决策本身做成核心乐趣，而不只是变强手段  
**关键启示**：三选一的价值不在于"变强"，在于"选择本身带来的策略思考乐趣"  

#### 《哈迪斯》（Hades）
**核心机制**：动作 Roguelike + 叙事整合 + 死亡即进度  
**关键创新**：把"死亡"从失败变成了叙事推进——死了也不算输  
**对三选一设计的启示**：每次选词条不只是变强，还可以和角色叙事/世界观联动

## 三、进化判断的操作方法

### 3.1 四步判断流程

当一个设计想法出现时，按以下步骤分析：

```
第一步：识别"原型产品"
         这个设计想法最先出现在哪个产品里？
         （如果想不到先例，可能是真正的创新，需要额外论证）

第二步：列出原型产品的"用户痛点"
         玩家在原型产品中最常抱怨什么？
         什么体验是原型产品做得不够好的？

第三步：判断当前设计是否解决了这些痛点
         如果解决了 → 进化
         如果没解决但体验一致 → 平移
         如果削减了原型产品的优点 → 倒退

第四步：判断进化是否对目标用户成立
         解决了痛点，但目标用户是否真的有这个痛点？
         （为错误的用户群体进化，等于没有进化）
```

### 3.2 常见的"伪进化"模式（需要警惕）

| 伪进化类型 | 表现 | 实质 |
|-----------|------|------|
| 复杂度堆砌 | "我们比 VS 多了 X 个系统" | 更多系统 ≠ 更好体验，可能增加了用户理解成本 |
| 视觉升级但机制平移 | "特效更好看" | 如果核心循环相同，视觉升级只能维持短期吸引力 |
| 为重度用户进化，但目标用户是轻度用户 | "我们的 BD 深度更高" | 目标用户（微信小游戏轻度用户）不需要更高的 BD 深度 |
| 针对没人抱怨的痛点进化 | "我们解决了 XX 问题" | 如果没有用户真正在乎这个问题，解决它没有价值 |

## 四、当前项目（多武器 PVE 模式）的竞品坐标定位

### 4.1 设计基因来源

| 设计元素 | 原型产品 | 当前项目的处理方式 | 初步判断 |
|---------|---------|-----------------|---------|
| 自动攻击 + 割草感 | 吸血鬼幸存者 | 悬浮武器自动索敌，保留割草感 | 平移（核心体验相同） |
| 三选一 Roguelike 构筑 | 吸血鬼幸存者 | 元素派生链增加了构筑深度 | 进化（派生链是增量） |
| TPS 视角 | 香肠派对原版 | 在熟悉视角上叠加新玩法 | 平移（视角本身无变化） |
| 多人协作 PVE | 弹壳特攻队等 | 1-4 人协作，动态难度调整 | 平移（行业标配） |

### 4.2 真正的差异化机会

当前设计中，**唯一有可能构成真正进化的点**是：

**元素派生链 × 多武器组合**

吸血鬼幸存者和弹壳特攻队的词条选择，本质上是"数值叠加"——选了之后变得更强，但策略深度有限。

当前设计的**元素派生链**（灼烧→火球→陨石→燃烧区）如果实现得足够清晰，玩家能在选词条的时候产生"我在构建一个连锁反应系统"的感受——这比"我在叠数值"有更高的策略乐趣和探索欲满足。

**这个点是否真正成为进化，取决于**：
1. 派生链的触发是否足够视觉清晰（玩家能看出来是自己的构筑在起作用）
2. 不同元素组合是否产生真正不同的游玩体验（而不只是数值差异）
3. 轻度用户能否在不理解完整派生链的情况下，仍然感受到正反馈

### 4.3 当前设计的主要风险

**风险一：BD 深度超出目标用户的接受范围**

元素派生链对于 Steam Roguelike 玩家是吸引力，对于微信小游戏的轻度用户可能是认知负担。如果核心用户是轻度用户，需要重新审视派生链的复杂度是否匹配。

**风险二：自动索敌削减了"射击手感"**

吸血鬼幸存者能接受自动攻击，因为它从一开始就不是射击游戏。当前产品建立在射击游戏的视觉语言上（TPS视角、枪械），玩家会有"我在控制枪"的预期——此时自动索敌可能导致预期落差。这是需要原型验证的核心问题。

## 五、竞品分析的使用规范

### 5.1 什么时候启动竞品分析

- 一个新设计想法被提出时（第一反应：这在哪里见过？）
- 讨论某个机制的深度或复杂度时（对标产品做到哪个程度？）
- 定义目标用户时（这类用户现在在玩什么？）
- 判断一个功能是否值得做时（竞品没做这个，是因为他们没想到，还是因为用户不需要？）

### 5.2 竞品信息的补充协议

由于训练数据有截止日期，当合作设计师描述一个我不熟悉的产品时，我需要以下信息才能进行有效分析：

```
1. 这个游戏的核心机制是什么？（一句话）
2. 它的目标用户是谁？
3. 玩家对它最常见的正面评价是什么？
4. 玩家对它最常见的负面评价是什么？
5. 它的商业模式是什么？（买断/内购/订阅）
```

有了这五个信息，我可以进行机制层面的分析判断，即使我没有实际游玩过这个产品。
