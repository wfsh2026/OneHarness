## 四、执行步骤

### 步骤 1：扫描目录结构（无文档可读，直接从代码入手）

> 1 代架构目录下无模式相关文档，本批次完全基于代码分析。

- 列出 Client/Mode/ 下所有子目录和文件
- 列出 Server/Mode/ 下所有子目录和文件
- 列出 Host/Mode/ 下所有子目录和文件
- 识别 C/S/H 三端的对应关系（同名模式）

### 步骤 2：识别关键类型

- 查找模式枚举（如 ModeType、GameMode 等枚举定义）
- 查找模式基类（如 ClientModeBase、ServerModeBase）
- 查找 Manager/System 入口类
- 识别模式注册/创建机制

### 步骤 4：枚举所有模式

- 根据目录结构和枚举定义，列出所有已实现模式
- 建立模式名称 ↔ 代码文件的映射表
- 识别每个模式的三端对应关系

### 步骤 5：识别关键消息/数据

- 扫描 Message/ 目录中与 Mode 相关的消息定义
- 扫描 Config/ 和 Data/ 中与 Mode 相关的配置
- 扫描 Template/ 中的模式模板数据

### 步骤 6：填写 system-map 条目

- 按格式填写系统地图条目
- 填写实例清单
- 填写意图识别关键词

### 步骤 7：创建 feature.json

- 为模式基础设施创建 mode-base.json
- 为每个具体模式创建独立 json
- 验证文件路径正确性

### 步骤 8：编写 1 代架构制作文档

- 基于步骤 1-5 的分析结果，编写 [[模式制作]]
- 格式参考 `载具制作.md`（架构概述 → 核心类依赖 → 制作流程 → 枚举/配置 → 注意事项）
- 重点覆盖：新模式添加流程、三端对应规则、模式注册机制

### 步骤 9：用户审核

- 提交产出物供用户审阅
- 根据反馈修正
