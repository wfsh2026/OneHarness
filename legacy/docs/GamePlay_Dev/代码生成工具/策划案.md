## 一、需求背景

AI Agent 在开发 Ability（AB/AE）、GPO、GPOM 功能时，需要手动参考范例编写大量结构化代码。实际运行中暴露两个核心问题：

1. **遗漏注册步骤**：如忘记在 `AbilityConfig_AutoGenerated.cs` 中添加 switch case，或忘记在 `ServerAbilityManager_SwitchAB.cs` 中注册路由
2. **代码结构偏差**：生成的 System、Select、RPC 代码与 AbilityEditor 标准输出不一致

这两个问题导致每次开发后需要用户逐一核查和修复，严重降低协作效率。

## 二、核心目标

将 Ability/GPO/GPOM 三类高度结构化的代码生成，从「AI 手写参考」转为「AI 调用 sh 脚本自动生成」：

| 指标 | 当前 | 目标 |
|------|------|------|
| 注册遗漏率 | 约 30%（2-3步/10步） | 0%（工具原子操作） |
| 代码结构一致性 | ~85%（有细节偏差） | 100%（heredoc 固定模板） |
| 单次生成耗时 | 5-10 分钟（含来回确认） | <10 秒（脚本执行） |

## 三、工具矩阵

| 工具 | 使用场景 | 创建文件数 | 修改文件数 | 输入方式 |
|------|---------|:---:|:---:|------|
| `ability-gen.sh` | 新建 AB/AE 技能 | 6 | 5-6 | 命令行参数 |
| `gpo-gen.sh` | 新建 GPO 类型 | 2 | 4 | 命令行参数 |
| `gpom-gen.sh` | 新建 GPOM 模板数据 | 1 | 0 | 命令行参数 |
| `scene-gen.sh` | 新建完整场景 | 1场景+1配置 | 2 | 命令行参数 + MCP |
| `scene-server-gen.sh` | 客户端场景转服务端 | 1场景 | BuildSettings | 命令行参数 + MCP |
| `mode-gen.sh` | 新建游戏模式 | 2 | 3（含4处注册） | 命令行参数 |
| `component-gen.sh` | 新建 Component 模板 | 1 | 0 | 命令行参数 |

## 四、使用场景描述

### 场景1：AI Agent 制作新 Ability（AB）

```
用户："制作一个新的火球技能 Fireball"
    ↓
AI Agent 确认参数（名称、类型、字段列表、是否同步客户端）
    ↓
AI Agent 调用: bash ability-gen.sh --name Fireball --type AB --fields "M_Power:int,M_LifeTime:float" --csv-fields "M_Power,M_LifeTime" --sync-client true --in-fields "In_StartPoint:Vector3"
    ↓
脚本输出：6个文件创建 + 5个文件修改，全部完成
    ↓
AI Agent 在生成的骨架代码上填充业务逻辑（组件挂载、表现逻辑等）
```

### 场景2：AI Agent 制作新 GPO

```
用户："制作一个新的地雷 GPO"
    ↓
AI Agent 确认参数（名称、中文名、类型ID、GPO ID、模板类型）
    ↓
AI Agent 调用: bash gpo-gen.sh --name LandMine --cn-name 地雷 --gpo-type-id 30 --gpo-id 3001 --template combat --custom-fields "Atk:int,ExplosionRadius:float"
    ↓
脚本输出：3个文件创建 + 5个文件修改
    ↓
AI Agent 在骨架代码上填充 AI 行为和战斗逻辑
```

### 场景3：AI Agent 更新 GPOM 数据

```
已有 GPOM_LandMine.cs 需要新增匹配模式数据
    ↓
AI Agent 按照 GPOM 文件格式手动在 Data 数组中添加新数据条目（无需调用工具）
```

### 场景4：AI Agent 制作新游戏模式（Mode）

```
用户："制作一个赛博炮台PVE测试模式"
    ↓
AI Agent 确认参数（名称、描述、地图、PVE/PVP）
    ↓
AI Agent 调用: bash mode-gen.sh --name CyberBatteryTest --desc "赛博炮台PVE测试" --map-id "MapSet.Id_CyberBatteryTest" --map-sign "CyberBatteryTest" --pve
    ↓
脚本输出：2个文件创建（Server/Client Mode）+ 3个文件修改（ModeData.cs 4处 + 2个System switch）
    ↓
AI Agent 在骨架代码上填充模式业务逻辑（回合控制、计分、AI刷新等）
```

### 场景5：AI Agent 创建新 Component

```
用户："给赛博泡泡 AI 创建一个移动组件"
    ↓
AI Agent 确认参数（名称、侧、类型、功能标志）
    ↓
AI Agent 调用: bash component-gen.sh --name ServerAICyberBubbleMove --side server --type ai --has-init-data --has-update --has-sync --desc "赛博泡泡移动组件"
    ↓
脚本输出：1个文件创建，包含完整生命周期注释和正确基类
    ↓
AI Agent 在生成的模板上填充具体移动逻辑（TODO 标记处）
```

## 五、成功标准

1. **原子性**：脚本要么全部成功创建/修改文件，要么全部不生效
2. **幂等性**：重复运行相同参数不会产生重复注册
3. **一致性**：脚本输出与 AbilityEditor.cs 产出的代码结构完全一致
4. **完整性**：所有注册步骤在脚本中一次性完成，AI Agent 无需手动补注册

## 六、不在范围内

- GUI 界面（工具仅供 AI Agent 通过命令行使用）
- 批量操作（初版不需要）
- UGC 相关代码生成（UGC 有独立流程）
