## 二、R-03：设计文档完整性框架拆分

### 2.1 问题

`设计文档完整性思维框架.md`（530 行）是唯一有拆分价值的 Skill 文件。每次 GD 被调度时全量加载 530 行，但实际只用 §十二（有效/无效速查，37 行）和 §十七（主流程生命周期，64 行）。

其他 5 个 Skill 文件（45~152 行）都在合理范围，不动。

### 2.2 方案

**拆分策略**：

| 去向 | 内容 | 预估行数 |
|------|------|---------|
| 速查版（替换原文件） | §十二「有效/无效内容速查」+ §十七「主流程生命周期」+ 各章节核心 checklist 提取 | ~100 行 |
| `references/完整性维度详解.md` | 各章节的详细展开（V62 炮台案例、弹道参数、几何尺寸等具体示例） | ~430 行 |

**拆分后结构**：

```
aigc/harness/skills/Gameplay_Designer/
├── 设计文档完整性思维框架.md          ← 精简为速查版（~100行）
└── references/
    └── 完整性维度详解.md              ← 详细案例展开（~430行）
```

> 不改文件名。现有引用方零变更。

### 2.3 评估

| 维度 | 评估 |
|------|------|
| **难度** | ★★☆☆☆ 低 — 1 个文件拆分 + 1 个新目录，不涉及任何引用更新 |
| **价值** | ★★★★☆ 高 — GD 调度从加载 530 行降到 ~100 行（节省 ~80% token） |
| **风险** | 极低。文件名不变，引用方零影响 |
