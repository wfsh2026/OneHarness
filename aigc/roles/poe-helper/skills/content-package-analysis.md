# 目录与内容包分析

本技能用于分析 POE / POE2 的安装目录、内容包、GGPK 内部路径、bundle 索引和后续可检索数据库。目标是区分“安装根目录结构”和“内容包内部资源结构”，并生成后续 mode 落地可用的索引依据。

## 分析边界

- 安装根目录分析关注本地文件系统：可执行文件、启动器、校验工具、内容包文件、日志、缓存、配置和本地补丁工具位置。
- 内容包内部分析关注 `Content.ggpk` 或等价内容包中的虚拟路径树、文件记录、目录记录、bundle 归属、路径哈希和资源大小。
- 两类结构不能混用：mode 替换通常需要内容包内部路径，而不是安装根目录下的普通文件路径。
- 具体安装路径、工具路径、导出文件、计数和本地结果属于项目事实，只写入目标项目知识库。

## 安装目录快照

- 只读扫描安装根目录，输出目录层级、核心文件名、文件大小、修改时间和可疑本地生成物。
- 优先识别内容包文件、游戏主程序、启动器、校验程序、配置目录、日志目录、缓存目录和补丁工具残留。
- 对官方文件、本地工具、生成索引、临时导出和用户补丁进行分类；无法确认来源时标记为待确认。
- 快照用于后续安装包路径调整或版本升级对比，不用于证明内容包内部资源存在。

## 内容包内部索引

- 使用只读 GGPK / bundle 解析器打开内容包；默认不写入、不重打包、不运行游戏、不执行修复或校验破坏性操作。
- 完整索引建议至少拆成文件、目录、资源包和摘要四类数据，便于快速检索和增量对比。
- 文件索引建议字段：内部路径、路径哈希、文件大小、资源包路径、资源包序号、偏移或块位置、压缩状态、解析状态。
- 目录索引建议字段：内部路径、深度、父目录、子项数量。
- 资源包索引建议字段：资源包路径、序号、文件数量、压缩或解压大小、异常状态。
- 摘要建议字段：生成时间、内容包标识、工具版本、总文件数、总目录数、总资源包数、未解析数量和索引格式版本。

## 数据沉淀

- 人类阅读文档放在目标项目文档目录，使用清晰中文命名。
- 大体积机器索引、SQLite、TSV、JSONL 或二进制缓存放在目标项目数据目录，并在文档中只引用位置和生成方式。
- 对高频检索主题应建立查询样例，例如 shader、fxgraph、minimap、metadata、bundle 路径、path hash 或文件名精确命中。
- 文档必须区分已确认、推断、待确认；不要把索引工具的解析缺口写成资源不存在。

## 交付要点

- 输出应包含：扫描对象、只读保证、索引格式、核心字段、可复现命令或工具入口、异常记录、后续对比方式。
- 当任务目标是支持 modes 落地时，应额外给出“从内部索引到 zip 条目路径”的转换规则和验证清单。
