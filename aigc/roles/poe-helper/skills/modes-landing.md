# Modes 落地修改

本技能用于处理 POE / POE2 的 mode、mod、补丁 zip、shader / fxgraph 替换和 VisualGGPK 写入方案。目标是把“要替换什么、替换到哪里、用什么工具写入、如何验证”说清楚。

## 核心判断

- modes 通常不是替换安装目录里的普通文件，而是替换游戏内容包内部的资源路径；zip 内条目路径应与内容包内部路径一致。
- 需要优先确认内部资源路径、大小、bundle 归属、路径哈希或索引位置，再制作或审查补丁包。
- zip 条目建议使用内容包内部相对路径，使用 `/` 分隔；不要带本地磁盘路径、安装目录前缀、`Content.ggpk/` 前缀或调试导出目录。
- 修改 shader、fxgraph 或类似资源时，应尽量以当前游戏版本导出的原文件为基底，只做目标差异，避免把旧版本完整文件直接覆盖到新版本。
- VisualGGPK 一类工具如果同时存在 GGPK 原始树和 bundle 树，应先确认普通 mode 写入入口对应 bundle 资源替换；直接覆盖原始 Bundles2 文件或根哈希通常属于更高风险路径。

## 推荐流程

1. 读取任务包，确认目标效果、允许读取范围、允许写入范围、禁止范围和回滚要求。
2. 只读定位目标资源：用内容包索引、GGPK / bundle 解析器或工具导出结果确认内部路径。
3. 建立替换清单：记录内部路径、文件类型、原始大小、候选 bundle、哈希或索引字段，并区分已确认与推断。
4. 准备替换文件：从当前版本原始文件导出或读取，应用最小必要改动，保留可追溯差异。
5. 生成或审查 mode 包：确认 zip 条目路径逐项命中内部路径，文件编码、换行、大小变化和数量符合预期。
6. 写入前检查：确认备份、回滚包、工具版本、写入入口、预期替换数量和失败时停止条件。
7. 写入后验证：优先做工具读回、索引命中或文件导出比对；游戏内效果验证应单独记录，不与写入成功混为一谈。

## 风险边界

- 未经明确授权，不写入、替换或删除游戏安装目录、`Content.ggpk`、bundle 文件、补丁工具目录或账号登录态文件。
- 不把工具显示“导入成功”等同于游戏内已生效；shader 缓存、预编译管线、启动器校验或资源加载优先级都可能影响最终表现。
- 涉及擦除根哈希、直接改写 GGPK 根节点、绕过启动器校验或覆盖整包 bundle 时，必须作为高风险方案单独提示。
- 不把旧会话、旧补丁或其他机器上的路径直接套用到当前安装包；必须以当前内容包索引重新确认。

## 交付要点

- 输出应包含：目标效果、确认过的内部路径、替换文件清单、写入工具和入口、验证方式、回滚方式、风险和待确认项。
- 知识沉淀时，只把通用落地方式留在角色技能；具体 mode 名称、补丁包路径、资源路径、工具目录、验证截图和实验结论写入目标项目知识文档。
