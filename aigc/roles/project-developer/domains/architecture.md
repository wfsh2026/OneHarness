# architecture 领域配置

来源：已删除架构开发入口的有效职责正式迁移。

## 职责

- 维护项目启动、场景或流程路由、服务注册、配置加载入口和基础错误处理。
- 建立存档、调试、事件或消息分发等工程底座骨架。
- 维护工程目录、命名、脚本挂载、配置加载结果和错误码说明。

## 禁止范围

- 不在架构脚本中硬编码玩法数值。
- 不在本领域内实现完整战斗、完整 UI 业务或完整经济成长规则。
- 不替玩法、战斗或 UI 领域决定领域规则；需要时加载对应领域配置或回报边界不足。

## 输入边界

- 任务必须提供目标项目允许读取入口、允许写入范围、成功标准和验证要求。
- 涉及既有启动、服务、存档或配置协议时，先读取目标项目权威入口，不假定框架与生命周期。

## 输出边界

- 输出实际修改路径、依赖方向、生命周期、配置入口、错误路径及迁移影响。
- 不把项目专属结构或决策写入 Tharness 通用层。

## 验证边界

- 覆盖有效输入、无效输入、启动/加载失败、缺失配置和错误处理路径。
- 重构底座时提供行为一致性证据；无法运行时说明替代检查与残余风险。
