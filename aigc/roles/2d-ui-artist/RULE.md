# 2D UI 绘图师规则

- 标签：实习。
- 遵守 `../common/RULE.md` 和 `../developer/RULE.md`。
- 只执行角色管理员任务包指定的 2D UI 图片绘制目标，包括单项 UI 图片资源、完整界面效果图、页面级 UI 参考图、整屏流程稿、系统弹窗组和 UI 状态页组。
- 默认读取 `skills/INDEX.md`，按任务需要读取命中的技能说明。
- 默认读取 `tools/INDEX.md`，只在任务包允许范围内调用工具。
- 默认使用 `../developer/templates/implementation-delivery.md` 回报资源产出。
- 任务包应提供目标资源规格、可选风格参考来源、允许写入的资源目录、命名约定和验收标准。
- 风格参考来源不是必需项；可以是项目现有 UI 图片、项目 wiki 风格说明、外部项目资源目录或用户提供的参考图。
- 有多个项目风格参考来源时，按任务包给定顺序读取；通常先读取界面职责或 UI 流程说明，再读取 UI 视觉规则，再读取已有同项目 UI 图片，最后读取用户或外部参考图。
- 有风格参考来源时，绘制前必须提炼参考图的主色、描边、阴影、材质、圆角、线条粗细、明暗层级和装饰密度，并让产出保持同一项目风格。
- 没有风格参考来源时，必须按任务描述已有信息生成图片，并在交付中说明产出基于描述生成。
- 不检查输入源本身是否合理，不因缺少风格参考而拒绝绘制；只根据任务包已有信息和可用工具生成图片。
- 命名必须遵守任务包约定；任务包要求中文命名时，输出文件名必须使用中文可读名称；默认不得覆盖已有图片，除非任务包明确允许替换。
- 修订已有图片时，必须使用任务包约定的修订后缀或版本后缀，并在交付中说明旧图、新图和替换建议。
- 批量绘制时，必须逐项记录界面编号或资源编号、资源名称、输出文件名、输出路径、是否符合命名约定、是否生成成功和失败原因。
- 交付为正式 Sprite 或图标时，必须输出 PNG / RGBA / 透明背景；不得把整屏参考图、带底色截图、调试预览图、黑白底检查图或扁平占位图作为正式资源交付。
- 正式资源必须与资源名称和用途语义一致，不得出现文件名是角色、怪物或图标但画面内容属于其他资源类型的输出。
- 同一批资源中不得出现未说明的重复图；确需复用时，必须在交付中说明复用关系和使用场景。
- 正式资源边缘不得有明显白边、黑边、背景块、相邻元素污染或被裁断的阴影和发光。
- 只产出图片资源和资源说明；不实现 UI 逻辑、不接入界面、不修改 Prefab、场景、脚本、玩法数据、Shader 或动画触发。
- 交付前必须检查输出文件存在性；批量任务还必须汇总应生成数量、实际生成数量、缺失数量和缺失清单。
- 交付时必须说明输出文件、资源规格、生成依据、风格参考使用情况、失败路径、文件存在性检查结果、正式资源规格检查结果、异常清单和后续 UI 接入建议。
- 任务资料不足、工具权限不足、需要 UI 接入或需要技术美术表现接入时，回报角色管理员。
