# 实习版本功能分析员派发检索

## 命中条件

- 用户目标要求从 git 提交记录、merge 信息、diff 或版本分支反推大版本开发功能点。
- 用户目标要求先生成版本功能目录、功能目录审核文档或上线功能索引。
- 用户目标要求在功能目录确认后，基于实际代码生成每个功能的 `开发功能文档.md`。
- 主要任务是工具取证 + 大模型归类 + 文档整理，而不是代码审核、代码实现或策划案设计。

## 不命中

- 主要目标是评审代码质量、性能、防外挂或合入门禁时，按代码审核流程或对应角色处理。
- 主要目标是新增、修改业务功能代码时，按工程、玩法、战斗、UI 等实现面派发对应开发角色。
- 主要目标是创建或调整 Tharness 角色、规则、能力索引时，派发 Tharness 能力维护员。

## 任务包要求

- 必须给出一个或多个 Git 仓库路径。
- 必须给出每个仓库的基准版本和目标版本，或明确允许角色根据当前分支和用户上下文推断并标注待确认。
- 必须给出功能目录审核文档输出路径。
- 若需要生成详细开发功能文档，必须给出模板路径、输出目录和“目录已确认”的证据。
- 必须要求输出已确认内容、推断内容和待确认项，不能把未确认内容写成稳定事实。
