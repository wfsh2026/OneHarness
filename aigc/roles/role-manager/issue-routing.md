# 写入位置路由规则

## 结论

`issue-routing.md` 是 Tharness 候选问题、候选知识和规则变化的唯一写入位置路由。其他规则、wiki 页面、模板或能力索引只能引用本文件，不得另建写入位置路由表。

## 路由表

| 候选内容 | 唯一写入位置 |
| --- | --- |
| 一次性失败、调试过程、临时命令 | 本轮交付物。 |
| 已确认项目事实、项目模块边界、项目构建测试入口 | 本轮交付物，或用户明确指定的项目文档。 |
| 项目技术决策 | 本轮交付物，或用户明确指定的项目文档。 |
| 未确认问题、待用户拍板内容 | 本轮交付物。 |
| 跨项目、跨角色、低频变化的通用架构原则 | `AIGC/wiki/architecture/`，并按 `AIGC/wiki/rules/building.md` 创建或更新页面。 |
| wiki schema、检索、写入或健康检查规则 | `AIGC/wiki/rules/`。 |
| 通用角色最小规则、角色管理员规则、验证规则或交付规则变化 | `AIGC/roles/` 下对应规则文件。 |
| 角色派发边界、冲突判断或主责任面选择 | `AIGC/roles/role-manager/role-routing/`。 |
| 具体执行角色的可复用执行技巧 | `AIGC/roles/{role-id}/skills/`。 |
| 具体执行角色的工具调用说明 | `AIGC/roles/{role-id}/tools/`。 |
| 游戏策划通用方法、方法卡、来源登记或策划输出模板 | `AIGC/roles/role-manager/game-design/`。 |
| 能力入口、状态或版本变化 | `AIGC/capabilities/`。 |

## 处理流程

1. 执行角色提交候选内容、来源和证据。
2. 角色管理员判断内容是否已经验证或由用户确认。
3. 角色管理员判断内容是否只属于当前项目。
4. 角色管理员判断内容的后续检索入口属于 wiki、角色规则、角色技能、角色工具、游戏策划资料、能力索引还是本轮交付物。
5. 只选择一个写入位置，或记录不写入理由。
6. 更新后执行对应健康检查。

## 禁止

- 禁止把未确认推测写成稳定事实。
- 禁止把一次性调试过程写入 wiki。
- 禁止同一经验在多个规则文件重复维护。
- 禁止从旧项目资料直接复制项目事实到通用 AIGC。
- 禁止在本文件以外维护写入位置路由表。
