# AIGC 变更记录

## 6.0.0

- 正式删除四个已发布开发角色目录及对应路由页，不再提供兼容、弃用或回退入口。
- 将旧技能索引中工程底座、UI 接入、玩法系统和战斗运行时的触发条件迁入 `project-developer/skills/domain-implementation.md`；职责、禁止范围、输入、输出与验证边界由四个正式领域文件完整承载。
- 角色库、路由、注册表、自检配置、能力索引、角色浏览器和测试移除旧角色及旧能力条目；项目开发者和四领域成为唯一正式入口。
- 新增活动入口负向检查：旧角色标识、显示名或路由重新出现在活动规则、注册表、配置和工具时，`check` 与 `eval` 失败。
- major 原因：删除已发布角色与路由入口是外部契约破坏。迁移方式是把旧角色规则入口替换为 `project-developer/RULE.md`，并在任务中声明 `architecture`、`ui`、`gameplay` 或 `combat` domain。
- 影响范围：角色库、项目开发者技能与领域、路由、注册表、能力记录、自检、角色浏览器和测试；不影响版本扫描器、项目绑定、视觉角色或项目事实边界。
- 验证方式：运行 `doctor`、`index --check`、`registry`、`check`、`eval`、三组单元测试、旧引用扫描和 `git diff --check`。

## 5.0.0

- 集中新增自治、授权、风险驱动假设和按收益委派权威策略，删除“所有具体任务必须 SubAgent”等重复绝对规则。
- 正式输出改为审计分级；新增轻量任务包，原任务包升级为完整审计版。
- 新增“项目开发者 + architecture/ui/gameplay/combat 领域配置”，从旧四角色迁入职责、禁止范围、输入、输出与验证边界；5.0.0 当时保留的过渡入口已在 6.0.0 正式删除。
- 机器注册源升级到 schema v2，以 `draft/contracted/tested/evaluated` 证据成熟度替代数值置信度，并登记 owner、契约状态、最后验证、Eval 和弃用迁移；当前没有实际模型评测，条目最高只标记 `tested`。
- 所有角色工具索引采用统一契约；新增 `registry` 与表驱动确定性 `eval` 命令，总检查覆盖工具契约、策略正负/变异场景与兼容路由。该 Eval 不代表真实模型行为评测。
- 角色管理器改用证据成熟度排序，RULE 编辑必须进入维护模式并预览差异、受影响入口、版本策略和自检计划后确认保存。
- 新增 GPT-5.6 模型与推理分级策略；档位仅在宿主支持时使用，并要求代表性 Eval 证明收益。
- 明确未增加当前会话 Token 统计、遥测或相关 UI。
- major 原因：`registry.yaml` 从角色 7 字段/能力 2 字段升级为必需的 11/8 字段 schema v2，旧读取器无法解析。迁移时必须先升级读取器；5.0.0 的角色过渡入口已在 6.0.0 删除。
- 影响范围：AIGC 入口、通用与管理员规则、角色库、开发角色、路由、工具契约、注册源、自检/Eval、角色浏览器、能力索引和测试；保留旧开发角色引用与现有工具入口。
- 验证方式：运行 `doctor`、`index --check`、`registry`、`check`、`eval`，以及 tharness、role-browser、version-feature-scan 单元测试和 `git diff --check`。

本文件只记录当前角色调度体系从 `1.0.0` 开始的有效变更。

## 4.8.0

- 修改内容：机器注册源的每个角色新增 0–100 整数置信度，定义为角色配置与验证成熟度；角色管理员固定 100 且必须唯一最高，自检验证完整性、整数、范围和唯一最高约束。
- 修改内容：角色管理页面默认按置信度降序、显示名升序排列，列表和详情均显示可访问的 `置信度 NN%` 文本，并保留搜索、类型筛选和能力筛选。
- 修改内容：角色规则标签支持直接编辑注册角色 `RULE.md`，提供保存按钮、脏状态、成功与失败提示、Ctrl+S，以及切换角色、切换文档和关闭页面前的未保存提醒；skills、tools 和路由保持只读。
- 修改内容：RULE GET 返回 SHA-256 hash/version；保存必须携带 base hash，当前文件变化时返回 409，禁止静默覆盖；保存使用同目录临时文件、fsync 和 `os.replace` 原子替换，并保留原 BOM 与换行风格。
- 修改内容：唯一 PUT 写接口只监听 `127.0.0.1`，校验 Host、Origin、启动期随机 CSRF、自定义请求头、application/json、UTF-8、非空和 512 KiB 限制；不开放 CORS 或任意路径写入。
- 修改原因：用户需要按稳定成熟度理解角色优先级，并在同一本地工具中安全维护角色规则，同时避免并发编辑静默覆盖。
- 影响范围：角色机器注册源、自检、角色管理服务与页面、能力索引、版本记录和专项测试；不改变 skills/tools、路由、业务项目、Rust 或 EXE。
- 验证方式：运行置信度、排序、GET hash、成功保存、冲突、写入边界、安全校验、原子保存、换行、前端交互和启动器 CRLF 测试，再运行 doctor、index、check、完整 unittest 与 diff 检查。
